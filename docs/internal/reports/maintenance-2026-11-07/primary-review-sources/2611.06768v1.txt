Abstract
Coding agents powered by models such as GPT-6-Astra connect spatial reasoning with executable robot behavior, raising the question of how such agents can produce lasting improvements in robot capabilities from physical interaction. In this work, we study embodied recursive self-improvement (RSI) through
real-world
exploration, code refinement, and deployment using PyRUA-REAL, a framework in which coding agents retain interaction experience as persistent memory and reusable executable skills that inform subsequent exploration and improvement. Our empirical study places physical manipulation at the center of the improvement process, examining how agents collaborate, what kinds of execution feedback support effective code refinement, and how task specifications and previously acquired skills influence robustness and task transfer. We further investigate the efficiency and capability of the resulting programs when deployed without involving an online agent for decision-making.
Across eight real-world tasks, PyRUA-REAL achieves an average success rate of 91.1%.
In complementary evaluation on 42 tasks from the RoboDojo benchmark, it achieves an average success rate of 84.4%. This study provides empirical guidance for turning physical exploration into reusable robot skills that support continued improvement and robust, efficient deployment.

. These capabilities make code a practical interface between high-level reasoning and physical behavior. They also raise a question beyond completing an individual task:
How can coding agents turn physical interaction experience into robot capabilities that persist and improve across successive attempts?
Experience-based adaptation and iterative code modification offer ways to improve agents while keeping foundation model parameters fixed

,

. In robotics, recent work has explored skill and agent-harness evolution in simulation

, simulation-based practice followed by physical deployment

. Building on these developments, we study embodied recursive self-improvement (RSI) as a process in which execution experience informs code revisions and is retained as memory and reusable skills for subsequent exploration. Our focus is an empirical account of this process in
real-world
manipulation, tracing how capabilities are acquired, refined beyond first success, and converted into programs for deployment.
Physical exploration presents challenges at several levels. Agents must decide which experiments to run, which implementation details to revise, and when to reconsider the underlying approach. Repeated local changes may leave an unsuitable perception or control strategy intact. Execution feedback is also ambiguous: an apparent task failure can originate in motion, perception, or the procedure used to verify success. Moreover, success under one configuration does not establish robustness to changes in object positions, orientations, or task requirements. Retaining a successful implementation therefore raises further questions about its reuse on new tasks and its ability to operate without repeated online agent decisions. Understanding embodied RSI requires examining these aspects of the improvement process alongside task success.
We present PyRUA-REAL (Python-based Robot-Use Agent for Robot Exploration and Adaptive Learning) as an embodied RSI framework for this study (Figure
1
). A researcher agent selects experimental objectives and technical approaches, while an engineer agent implements programs, executes robot trials, and diagnoses failures. Their interaction connects local code improvement with task-level reassessment. A persistent repository records environmental facts, attempted approaches, execution outcomes, and reusable implementations, allowing later experiments to build on earlier experience while model parameters remain fixed. For deployment, the resulting code can be frozen and executed without runtime language-model calls, while still responding to live observations through its perception, control, and recovery routines. This separation enables us to study both the process of developing robot capabilities and the behavior of the programs that retain them.
Our experiments cover eight manipulation tasks on a dual-arm Franka platform, spanning reasoning, long-horizon execution, precise contact, deformable objects, and bimanual coordination. Recorded development success averages 91.1% across tasks. These rates aggregate attempts across code revisions; frozen-program performance is evaluated separately. Complementary evaluation on 42 RoboDojo tasks yields 84.82% success, averaged equally over five capability groups, compared with reported results of 50.35% for PyRUA-Lean and 22.48% for GPT-6-Astra. Our main contributions can be summarized as:
•
An empirical study of skill acquisition and continued improvement through real-world interaction.
Across eight physical manipulation tasks, we trace how coding agents turn exploration experience into executable robot skills and improve them beyond first successful rollout, documenting gains and trade-offs in task completion, execution time, and placement precision across program revisions.
•
Case studies on the factors shaping embodied RSI.
Through comparative experiments and diagnostic case studies, we examine how agent coordination, execution feedback, explicit task requirements, and previously acquired skills affect revision efficiency, robustness, and transfer to new tasks.
•
An evaluation of the resulting robot capabilities and their deployment costs.
Real-world evaluations compare frozen programs with online agent execution, quantifying execution-time benefits and identifying situations that still require online assistance. Complementary evaluation on 42 RoboDojo tasks measures performance across five capability groups against reported baselines.

Our work lies at the intersection of programmatic robotic control and agent-driven self-improvement, aiming to enable robots to continuously improve their capabilities through real-world interaction. We review related research in LLM for robotic control, agentic RSI, and embodied RSI.

Large language models (LLMs) have enabled robot control by composing perception, planning, and control primitives into executable programs

In contrast, executable programs enable efficient closed-loop control without continuous LLM intervention. Building on this paradigm, we employ coding agents to construct and progressively refine both reusable robot primitives and task-specific policies, while delegating high-frequency control to independently executable robot programs.
Agentic RSI.

Inspired by these developments, our work extends agentic self-improvement to physical interaction, where coding agents continuously accumulate execution-grounded knowledge and reusable control capabilities to improve subsequent robot policy generation and refinement.
Embodied Recursive Self-Improvement.
Recent embodied RSI research leverages environmental feedback to autonomously improve robot policies, reusable skills, and agent capabilities. Simulation-centered approaches evolve skills and agent harnesses in virtual environments, sometimes followed by real-world transfer

3.2
System Overview
PyRUA-REAL consists of three components:
improvement
,
execution
, and
experience
, as illustrated in Figure
2
. The system receives a human-provided task goal (
goal
) and a task specification (
survey
), which describes the required coverage of objects, positions, orientations, and task variants. With the underlying agent model parameters held fixed, the system develops task programs through code generation, testing, and feedback analysis. The resulting task program runs independently of the development agents.
The improvement component comprises two agents with complementary responsibilities. The
researcher
manages the overall technical approach and specifies the objective, stopping criteria, and relevant experience for each experiment. The
engineer
implements these requirements, diagnoses problems through environmental interaction, and revises the code. They coordinate through structured
experiment
specifications and
report
artifacts, connecting task-level experimental decisions with implementation-level exploration.
The execution component independently runs the task program, whose perception, planning, and control components use live observations to generate actions and advance the task. The program may invoke locally deployed pretrained models, such as SigLIP
[
25
]
and SAM
[
9
]
, as perception components. Execution frames, states, and logs support subsequent program revisions. The researcher organizes the resulting environmental facts, problem-solving records, and reusable implementations in the experience repository for future experiments and tasks.
3.3
Coding Agents Collaboration
The
researcher
and
engineer
address problems at different levels of granularity. The
researcher
considers the complete task and its required variations to choose a technical approach and decide when to change methods or advance to the next stage. The
engineer
focuses on implementation, environment interaction, and local diagnosis within the current experiment. Their basic unit of coordination is an
experiment
: a goal-directed exploration process that may include multiple code revisions and tests.
Each experiment specifies an objective, stopping criteria, and selected experience. The researcher defines the objective for the current stage, provides relevant facts, historical approaches, and skill references, and autonomously sets the stopping criteria. Besides goal completion, stopping conditions may include a rejected hypothesis, a bottleneck requiring a different technical approach, or repeated revisions without progress. When a stopping condition is met, the engineer hands the problem back to the Researcher for reassessment.
Within an experiment, the engineer may revise code and conduct multiple focused tests without executing the complete task each time. For example, when object recognition is unreliable at a particular step, the engineer can compare recognition methods at that stage. The engineer independently decides how to implement and validate these changes within the scope of the experiment.
At the end of the experiment, the engineer returns a
report
containing the outcome and termination reason (
results
), findings from the exploration (
learned
), supporting execution records (
evidence
), and the final implementation (
code
). The researcher uses this report to decide whether to refine the current approach, change direction, or advance to another task stage and defines the next experiment accordingly.

Experiments and Empirical Findings
In this section, we investigate how coding agents turn physical interaction experience into improved, reusable robot programs. We first introduce the research question and hypotheses (Section
4.1
), describe the experimental settings (Section
4.2
), and report capability acquisition and continued improvement beyond first success (Section

4.4

4.1
Research Question and Hypotheses
Our experiments address one overarching research question:
How should coding agents turn physical interaction experience into progressively more capable robot programs?
Specifically, we examine the following hypotheses, which the experimental results may support or challenge:
•
H1: Accumulated physical experience supports sustained self-improvement.
Retaining execution experience as memory and executable skills enables successive improvement cycles to build on prior discoveries and failures, improving robot capabilities beyond the first successful program. (Section
4.3
)
•
H2: Multi-agent coordination with specialized responsibilities improves RSI efficiency.
Distributing task-level planning, implementation, and independent review across specialized agents is expected to improve the efficiency of successive exploration and revision cycles. (Section
4.4
)
•
H3: Rich execution feedback improves RSI efficiency.
Visual records and robot-state information enable more effective failure diagnosis and program revision than outcome-only feedback. (Section
4.5
)
•
H4: Explicit task requirements improve the robustness of robot programs.
Specifying objects, layouts, and task variants guides exploration and skill refinement toward better robustness on unseen task variations. (Section
4.6
)
•
H5: Developed primitive skills can positively transfer to new tasks.
Agents given a primitive-skill library acquired on earlier tasks are expected to develop more successful programs for new tasks than agents without that library. (Section
4.7
)
•
H6: Consolidating exploration into executable programs improves deployment efficiency.
Encoding task decisions in reusable programs reduces repeated online agent calls and execution time. (Section
4.8
)

4.3
Embodied RSI Performance in the Real World and Simulated Environments
We examine whether
physical interaction experience can be translated into executable robot capabilities and further improvements through embodied RSI (H1).
We first report results across the eight physical tasks, then examine continued improvement beyond first successful exploration rollout and the limits of agent-free execution. Frozen-program evaluation on RoboDojo provides complementary evidence on a broader task suite.
4.3.1
Real-world capability acquisition with agent
Physical exploration produces agent-free programs for seven of the eight tasks (Figure

Approximate time to first success ranges from 1.5 hours for block storage to 45 hours for Push T, indicating substantial variation in acquisition cost across tasks. Ethernet insertion remains unsuccessful without online agent participation in the reported development record.
Across the seven tasks with agent-free solutions, recorded development success ranges from 91.67% to 100% (Figure
5

4.4
Agent Coordination for Exploration
We examine H2 through physical development histories, asking whether specialized agent responsibilities help programs improve through successive physical trials. We analyze the cost of adding a reviewer to the engineer’s revision and testing cycle, then examine cases in which local revisions continue without resolving a stalled approach.
Figure 9
:
Coordination costs with and without a reviewer. (a) Result-to-next-trial intervals on a logarithmic scale; boxes show medians and interquartile ranges. (b) Six review–revision cycles before hardware execution in the Hanoi experiment. Review includes dispatch and review; Repair includes modification and resubmission. Bar-end labels show total cycle time. (c) Elapsed time in the reviewed phase and the subsequent direct-testing phase, which reaches the first verified disk-on-peg insertion.
An additional reviewer agent can slow down exploration.
We compare development records with and without a reviewer that inspects each submitted program before hardware execution. The reviewer can reject a submission but cannot modify it; the engineer must therefore revise and resubmit rejected programs. The median interval from reporting a result to starting the next physical trial is 16.9 minutes with the reviewer and 3.4 minutes without, across 40 and 9 recorded transitions, respectively (Figure
9
a). Six submission–rejection–revision cycles in the Hanoi experiment take 5.1–19.0 minutes each, with a median of 8.5 minutes (Figure
9
b), showing how review adds waiting before the next physical test. The reviewed phase records no verified disk-on-peg insertion over 45.0 hours, whereas the subsequent direct-testing phase reaches its first insertion 2.8 hours after the first grasp test (Figure
9
c). Because the phases are sequential, the later phase may benefit from earlier exploration, so the insertion timeline does not isolate the effect of removing the reviewer. The directly observed review delays nevertheless identify a coordination cost: assigning approval to a separate agent can reduce the rate at which the system obtains new physical evidence for improvement.
Task-level reassessment can break local revision deadlocks.
Repeated local revisions can leave exploration stalled when the underlying approach remains unchanged. Figure
10
shows seven simulated and three physical task histories in which unsuccessful trials are followed by success after task-level reassessment. A single Researcher is involved throughout each history; the intervention marks its reassessment of accumulated failures and redirection of the Engineer’s exploration. In all three physical cases, the next trial succeeds, with subsequent development records totaling 3/3 successes for stacking, 1/1 for towel folding, and 3/3 for Hanoi. Progress in simulation is less uniform: Push T records 11/17 successes after reassessment, while Imitate sorting sequence records 4/11. These histories motivate bounding local revision and returning unresolved failures to the Researcher for reassessment. They associate reassessment with renewed progress, without isolating its effect from continued exploration.

4.5
RSI Based on Execution Feedback
We examine H3 by investigating how execution experience becomes actionable evidence for embodied RSI. Physical diagnostic traces connect inspected observations to program revisions and subsequent validation, while a simulation study compares feedback interfaces under a fixed revision budget.
Reliable improvement requires reliable execution feedback.
Apparent execution failures can originate in perception or verification. In tic-tac-toe, merging two touching rings causes a false placement rejection; correcting the detector makes the same image pass the unchanged acceptance criterion, without moving the robot. In stacking, successful cycles still produce large reported block-return errors. Inspection reveals an unintended camera view; correcting view selection lowers the visual error estimates, but does not independently establish more accurate motion. Embodied RSI must therefore identify whether a discrepancy comes from execution or its measurement before revising control, perception, or verification.

4.8
Offline Coding: Execution Efficiency and Capability
We distinguish two coding modes by when agent-generated code is produced relative to deployment. In
offline coding
(PyRUA-REAL), agents develop and revise programs through physical exploration before deployment; the resulting code is then frozen and executes without language-model calls. Its sensing, conditional actions, and recovery logic still respond to live robot observations. In
deployment-time coding
(PyRUA-Lean), the agent writes and executes code during the task, uses execution feedback, and generates subsequent code as needed. A code segment can perform multiple actions and local checks, but execution still includes agent calls between segments. Figure
14
compares these modes with
online robot action inference without coding
, which selects actions from visual observations and robot state without writing code or accessing a shell.
Figure 14
:
Execution time and online thinking overhead.
Offline times are successful-run medians including reset; online bars show recorded times. Dashed outlines mark non-completion within 120 minutes with unmeasured timing splits. Development time is excluded.
Converting online exploration into fixed programs avoids repeated agent decisions(H6).
In offline coding mode, the programs for tic-tac-toe, five-block stacking, and Tower of Hanoi complete execution and reset without runtime language-model calls, with median successful cycle times of 8.99, 2.99, and 16.72 minutes, respectively. On tic-tac-toe and stacking, online coding with PyRUA-Lean takes approximately 4.6–5.0 times as long as offline coding with PyRUA-REAL; online action selection with GPT-6-Astra takes approximately 9.9–11.5 times as long (Figure
14
). Agent thinking accounts for 63–90% of the recorded online execution time. For stacking, PyRUA-Lean spends 10.6 of 13.7 minutes thinking; its remaining 3.1 minutes are close to the program’s 2.99-minute cycle. Thus, most of this observed timing gap comes from waiting for agent decisions. Neither online baseline completes Hanoi within 120 minutes. The comparison concerns execution time and excludes the cost of online exploration and program development.
Precise, contact-rich tasks can still require online agent assistance.
The efficiency of offline coding depends on whether the frozen program handles the conditions encountered during execution. Ethernet insertion, which requires precise connector alignment and contact with the port, exposes a limitation of the current code: the development records contain 0/4 successes with scripted execution and 10/17 with a workflow using GPT-6-Astra Medium for online decisions. This assisted workflow combines programmed motion with online assessment and decisions between stages; it does not yet provide agent-free execution in offline coding mode. In one successful run, motion takes 281.8 s and inter-stage checks and decision gaps take 220.8 s, accounting for 44% of the total 502.7 s. These gaps include visual checks and human review and therefore cannot be attributed entirely to agent thinking. The higher observed success rate supports retaining online assistance where the current program remains unreliable.
5
Discussion
Method selection can limit self-improvement.
The deadlocks in Section
4.4
suggest that progress can be limited by which methods an agent considers. Depth and calibration errors constrained geometric localization: stacking progressed with local visual alignment and contact feedback, while Hanoi combined coarse localization with wrist-camera feedback. In simulated general pickup, success improved after a human suggested SigLIP, a visual model the agent had initially overlooked. These cases indicate that the ability to implement and refine a method does not ensure that useful alternatives will be explored. A practical implication is to include explicit comparisons of alternative perception and control strategies when the current approach repeatedly fails.
Human assistance can shape the skills agents acquire.
The SigLIP case in the preceding paragraph illustrates how guidance can expand the methods considered during exploration. Human input also resolved an episode in which an agent repeatedly routed around a false contact detection. When human assistance was unavailable, the Hanoi agent developed a strategy for pushing hard-to-grasp disks into accessible positions; this strategy was later reused in tic-tac-toe. These observations suggest that intervention affects both immediate progress and the recovery skills retained for future tasks. Reports of autonomous improvement should therefore document what humans contributed and which operations the resulting program performs independently. The cases motivate studying when to intervene, without establishing an optimal level of assistance.
Offline programs may still need online agent assistance.
Successful online exploration and conversion into an executable program do not ensure that its encoded logic covers every situation encountered during evaluation. A fixed program can respond through its implemented perception, control, and recovery routines, but situations beyond those routines may still require an online agent to interpret observations and adapt the next action. The Ethernet insertion results in Section
4.8
illustrate this limitation of the current implementation: successful execution still uses online decisions between programmed motion stages. This suggests a deployment strategy that combines efficient offline execution with online assistance when the program cannot resolve an encountered situation. Determining when to invoke the agent and whether its decisions can subsequently be incorporated into reusable code remains an open question.
6
Conclusion
We investigated embodied RSI through real-world robot experiments with PyRUA-REAL, where coding agents accumulate physical experience as memory and executable skills. The real-world experiments demonstrate how physical exploration can produce progressively improved robot programs that retain acquired capabilities and execute without repeated agent decisions. This connects recursive self-improvement through physical interaction to efficient deployment, with progress assessed by the robust and independence of the resulting programs. Our findings provide an empirical basis for developing embodied RSI systems that turn physical experience into reliable robot capabilities for robustness deployment.

Appendix C
Physical Task Configurations and Completion Criteria
Tic-tac-toe.
The two arms alternate legal moves on a
3
×
3
3\times 3
board. The left arm places blue square-frame pieces and the right arm places red rings. A game terminates with a win or draw. The complete-cycle measurements also include clearing the board and returning the pieces to their respective sides.
Five-block stacking.
Five blocks initially lie on the table. The robot stacks the blocks to form a freestanding tower. Complete-cycle measurements include dismantling the tower in reverse order and returning the four upper blocks to their table positions.
Tower of Hanoi.
The robot sorts eight disks by size and places them onto the middle peg, from largest at the bottom to smallest at the top. This task evaluates ordered disk manipulation and repeated hole–peg alignment, rather than solving the conventional three-peg transfer puzzle. Complete-cycle measurements also include removing the disks and returning them to the table.
Ethernet insertion.
The robot grasps a yellow-booted RJ45 connector from the table and inserts it into the Ethernet port of a fixed computer chassis. Completion requires the connector to remain seated after the gripper releases it and retreats. Electrical connectivity is not evaluated.
Towel folding.
The towel initially lies flat on the table. The two arms grasp it and fold it over onto itself, requiring coordinated manipulation of a deformable object. Evaluation covers the folding operation only.
Push T.
The robot pushes a T-shaped object across the table to align its position and orientation with a target pose. Manipulation is performed through pushing, without grasping or lifting the object.
Block sorting.
The robot identifies orange and dark-blue blocks and places them into their corresponding color bins. Each trial covers sorting the specified blocks and combines visual discrimination with repeated pick-and-place operations.
Block storage.
The robot collects scattered blocks into a bowl. Success requires storing all blocks. Missed grasps followed by successful recovery remain part of the same trial.
