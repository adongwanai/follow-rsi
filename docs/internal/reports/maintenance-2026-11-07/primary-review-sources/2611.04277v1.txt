Abstract
Harness evolution from a common base exhibits
Locality
,
Complementarity
, and
Nonstationarity
: variants repair different failures, and their utility changes as the policy learns. Rather than seeking a universally superior harness, we introduce
Harness-S
to selectively rescue failures of a base execution system through
sibling harnesses
and transfer the resulting capabilities into a single policy that
remains effective under the original harness
.
Directional Harness Evolution
develops specialized
sibling harnesses
along distinct repair directions, forming a reusable
Sibling Harness Pool
that remains fixed during policy training.
Complementary Harness Rescue Training
invokes this pool only when all initial attempts under the base harness fail. The same policy generates fresh rollouts under selected auxiliary harnesses, and these trajectories replace the failed group for reinforcement learning. An
Adaptive Harness Router
selects the Top-
k
k
variants using
Harness Behavior Profiles
and voting across multiple LLMs.
Policy-aware profile re-anchoring
refreshes this evidence as the policy learns. Across AppWorld, SWE-Gym, and DBBench, the trained policy substantially outperforms policy-only training when returned to the original base harness. Behavioral analyses and held-out cases support the transfer of harness-elicited behaviors into the policy itself. Reusing the router for Rank-1 inference provides additional gains at the same executor rollout count.

Introduction
An agent’s behavior depends jointly on its model policy and its
harness
: the prompts, tool interfaces, context and memory mechanisms, and execution rules that govern interaction with the environment. Even with model weights held fixed, the harness shapes the information the policy receives and how its decisions become actions. ReAct demonstrates the value of interleaving reasoning and action
(
Yao et al., 2023b
)
, while SWE-agent shows how the design of the agent–computer interface affects task execution
(
Yang et al., 2024b
)
. Recent methods automate the optimization of prompts, workflows, and harness code from execution feedback
(
Hu et al., 2025
;
Zhang et al., 2025
;
Agrawal et al., 2026
;
Lee et al., 2026
)
. A central question is whether specialized execution support can improve the policy itself, so that its benefits persist under the original harness.

We study harness evolution from a common base
H
0
H_{0}
within a single execution system, a setting motivated by recent work such as Meta-Harness
(

, HarnessX
(

(

•
Locality.
Harness edits often repair a subset of failures while introducing regressions on previously solved tasks (Figure
1
a). Their effects depend on the failures being targeted, so successive variants develop distinct strengths.
•
Complementarity.
Sibling harnesses can recover one another’s errors. Their oracle union covers more tasks than individual variants or repeated sampling with
H
0
H_{0}
at the same rollout count (Figure
1

•
Nonstationarity.
A harness’s utility changes as the executing policy learns. Its advantage over
H
0
H_{0}
can become a disadvantage, and the ranking of variants can reverse across policy checkpoints (Figure
1
c).
These properties expose two limitations of harness optimization.
(i)
Combining local repairs into a universal harness is extremely difficult. Repairs may impose incompatible execution requirements, and even compatible edits can interfere with one another. A single accumulated design can therefore lose the strengths of its constituent variants.
(ii)
Coupled harness–policy evolution incurs substantial evolution cost and limits harness reuse. Alternating harness and policy updates
(
Chen et al., 2026b
;
Chen et al., 2026c
)
requires repeated generation and validation of variants as earlier repairs become less useful to the changing policy. Gains achieved by the evolved pair may also fail to transfer when the policy returns to the base harness
H
0
H_{0}
. We introduce
Harness-S
to selectively rescue failures of the base system with specialized sibling harnesses and
transfer the resulting capabilities into a single policy that remains effective under the original
H
0
H_{0}
.
Directional Harness Evolution
first develops variants along distinct repair directions. Starting from
H
0
H_{0}

uses this pool to expand exploration on tasks the policy fails to solve with

selects the Top-

These rescue rollouts replace the failed group for reinforcement learning, allowing the shared policy to learn from its own actions under complementary execution support. The objective is to retain the acquired behaviors when the policy returns to
H
0
H_{0}

The Adaptive Harness Router matches tasks to sibling harnesses using behavioral evidence and independent votes from multiple LLMs.
Harness Behavior Profiles

•

•

2.3
Recursive Self-Improvement
Recent surveys distinguish self-improvement by whether updates modify model parameters or the surrounding scaffold
(
Ren et al., 2026
)
. Program-level approaches improve optimization code or agent logic that supports subsequent improvements
(
Zelikman et al., 2024
;

(
Yuan et al., 2024

Zweiger et al., 2025

Its self-improvement loop operates over policy parameters and experience selection, with a fixed optimizer, verifier, and training-time harness pool, rather than recursively redesigning the improvement algorithm. Rescue Strategies (RQ3)
Task-specific allocation and profile refresh improve rescue at a fixed rollout budget (AppWorld, Qwen3.5-4B; Table
2

Random Harness samples pool members, while Rule Router (without Profiles) ranks them by success on similar validation tasks. LLM Router (

The fixed-profile Top-8 variant keeps its profiles unchanged, while Harness-S re-anchors them during training. Rescue success measures the fraction of rescue-triggering tasks with at least one successful rollout (Appendix

Task-specific selection improves rescue success across training stages.
Both rule-based and LLM-guided strategies outperform random selection throughout training. Top-8 Adaptive also exceeds LLM Router (

Adaptive profiles improve routing over a fixed-profile Top-8 variant.
With the rollout allocation held at one attempt per selected harness, re-anchoring yields higher rescue success in all four stages and improves final Avg@3 by 4.71 percentage points. This comparison supports updating the router’s behavioral evidence as the policy learns.
All evaluated rescue strategies improve final test performance over GRPO, with Top-8 Adaptive achieving the highest Pass@3 and Avg@3.

Policy Behavior (RQ4)
Harness-S changes how the policy gathers evidence and completes actions under
H
0
H_{0}
.
Table
3
compares concrete workflows of the base, GRPO, and Harness-S policies. On AppWorld, Harness-S consults API schemas before first use more often than GRPO and repeats execute code less often, while also increasing pagination, multi-call execution, and read-back after writes. These shifts suggest greater use of interface information and state verification, rather than a uniform increase in tool activity. The frequencies describe behavior, not correctness: more calls or checks are useful only when they serve the task.
The SWE-Gym trajectories show more explicit verification and recovery from blocked tests.

These patterns describe alternative ways to validate a patch when the standard test workflow is unavailable.

Conclusion and Future Directions
Harness-S trains a shared policy to retain capabilities elicited by complementary sibling harnesses under the original
H
0
H_{0}
. Directional evolution preserves distinct repair strategies, while selective rescue recovers learning signals from base-harness failures. Across AppWorld, SWE-Gym, and DBBench, gains persist under
H
0
H_{0}
; behavioral analyses support transfer, and Rank-1 routing improves inference. Future work will study lasting transfer and efficient pool reuse across policies. We will study how independently developed harnesses exchange task state across execution interfaces. Harness Scaling experiments will measure how additional repair diversity affects policy gains and calibration cost.

Appendix H
Extended Related Work
H.1
Agent RL Training
Interactive environments make action selection and observation handling part of the training problem. Toolformer learns API use through self-supervised examples, while AgentTuning initializes agent capabilities through instruction tuning on interaction trajectories
(
Schick et al., 2023
;
Zeng et al., 2023
)
. Such supervision can initialize tool-use behavior before reinforcement learning from task outcomes. WebGPT combines browsing demonstrations with human-preference feedback
(
Nakano et al., 2022
)
. ReTool learns to interleave reasoning with code execution, while Search-R1 learns multi-turn search interactions and masks retrieved content during optimization
(
Feng et al., 2025
;
Jin et al., 2025
)
. SWE-RL develops software-engineering reasoning from software evolution data with rule-based solution rewards
(
Wei et al., 2025
)
. The supervision source and action interface jointly determine which behaviors can be learned.
Long interactions introduce credit-assignment and rollout-quality problems beyond optimizing individual responses. RAGEN identifies instability associated with collapsing reward variation and studies how rollout diversity and feedback shape multi-turn learning
(
Wang et al., 2025
)
. LOOP trains agents directly in stateful environments such as AppWorld using a memory-efficient PPO variant
(
Chen et al., 2025
)
. AgentGym-RL explores a complementary curriculum, gradually increasing interaction horizons to balance early exploitation with broader exploration
(
Xi et al., 2025
)
. Agent Lightning separates execution from optimization and decomposes trajectories into transitions with assigned credit
(
Luo et al., 2025
)
. These directions distinguish the learning objective, interaction curriculum, and runtime interface through which training experience is collected.
Classical RL offers additional ways to learn when successful outcomes are rare or delayed. Hindsight Experience Replay reuses unsuccessful attempts by relabeling them with goals that were achieved
(
Andrychowicz et al., 2018
)
. RUDDER redistributes delayed rewards through return decomposition
(
Arjona-Medina et al., 2019
)
, whereas Go-Explore separates returning to promising states from exploring beyond them
(
Ecoffet et al., 2021
)
. These methods intervene in goal assignment, credit distribution, and state coverage, respectively. The distinction matters for language agents: changing how experience is generated and changing what an existing trajectory teaches are different interventions.
Uniformly rewarded groups limit the signal available to group-relative updates. PPO uses a surrogate objective to control policy updates, while GRPO estimates advantages from rewards within a sampled group
(
Schulman et al., 2017
;
Shao et al., 2024
)
. DAPO uses dynamic sampling to retain groups with reward variation, filtering groups whose samples are all correct or all incorrect
(
Yu et al., 2025
)
. Model-aware tool-use data evolution in LoopTool and hint-conditioned generative recommendation in HCGRec address related data and exploration bottlenecks
(
Zhang et al., 2026d
;
Zhang et al., 2026b
)
. Harness-S changes execution support before generating fresh attempts on the same failed task. It keeps the task and verifier fixed while seeking the successful alternatives needed for policy updates.
H.2
Knowledge Transfer
The form of supervision determines what a student can inherit from a teacher. Classical knowledge distillation transfers predictive distributions
(
Hinton et al., 2015
)
, while Sequence-Level Knowledge Distillation trains autoregressive students with teacher-generated sequences
(
Kim and Rush, 2016
)
. These approaches transfer information at different granularities: relations among candidate outputs versus complete generated solutions. The distinction is relevant when successful behavior consists of a sequence of decisions rather than a single prediction.
Multiple specialists can also be consolidated into a shared decision-making model. Policy Distillation combines task-specific reinforcement-learning policies into a single network
(
Rusu et al., 2016
)
. Kickstarting combines guidance from previously trained agents with continued reinforcement learning, allowing a student to benefit from several experts and improve beyond them
(
Schmitt et al., 2018
)
. The resulting learner can act without querying every original expert, separating the resources used to acquire a capability from those required to deploy it.
Additional computation and reasoning traces provide another source of transferable knowledge. Expert Iteration alternates tree-search planning with training a policy to generalize the resulting decisions
(
Anthony et al., 2017
)
. STaR trains on successful self-generated rationales, including rationales regenerated with access to the correct answer after failure
(
Zelikman et al., 2022
)
. Distilling Step-by-Step uses teacher-generated rationales as additional supervision alongside task labels
(
Hsieh et al., 2023
)
. These approaches differ in how they obtain useful traces, but all use richer training-time computation to shape a model’s subsequent behavior.
Transfer must also account for the distribution induced by the learner. DAgger aggregates expert-labeled states visited by successive learner policies to address distribution shift in sequential imitation
(
Ross et al., 2011
)
. Generalized Knowledge Distillation similarly obtains teacher feedback on student-generated sequences
(
Agarwal et al., 2024
)
. MiniLLM studies on-policy optimization of reverse KL divergence to limit student probability mass on outputs that the teacher assigns low likelihood
(
Gu et al., 2026
)
. Together, these works show why the training distribution and the matching objective are separate design choices.
Teachers may additionally have information that the deployed learner will not receive. Generalized distillation connects this setting to learning with privileged information
(
Lopez-Paz et al., 2016
)
; Learning by Cheating applies it to driving by training a vision-based policy from an agent with privileged environmental state
(
Chen et al., 2019
)
. VAD examines the source of multimodal teacher feedback through controlled visual-evidence interventions
(
Zhang et al., 2026c
)
. Harness-S instead obtains behavioral diversity by executing the same current policy under different harness contexts. Task outcomes supervise its trajectories, and evaluation under
H
0
H_{0}
tests whether useful behaviors persist when auxiliary execution support is removed.
H.3
Harness Editing and Reusable Skills
The execution interface determines how a language model’s outputs become actions. ReAct interleaves reasoning and environment interaction
(
Yao et al., 2023b
)
; SWE-agent and CodeAct study dedicated computer interfaces and executable code actions, respectively
(
Yang et al., 2024b
;
Wang et al., 2024b
)
. AutoGen extends the design space to configurable conversations among agents, tools, and human participants
(
Wu et al., 2023
)
. These systems establish different control structures and action representations that later optimization procedures can modify.
Execution support can be optimized at several levels of granularity. OPRO uses evaluated solutions to guide new prompt proposals
(
Yang et al., 2024a
)
. EvoPrompt applies evolutionary operators to prompt populations, while Promptbreeder also evolves the mutation prompts that generate candidates
(
Guo et al., 2025
;
Fernando et al., 2023
)
. DSPy compiles modular language-model pipelines against task metrics
(
Khattab et al., 2023
)
. TextGrad propagates textual feedback through computation graphs, and AFlow searches code-represented workflows with execution feedback
(
Yuksekgonul et al., 2024
;
Zhang et al., 2025
)
. AgentOptimizer treats an agent’s functions as adjustable parameters while keeping the underlying language model fixed
(
Zhang et al., 2024
)
. Thus, prompt editing, workflow search, and function revision expose different parts of an execution system to optimization.
Maintaining an archive supports exploration of multiple improvement directions. ADAS searches code-defined agents using previous discoveries, and the Darwin Gödel Machine branches from an archive of executable agents whose modifications are evaluated empirically
(
Hu et al., 2025
;
Zhang et al., 2026a
)
. GEPA combines trajectory-based reflection with complementary prompt candidates on a Pareto frontier
(
Agrawal et al., 2026
)
. Meta-Harness gives its proposer access to earlier implementations, scores, and execution traces
(
Lee et al., 2026
)
. Harness-R1 makes the editing policy itself learnable from the outcomes of its runtime changes
(
Shao et al., 2026
)
. Archive design and proposal learning therefore address distinct parts of search: retaining alternative behaviors and improving how candidates are generated.
Reusable tools and skills reduce the need to rediscover useful procedures. LLMs As Tool Makers separates a model that constructs reusable tools from one that applies them, allowing construction costs to be shared across later requests
(
Cai et al., 2024
)
. Voyager accumulates executable skills through interaction, while Agent Workflow Memory induces reusable routines from past experience
(
Wang et al., 2023
;
Wang et al., 2024c
)
. The reusable object can consequently range from a callable function to a workflow supplied as context, with different requirements for retrieval and execution.
Natural-language memory offers another way to preserve experience without immediately updating model weights. Reflexion stores linguistic feedback for subsequent trials, ExpeL extracts insights from past tasks, and ACE incrementally curates strategies in context playbooks
(
Shinn et al., 2023
;
Zhao et al., 2024
;
Zhang et al., 2026f
)
. MMSkills extends reusable packages to multimodal evidence; SkillRise and SkillGate learn skill curation and selection, respectively
(
Zhang et al., 2026e
;
Yao et al., 2026
;
Li et al., 2026
)
. Representing a procedure, deciding when to retrieve it, and retaining its benefits in policy parameters remain separate questions.
Execution resources can evolve jointly with the policy or be allocated during its training. Co-Harness and WHALE alternate harness and model optimization, while HarnessForge evolves coupled harness–policy systems
(
Chen et al., 2026c
;
Kim et al., 2026
;
Chen et al., 2026a
)
. HarnessBandit instead schedules one harness per optimizer step using learnability and cross-harness transferability signals
(
Wei et al., 2026
)
. Harness-S allocates a fixed sibling pool at the task level, invoking auxiliary harnesses after all initial attempts under
H
0
H_{0}
fail. Policy-aware profiles track which variants remain useful, while rescue trajectories update one shared policy. This links harness search to policy learning through complementary exploration, with base-harness evaluation separating retained policy gains from additional inference-time support.
