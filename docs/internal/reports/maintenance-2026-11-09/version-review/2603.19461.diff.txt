 6 Safety Discussion
 The DGM-Hyperagents (DGM-H) introduces distinct safety considerations due to its ability to autonomously
 modify its own behavior and improvement mechanisms over time. In this work, all experiments are conducted
 under strict safety constraints. In particular, agent-generated code is executed within carefully sandboxed
-environments with enforced resource limits (e.g., timeouts, restricted internet access). These measures are
-designed to prevent unintended side effects, contain failures, and ensure that self-modifications remain confined
-to the intended experimental scope. Moreover, evaluation is performed using predefined tasks and metrics,
-and human oversight is maintained throughout all experiments.
+environments (i.e., Docker containers with a restricted workspace and no general external network access)
+with enforced resource limits (e.g., timeouts, memory and compute limits). Test tasks are unavailable to the
+task and meta agents and are used only for final evaluation, which prevents direct test leakage but does not
+eliminate gaming of the training proxy. All prompts, tool calls, outputs, code diffs, failures, and evaluation
+results are logged, and these logs are released in our open-sourced repository for auditing. These measures
+are designed to prevent unintended side effects, contain failures, and ensure that self-modifications remain

+F Additional Limitations
+Our experiments use frozen, closed FMs; to support reproduction despite API versioning and stochasticity,
+we release all logs, prompts, splits, and agents. We measure progress in outer-loop iterations, which count
+opportunities to generate a new agent rather than a fixed amount of compute, since evolved agents are free
+to use more or fewer FM calls within each iteration (bounded by a timeout); we report cost estimates in
+Appendix D.2, and comparing methods under matched compute (e.g., tokens, monetary cost, CPU/GPU
+usage, wall-clock time) is a natural extension. In the paper review domain, performance measures agreement
+with historical human accept/reject decisions, and the DGM-H learns decision procedures that reflect these
+decisions; evaluating review quality directly, and controlling for acceptance priors and memorization of
+public outcomes, would further strengthen this domain. The robotics domain uses one quadruped robot and
+two tasks, and the same framework can accommodate additional robots and objectives by evaluating each
+agent on several tasks and aggregating their performance (Appendix A.4). Finally, improvement plateaus
+within a few hundred iterations in our settings, which may reflect the fixed task set and evaluation signal;
+expanding or co-evolving the task set, evaluators, and search strategy, and optimizing across more tasks to
+favor domain-general mechanisms, are promising ways to sustain progress at larger budgets.
