However, existing proactive interaction approaches are largely designed for explicit queries (e.g. “Notify me when a goal is scored.”), and isolated, single-turn requests ( Li et al., 2026a ; Kundu et al., 2026 ) , as illustrated in Figure 1 (i). However, these paradigm is less suited to real-world open-ended settings across three challenges, where ( i ) implicit user intents (e.g. “Help me finish this task whenever I get stuck.”) must be inferred from ongoing observations and interactions. Beyond identifying user intent, effective assistance requires ( ii ) task-relevant state tracking . As shown in Figure 1 (ii), prior interactions can change the environment and task progress, making a response that was appropriate earlier unnecessary or incorrect later. Although existing streaming models can retain long interaction histories ( Yao et al., 2026a ; Wang et al., 2025a ) , they still struggle to maintain an up-to-date state, resulting in repeated, outdated, or missed responses. Lastly, as shown in Figure 1 (iii), ( iii ) user intents is evolving as the interaction unfolds ( Tack et al., 2026 ; Tao et al., 2026 ; Yang et al., 2026d ) . Later feedback may introduce new goals, revise existing constraints, or shift the current focus, while existing methods often fail to update which intents remain relevant and instead continue to rely on earlier requests. These challenges make proactive interaction more than a problem of real-time long-context modeling: it requires the agent to continuously infer and update user intent while tracking the evolving interaction state. This motivates three key research questions forward “ Intent-aware interaction ”: How can we construct a testbed for proactive interaction with implicit user intent? How can such intent-aware interaction be internalized as a native model capability? How to flexible manage context to track environmental and user intent changes? In this work, we address these three questions through benchmarking, modeling, and agentic design. Firstly, we introduce StreamVibe-Bench, a unified intent-aware benchmark for sustained proactive interaction with 4.1K evaluation samples and 85K training samples spanning explicit, implicit, and dynamic user intents. Building on this benchmark, we further develop StreamVibe-VL, a streaming proactive model that infers implicit user intents and adapts its interactions as these intents evolve. Streaming supervised fine-tuning (SFT) jointly learns when and how to assist, while localized trajectory reinforcement learning (RL) focuses optimization on interaction-critical moments to improve response timing and quality. Lastly, we further develop StreamVibe-Harness, which maintains user intents as persistent, updatable states with flexible lifecycles, while hierarchical memory retrieves relevant history to keep subsequent decisions aligned with the current interaction context and user intent. Our main contributions are as follows: • To the best of our knowledge, we are the first work to study user intents in proactive streaming interaction. To this end, we construct StreamVibe-Bench, a unified benchmark with 4.1K evaluation and 85K training samples spanning explicit, implicit, and dynamic intents. • We introduce StreamVibe-VL, a proactive streaming video model that jointly learns when and how to assist under implicit and evolving user intents. • We develop the StreamVibe-Harness, which maintains updatable intent states with flexible lifecycles and hierarchical memory for consistent behavior over sustained interaction. 2 Related Work Streaming Video Benchmark. Early video benchmarks focus on offline understanding ( Fu et al., 2025a ; Zhao et al., 2025 ) , while online benchmarks evaluate sequential perception and response before video completion ( Li et al., 2025b ; Huang et al., 2025 ) . Recent proactive benchmarks further require models to decide when to respond, often using annotated trigger points and extending to egocentric or task-guidance settings ( Wang et al., 2025e ; Kundu et al., 2026 ; Ran et al., 2026 ) . However, most focus on a single intent type or environment and evaluate responses independently. StreamVibe-Bench instead unifies explicit, implicit, and dynamic intents across physical and digital tasks, with both pointwise and trajectory evaluation. Proactive Interaction Models. Online video-language models support continuous perception and low-latency responses ( Zeng et al., 2025 ; Cui et al., 2026 ) , while real-time and task-guidance systems further learn when to speak or provide assistance during ongoing interaction ( Sitong et al., 2026 ; Liu et al., 2026 ; Lu et al., 2026 ) . However, most existing approaches center on explicitly specified requests or task objectives, with limited support for tracking interaction state and adapting to evolving user intent over time ( Tack et al., 2026 ; Tao et al., 2026 ) . StreamVibe-VL targets open-ended proactive interaction, where intents must be inferred from user goals, environment changes, and task progress, and updated throughout the interaction. Memory and Agent Harness. Agentic systems increasingly incorporate persistent memory ( Xu et al., 2025 ) , planning ( Xiong et al., 2025 ) , reflection ( Yuan et al., 2025 ) , and reusable skills ( Zheng et al., 2025 ) to preserve and reuse historical context over long-horizon tasks. Recent memory systems further study how to retrieve, integrate, and abstract historical information into reusable experience for long-term interaction ( Yu et al., 2026 ; Chhikara et al., 2025 ) . However, these methods mainly organize and access past information without explicitly tracking evolving user intents and task progress, which can cause proactive responses to drift from the current interaction state. The agent observes a video stream 𝒱 = { v t } t = 1 T \mathcal{V}=\{v_{t}\}_{t=1}^{T} while the user may express one or more intents i j i_{j} over time, explicitly or implicitly, possibly before earlier intents are fulfilled. Each intent becomes available to the agent at time τ j \tau_{j} . Let ℐ ≤ t \mathcal{I}_{\leq t} denote all intents available by time t t , and 𝒜 t ⊆ ℐ ≤ t \mathcal{A}_{t}\subseteq\mathcal{I}_{\leq t} the currently active ones. At each timestep, the agent accesses only c t = ⟨ 𝒱 ≤ t , ℐ ≤ t , ℋ < t ⟩ c_{t}=\langle\mathcal{V}_{\leq t},\mathcal{I}_{\leq t},\mathcal{H}_{<t}\rangle and predicts a t = π ⁡ ( c t ) ∈ { silence , response } a_{t}=\pi(c_{t})\in\{\textsc{silence},\textsc{response}\} . If responding, it generates y t y_{t} for some i j ∈ 𝒜 t i_{j}\in\mathcal{A}_{t} , without access to future video or user inputs. Unlike retrospective VideoQA, relevant evidence may emerge only after an intent is expressed. Each intent i j i_{j} can correspond to one or more evidence points ξ j ​ k \xi_{jk} , each with a valid response window [ s j ​ k , e j ​ k ] [s_{jk},e_{jk}] and reference response y ^ j ​ k \hat{y}_{jk} . An evidence point is covered if the agent responds within its window with a semantically correct response to the corresponding intent. An intent remains active until all its evidence points are covered. The agent must therefore determine both when to respond and what to respond, while avoiding premature, missed, repeated, or irrelevant responses. 3.2 Hierarchical Difficulty StreamVibe-Bench characterizes proactive interaction along two dimensions: intent explicitness and intent dynamics . Existing benchmarks primarily focus on (i) Level 1: Explicit Intents , where the user specifies a condition, event, or state to monitor, and the agent responds when it occurs, e.g. Let me know when the water starts boiling. We further introduce (ii) Level 2: Implicit Intents , where the user provides only a high-level goal, requiring the agent to infer when and how to assist from ongoing observations and task progress, e.g. Help me keep an eye on this dish. Finally, (iii) Level 3: Dynamic Intents considers intents that evolve throughout the interaction. As the task unfolds, the user may provide multiple new inputs, requiring the agent to continually update the currently valid task state. We consider three common forms: Revision (RV) , which modifies an existing intent; Composition (CP) , which adds a new intent or constraint while preserving existing ones; and Interruption (IT) , which introduces an immediate request while the ongoing task remains active. These changes may occur repeatedly and in combination within a single interaction. 3.3 Benchmark Construction Task Collection. We collect task videos from both physical and digital environments to cover two complementary forms of proactive interaction. In (i) physical environments, assistance mainly relies on understanding continuous visual processes, including user activities, task progress, and emerging intents. In contrast, user intent in (ii) digital environments is often implicit in interaction trajectories such as navigation, content editing, and tool use, requiring the agent to infer user goals, constraints, and task state from the current interface and interaction history. The two settings thus capture user intent through physical behavior and digital interaction, respectively, covering proactive assistance across different interaction environments. Specifically, physical tasks mainly include egocentric daily activities and task execution, while digital tasks focus on GUI and computer-use scenarios. Annotation and Verification. For each video-request pair, we use Gemini-3.8-Flash ( Google DeepMind, 2026 ) to clean the data and identify candidate help points with response windows, preferred times, and reference answers. For dynamic intents, we further construct timestamped multi-turn interactions in which intents may be revised, extended, or interrupted as the task unfolds. Four reviewers then independently verify the user requests and response timing, correcting or removing samples without sufficient evidence and retaining only those approved by all reviewers. The validated annotations are aligned to 1 FPS streams and converted into causal interaction sequences for training and evaluation. Details are provided in Appendix B.3 . 3.4 Data Statistics Categories and Scale. Building on the three proactive interaction settings in Section 3.2 , we organize StreamVibe-Bench into finer-grained task subtypes, as illustrated in Figure 2 (b). The 600 Explicit Intents samples span Single Event (I), Transition (P), and Recurring Event (R). For Implicit Intents , 2,000 samples cover Guidance (G), Learning (L), Monitoring (M), and Tool (T). The remaining 1,500 Dynamic Intents samples consist of Revision (RV), Composition (CP), and Interruption (IT). Subtypes are evenly distributed within each category. In total, StreamVibe-Bench contains 4,100 evaluation samples, 20,546 help points, and 183.4 hours of video. Additional statistics and detailed explanations are provided in the Appendix B . Training Data Curations. We construct the StreamVibe-85K training set, consisting of 70K samples for supervised fine-tuning and 15K tasks for reinforcement learning. During supervised fine-tuning, we further incorporate 768K general streaming-video samples from sources including TimeChat-Online ( Yao et al., 2025 ) and VideoChat-Flash ( Li et al., 2025a ) to improve general streaming-video modeling. Detailed components are provided in Appendix B.4 . 3.5 Evaluation Protocol Settings. As illustrated in Figure 2 (c), two complementary evaluation settings are adopted to distinguish local proactive decision-making from sustained interaction behavior. (i) Pointwise Evaluation samples positive and negative timestamps around annotated help points and independently predicts whether the model should respond. Both Gold History and Self History are considered, where the former isolates local decision ability and the latter measures the effect of model-generated history. Independent evaluation avoids error accumulation across time. (ii) Trajectory Evaluation runs the model continuously over the full video stream, with each decision conditioned on prior observations and self-generated interaction history. This setting captures error propagation, requirement tracking, and repeated or missed responses. Together, the two settings evaluate local decisions under a given history and sustained interaction under self-generated history. Metrics. We evaluate models along two dimensions: response timing and response quality. Timing is measured by Precision, Recall, F1, and False Positive Rate (FPR), capturing response accuracy, coverage, and false activations. Quality is evaluated using Answer Score for overall correctness and relevance, and Content F1 for key-content alignment with reference answers. 4 StreamVibe: Grounding Evidence, Tracking Intent Overview. As shown in Figure 3 , the formulation in Section 3.1 highlights two key challenges in proactive interaction. (i) Evidence Grounding. The policy π \pi must ground each active intent i j i_{j} in emerging visual evidence ξ j ​ k \xi_{jk} and determine when and how to respond. We address this with a dedicated training framework that directly improves the streaming video policy. (ii) State Tracking. As intents evolve, maintaining an up-to-date active set 𝒜 t \mathcal{A}_{t} and interaction history ℋ < t \mathcal{H}_{<t} becomes challenging for the policy alone. We therefore introduce the StreamVibe-Harness ϕ \phi , which explicitly maintains these interaction states and provides π \pi with continuously updated context, c ~ t = ϕ ⁡ ( c t , 𝒜 t ) \tilde{c}_{t}=\phi(c_{t},\mathcal{A}_{t}) . This separates video-grounded response decisions from persistent state tracking: the Harness tracks dynamic intents and task progress, while response decisions and generation remain with π \pi . The Harness maintains an explicit interaction state 𝒮 t = ⟨ 𝒜 t , 𝒫 t , ℛ t ⟩ \mathcal{S}_{t}=\langle\mathcal{A}_{t},\mathcal{P}_{t},\mathcal{R}_{t}\rangle , where 𝒜 t \mathcal{A}_{t} denotes the currently active intents, 𝒫 t \mathcal{P}_{t} captures task progress and environment state, and ℛ t \mathcal{R}_{t} records previously delivered responses. As new user inputs and observations arrive, the Harness incrementally updates 𝒮 t − 1 \mathcal{S}_{t-1} to 𝒮 t \mathcal{S}_{t} by adding, revising, or terminating intents and updating task progress. State changes are applied only when supported by sufficient interaction or perceptual evidence, avoiding premature updates from uncertain observations. Intent Lifecycle. Each intent i j i_{j} is maintained as an independent stateful instance, allowing multiple intents to remain active and evolve concurrently. The Harness tracks its current status, relevant evidence, and completion state, and updates the lifecycle as the interaction unfolds. Persistent intents may remain active across multiple events, whereas one-time intents are closed once satisfied. Importantly, the lifecycle only determines which intents remain valid; when and how to respond are still decided by the agent policy π \pi . Hierarchical Memory. The Harness organizes past observations and interactions into hierarchical memory ℳ < t \mathcal{M}_{<t} , preserving relevant history without continuously expanding the agent context. Recent information is retained in fine-grained form, while older content is progressively compressed to preserve task-relevant entities, actions, constraints, and state changes. Given the active intents 𝒜 t \mathcal{A}_{t} and task state 𝒫 t \mathcal{P}_{t} , the Harness retrieves relevant history as m t = Retrieve ⁡ ( ℳ < t , 𝒜 t , 𝒫 t ) m_{t}=\operatorname{Retrieve}(\mathcal{M}_{<t},\mathcal{A}_{t},\mathcal{P}_{t}) , prioritizing recent and task-relevant information. The retrieved memory serves as additional evidence for the current decision without directly modifying the persistent interaction state. State Integration. Before each decision, the Harness integrates the persistent interaction state and retrieved memory with the causal context to obtain c ~ t = ϕ ⁡ ( c t , 𝒮 t , m t ) \tilde{c}_{t}=\phi(c_{t},\mathcal{S}_{t},m_{t}) , which is then passed to the agent policy π \pi for response decision and generation. After a response is delivered, the resulting interaction is written back to the state and memory for subsequent decisions. 4.2 Evidence-Grounded Policy Learning for Streaming Interaction Stage 1 : Adaptive Streaming SFT. Stage 2 : Localized Trajectory RL. Building on SFT, we introduce localized trajectory reinforcement learning. Full-trajectory optimization mixes correct and erroneous behaviors, leading to diffuse credit assignment and reward interference. We therefore construct short causal rollouts around annotated help points and optimize them with GRPO ( Shao et al., 2024 ) using complementary point-level and trajectory-level rewards. (i) Point-Level Reward. For each evidence point g g and predicted response p p , the temporal offset is defined as Δ g , p = t p − t g \Delta_{g,p}=t_{p}-t_{g} . Figure 5 and Figure 6 reveal three main findings. (i) Intent understanding remains difficult. Implicit and Dynamic Intents are markedly harder than Explicit Intents, indicating that agents struggle to determine what help is needed when intents are unstated or keep changing. (ii) Response selectivity is insufficient. Higher Recall often comes with more false triggers, suggesting that current methods cannot yet balance coverage against unnecessary responses. (iii) Sustained interaction amplifies these problems. Timing F1 declines steadily with interaction length; Revision shows a sharper late-stage Recall drop, and Composition exhibits weaker content quality, indicating difficulty in continuously updating intents while maintaining multiple constraints. Correct individual judgments are thus insufficient for stable proactive behavior throughout interaction. ♠ \spadesuit RQ3: Policy learning improves proactive decision-making, while state tracking enhances sustained interaction stability. As shown in Figure 6 (2), SFT makes the model more sensitive to potential assistance opportunities, leading to higher Recall but also more unnecessary triggers. RL further improves decision selectivity, substantially reducing FPR while also improving answer quality. Figure 6 (3) further shows that, with the policy fixed, adding the Harness continues to suppress unnecessary responses and improves content quality in most settings, with the clearest gains on Dynamic Intents. These results suggest that policy learning mainly improves local proactive decisions, whereas state tracking helps preserve valid intents and task progress over long-horizon interactions, thereby reducing outdated, redundant, or state-inconsistent outputs. Qualitative Analysis. Figure 7 illustrates how StreamVibe-VL assists users in representative physical and digital interactions. Across multiple assistance points within the same task, it grounds responses in the current visual evidence and task state, providing assistance at appropriate moments. In contrast, streaming baselines often respond before sufficient evidence appears or fail to update later responses as the task evolves, yielding premature, inconsistent, or redundant assistance. These cases show that our agent keeps both response timing and content consistent throughout sustained interaction. Additional qualitative examples are provided in Appendix D.2 . Across physical and digital tasks, StreamVibe-VL better aligns response timing and content with the evolving visual evidence and task state, while streaming baselines more often produce premature, missing, or inconsistent assistance. 6 Conclusion We study proactive interaction over streaming video, where user intents may be implicit, evolve over time, and must be tracked alongside a changing environment. We introduce StreamVibe-Bench, a unified benchmark spanning explicit, implicit, and dynamic intents with pointwise and trajectory evaluation; StreamVibe-VL, a proactive streaming policy trained with adaptive streaming SFT and localized trajectory RL; and StreamVibe-Harness, which maintains user intents and task progress as persistent interaction states. Experiments show that our model improves response timing and quality while preserving general video understanding, while explicit state tracking further reduces outdated and redundant responses. More broadly, real-world proactive interaction may involve richer intent evolution and tighter coupling between user needs and environmental changes than captured in our current setting. New observations, task outcomes, and prior assistance may jointly reshape both user needs and the environment, leading to new goals and constraints. Future work could further study such co-evolving interactions, particularly the complex feedback between intents and environmental states over longer horizons. Appendix B Dataset Construction and Evaluation Details This section consolidates the taxonomy, source provenance, training mixture, evaluation cohorts, and metrics summarized in the main paper. B.1 Overview of Evaluation Datasets Our evaluation covers proactive interaction and general video understanding. The former tests when to intervene and whether the response supports the ongoing task; the latter checks whether proactive policy learning preserves video perception and temporal reasoning. We describe the datasets below; protocols and metrics are detailed in Appendix B.5 . StreamVibe-Bench. Our primary benchmark evaluates sustained proactive interaction under Explicit, Implicit, and Dynamic Intents. Its 4,100 evaluation samples cover ten subtypes, ranging from responding to specified events to inferring useful assistance and tracking revised or interleaved requests. Pointwise evaluation isolates response decisions at individual timestamps, while Trajectory evaluation tests continuous interaction with model-generated history. The following subsections describe its taxonomy, sources, and construction. General-Timing. We construct General-Timing as a separate evaluation subset drawn from the publicly released training data of JoyAI-VL-Interaction ( Yao et al., 2026b ) . The selected samples are held out from our training: they are used for neither supervised fine-tuning nor reinforcement learning, and are reserved exclusively for evaluation. This subset tests response timing and content quality on additional streaming-video interactions beyond StreamVibe-Bench. We apply our Pointwise and Trajectory protocols and report results in Tables 11 and 11 . EgoProactive. EgoProactive ( Kundu et al., 2026 ) evaluates proactive procedural assistance from wearable, egocentric videos. Its annotations include out-of-plan deviations and recovery guidance, requiring an assistant to recognize task progress, decide when an interruption is useful, and provide appropriate corrective assistance. We use its official evaluation protocol to assess proactive assistance in physical task execution. IPIBench. IPIBench ( Li et al., 2026b ) evaluates interactive proactive intelligence under continuous video streams. It covers proactive monitoring, proactive task management, and interleaved reactive–proactive requests, including multi-turn interactions in which users add, modify, or cancel requests. It complements StreamVibe-Bench by testing the coordination of response timing and evolving interaction requirements under an external protocol. We follow its official evaluation setup; results for IPIBench and EgoProactive are reported in Table 11 . MVBench. MVBench ( Li et al., 2024 ) evaluates video understanding across diverse temporal tasks that require reasoning beyond a single frame. We use it to assess whether proactive policy learning preserves general temporal perception and reasoning, following its official evaluation protocol. Video-MME. Video-MME ( Fu et al., 2025a ) assesses video understanding across varied content domains and video durations. It complements MVBench by testing broader video comprehension over different temporal scales. We follow its official evaluation protocol and report the corresponding benchmark score. OVO-Bench. OVO-Bench ( Li et al., 2025b ) evaluates timestamp-aware online video understanding through backward tracing, real-time perception, and forward active responding. These settings test whether a model can recall relevant past events, interpret the current observation, and respond as a stream unfolds. We retain its official task definitions and evaluation metrics. OVBench. OVBench ( Huang et al., 2025 ) evaluates online video understanding as visual observations arrive over time. We use it to assess comprehension of ongoing video streams alongside the proactive interaction benchmarks, following its official evaluation protocol and reported metrics. B.3 Human Review Criteria and Inter-Annotator Agreement Review unit and acceptance rule. The review unit is a complete candidate sample: the source video, initial instruction, timestamped user turns, evidence windows, preferred response times, and reference answers. Four human reviewers independently assess the same sample against Table 16 . A reviewer approves a sample only when all applicable criteria are satisfied; a required correction counts as non-approval of the current version. A sample is retained only if all four reviewers approve the same final version. Thus, three approvals are insufficient. Samples with any objection must be corrected and reviewed again by all four reviewers, or discarded; changing an annotation invalidates approval of its earlier version. Unresolvable ambiguity or insufficient visual evidence requires exclusion rather than a guessed reference answer. Table 16: Human review rubric. Each reviewer checks every applicable criterion. Acceptance requires four independent approvals of the same sample version, with no unresolved issue. Criterion Standard for approval Intent fidelity The instruction is coherent and compatible with the task. The assigned Explicit, Implicit, or Dynamic category matches the interaction; inferred intents are supported by the user’s context, not invented. Evidence and causality Every annotated intervention has identifiable visual or interaction evidence available by its response time. Future frames and later user turns are not needed to justify the response. Coverage and non-redundancy Distinct, necessary intervention opportunities are covered, without duplicate evidence points or repeated assistance after the relevant intent has already been satisfied. Temporal validity Each response window and preferred timestamp correspond to a moment when the evidence is sufficient and assistance is still useful; the preferred time lies within the window and neither anticipates evidence nor misses the actionable moment. Reference-answer quality The reference is correct, relevant, and useful for the active intent. Dynamic-intent consistency For Dynamic samples, timestamped revisions, compositions, and interruptions are coherent. Appendix C StreamVibe-Harness Implementation Details This section provides implementation details for the four functional components introduced in Section 4.1 . StreamVibe-Harness maintains persistent interaction state and organizes causal evidence for the interaction policy. These components jointly support a single interaction process and should not be interpreted as four independent models. We use Qwen3-VL-4B-Instruct ( Bai et al., 2025 ) as an auxiliary visual-memory model for memory summarization and consolidation with greedy decoding, while the StreamVibe-VL checkpoint under evaluation serves as the interaction policy. State changes are represented as typed events with an identifier, timestamp, source, and payload. A deterministic update function applies valid events to the corresponding state fields and ignores duplicate updates. User instructions may introduce, revise, or retire requests; visual observations may establish task-relevant events; and observed progress or explicit user confirmation may update procedural state. A delivery record is created only after a response has been emitted to the user. We enforce source-specific update constraints so that information retains its semantic role across the interaction. In particular, a request specifies what should be monitored rather than what has already occurred; a reference plan describes possible future steps rather than completed actions; and an assistant suggestion is not treated as evidence of user progress. Fields without sufficient support remain unresolved. Historical evidence may be exposed to the policy as context, but cannot by itself create, revise, or retire an intent. Procedural memory retains at most eight completed steps and twelve evidence intervals that serve as temporal retrieval anchors. Progress is updated only when supported by observation or explicit confirmation. For event-monitoring requests, the auxiliary model additionally extracts and normalizes evidence from causal frames within a two-second window. This event parser updates evidence and event state only; it does not generate user-facing responses and therefore does not constitute a second action policy. C.2 Intent Lifecycle Each active intent is assigned a stable identifier and maintains an independent record of its criterion, associated event, evidence reference, and delivery status. A newly registered criterion begins in an evidence-waiting state. Once sufficient evidence supports a match, the criterion is linked to a concrete event instance. If the policy subsequently responds, the resulting delivery record identifies both the addressed event and the associated intents. This design allows multiple intents to remain active concurrently without treating a response to one intent as completion of the others. The lifecycle explicitly separates request validity from event coverage . Answering a one-time question closes that pending question. By contrast, reporting an occurrence under a standing request marks only that event instance as addressed while keeping the request active for future evidence. Closing an event returns the corresponding instance to an evidence-waiting state, whereas explicit user cancellation retires the request itself. These transitions update interaction bookkeeping rather than policy behavior: neither an active intent nor a matched event deterministically triggers a response. Skill library and selection. The Harness maintains ten fixed, read-only Skill records covering visual question answering, multiple-choice answering, event detection, explanation, hazard monitoring, milestone reporting, mistake monitoring, narration, next-step guidance, and stage summarization. Each Skill specifies request cues, evidence to inspect, response and waiting conditions, interaction cadence, and answer form. Skills are reusable behavioral specifications rather than neural models. Each active criterion maintains its own execution instance, including phase, evidence reference, event association, and delivery status. Skill selection first restricts candidates to those compatible with the current interaction type and requires non-empty observed memory, procedural context, or event context. A pending question prioritizes the question-answering Skill, followed by direct matches to active criterion types. If neither applies, lexical overlap between the request and observed context is used as a fallback, with at least two shared terms required. At most one Skill is selected for each context construction, and selecting no Skill is a valid outcome. For example, next-step guidance is conditioned on observed task progress, whereas event detection tracks a requested transition and whether the corresponding occurrence has already been reported. Importantly, selecting a Skill does not imply that its response condition has been satisfied. C.3 Hierarchical Memory Storage and consolidation. The memory system contains three levels: recent raw visual context, timestamped mid-term summaries, and older consolidated text blocks. Under the chunked-streaming configuration, we use T s = 32 T_{s}=32 steps per chunk, consolidate every M = 5 M=5 mid-term summaries, and retain up to L = 8 L=8 long-term blocks. At one step per second, each chunk corresponds to 32 seconds of video. The auxiliary model processes frames from the short-term buffer in chronological order, uniformly subsampling when the 64-frame input limit is exceeded, and conditions each summary on the current request. Consolidation of older summaries is performed using text-only input. Mid-term summaries preserve task-relevant object states, quantities, on-screen text, and temporal transitions. Intervals without meaningful change are collapsed, unsupported attributes remain unknown, and the most recently observed state is retained when visually established. Each ordered transition records its temporal interval, actor, action, object, prior and resulting states, temporal relation, and confidence. The mid-term summarization prompt is capped at 220 words, while procedural fields distinguish observed current and completed steps from request-supported references to possible next steps. Every M M consecutive mid-term summaries are consolidated into one long-term block using a 300-word prompt budget. Consolidation removes redundant static descriptions while preserving timestamps, distinct actions, temporal order, and supported procedural information. Each mid-term summary belongs to exactly one non-overlapping consolidation group. Once the number of long-term blocks reaches the capacity L L , older blocks are evicted in first-in, first-out order. To preserve causality under asynchronous execution, summarization is submitted before the chunk boundary using only frames already observed at submission time. Frames arriving afterward remain in the next short-term buffer, preventing gaps in temporal coverage. Mid-term inputs remain available while long-term consolidation is pending. If consolidation fails or produces an empty output, their concatenation is retained instead, preserving the available evidence without assuming that generated summaries are lossless. Indexing and retrieval. Summary facts are indexed using normalized text together with stable identifiers, source intervals, and lexical terms. Repeated observations of the same fact update its observation interval rather than creating duplicate entries. Ordered transitions are indexed separately to preserve event sequence. Request descriptions and reference-plan fields are excluded from the factual index, and response records remain separate from visual evidence. At retrieval time, the Harness constructs a focus string from the pending question, current request, and relevant procedural state. Candidate entries are ranked primarily by lexical overlap with this focus and secondarily by recency, with additional relevance assigned to entries overlapping task-relevant temporal anchors. Facts and ordered transitions are selected independently, with up to three candidates from each category and at most six entries before context projection. If no candidate matches the focus, the most recent entries are retained as a fallback. Selected transitions are reordered chronologically before projection. For native event-monitoring adapters, target retrieval is further restricted to at most three matching evidence lines, excluding negative or uncertain statements. No embedding model or learned retriever is used. The retrieval capacity is intentionally decoupled from the amount of evidence exposed to the policy. In the compact lifecycle projection, only the first rendered evidence line is retained and truncated to 180 characters; this line may contain a joined excerpt of multiple selected facts. For a pending question, the bounded fact and transition blocks may instead be exposed directly. Retrieved items are always treated as timestamped historical context, and current observations take precedence whenever they supersede an earlier state. C.4 State Integration Before each policy call, the Harness compiles the relevant state fields and retrieved evidence into a compact textual context and combines it with the causal video input, c ~ t = ϕ ⁡ ( c t , 𝒮 t , m t ) , \tilde{c}_{t}=\phi(c_{t},\mathcal{S}_{t},m_{t}), where c t c_{t} denotes the causal interaction context, 𝒮 t \mathcal{S}_{t} the persistent interaction state, and m t m_{t} the retrieved memory. The projected context explicitly distinguishes pending questions, observed progress, event status, delivery records, uncertainty, and historical evidence. Inactive or empty fields are omitted, and the full memory store is not appended by default. Within a context epoch, the header remains fixed while subsequent observations and actions are appended, allowing the policy to reuse the shared prompt prefix. Skill Projection for Policy Inference. Although each Skill stores a complete behavioral specification, the policy receives only the subset required for the current interaction. For single-criterion guidance, monitoring, and explanation, the projected context includes the selected Skill’s execution phase, evidence reference, response basis, and a compact cadence description. Question-answering and multi-criterion contexts expose only the answer-form field, while single-criterion narration retains a compact symbolic representation. The complete Skill specification is therefore not copied into the prompt, and Skill metadata does not replace policy generation. Request changes update the interaction type causally; after an intervening question is answered, the context of the standing request is restored. The interaction policy π \pi remains the sole component that decides whether to remain silent or respond and, when responding, generates the user-facing text. Once a non-empty response is delivered, its timestamp and intent/event associations are committed to ℛ t \mathcal{R}_{t} , while its exact text is preserved in the interaction history. Subsequent context projections may retain the most recent response verbatim and compress older responses into action markers. Assistant outputs are excluded from visual summarization. Response verification, cadence gating, and post-generation rewriting are disabled. Consequently, this feedback path records delivered assistance for future state construction without introducing new visual evidence or modifying the policy output.
