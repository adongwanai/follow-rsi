Recent work improves these systems through better harnesses and external memory, but relies on powerful closed-source models as planners and does not improve the planners’ own capabilities. In contrast, coding agents have improved substantially by post-training the model itself. We therefore investigate whether post-training can also improve robot planners. However, applying it across robot harnesses requires accommodating different execution mechanisms, including VLA skill invocation and control-code generation. To this end, we introduce AgenticRoboRL , a framework for post-training robot planners across different harnesses. The training recipe combines supervised fine-tuning with multi-turn reinforcement learning. To accommodate different execution mechanisms, harness-specific adapters connect recorded planner interactions with task outcomes, enabling a common RL training pipeline while keeping execution components fixed. On LIBERO-PRO, AgenticRoboRL raises the success rate of a 9B-parameter planner from 18.1% to 71.0% without external memory, approaching the 72.1% achieved by Codex (GPT-5.5) with external memory. These results demonstrate post-training as an effective approach for improving robot planners. Agentic robotics systems can perform complex manipulation tasks by combining a planner with a robot harness. The planner invokes VLA skills ( Zhang et al., 2026c ) or generates control code ( Liang et al., 2023 ; Fu et al., 2026 ) , observes the execution results, and decides what to do next over multiple rounds of interaction. Recent work has improved performance by refining robot harnesses and storing experience from task exploration in external memory ( Zhang et al., 2026c ; Xu et al., 2026b ) , with coding agents such as Codex and Claude Code ( OpenAI, 2025 ; Anthropic, 2025 ) serving as planners. However, these approaches primarily leverage existing planner capabilities and strengthen the support available to the planner. We explore a complementary direction: enhancing planners’ own capabilities to improve the performance of agentic robotics systems. For coding agents, enhancing the model’s own capabilities through post-training, including supervised fine-tuning and reinforcement learning, has proven highly effective ( Pan et al., 2024 ; Yang et al., 2026 ; Cao et al., 2025 ) . These advances raise a natural question: Can the post-training methods used for coding agents also improve the performance of agentic robotics systems? Applying these methods to robot planners is complicated by the fact that robot harnesses differ in how they carry out a planner’s response. In some harnesses the planner calls learned VLA skills, and a VLA policy executes each call. In others the planner writes control code over perception and control APIs, and a motion controller executes it. Harnesses also differ in what feedback they return to the planner and in how they decide whether the task has succeeded. Training planners across harnesses therefore requires a single pipeline that supports these different execution mechanisms. To realize such a pipeline, we introduce AgenticRoboRL, a framework for post-training robot planners across different harnesses (Figure 1 ). The training recipe combines supervised fine-tuning (SFT) with multi-turn reinforcement learning (RL). SFT trains the planner on successful demonstrations, providing a starting point for RL. During RL, we train on recorded planner requests and responses, while harness-specific adapters associate these interactions with episode outcomes. This allows the same RL pipeline to support VLA skill invocation and control-code generation without changing their execution interfaces. In both stages, only the planner is optimized, while the underlying execution components remain fixed (Figure 2 ). We evaluate the pipeline across these two execution mechanisms using a 9B planner. With RPent ( Zhang et al., 2026c ) , a harness that invokes VLA skills, SFT improves success on LIBERO-PRO from 18.1% to 65.1%, and RL further raises it to 71.0%, without external memory. The same checkpoint achieves 72.2% on LIBERO-Plus ( Fei et al., 2025a ) without additional training, compared with 19.2% for the original model. With the CaP-X harness ( Fu et al., 2026 ) , post-training improves success from 2.7% to 28.5%. These results establish post-training as an effective approach for improving agentic robotics systems. Our contributions are threefold: • To our knowledge, AgenticRoboRL is the first general post-training framework to agentic robotics systems. • AgenticRoboRL first fine-tunes the planner on successful demonstrations and then refines it with RL, updating only the planner while keeping execution components fixed. Lightweight harness-specific adapters link each recorded planner call to its episode outcome, so the harnesses do not need a shared low-level action representation. • Strong empirical results and an open release. With AgenticRoboRL , a 9B planner improves from 18.1% to 71.0% on LIBERO-PRO without external memory. This nearly matches Codex (GPT-5.5) with external memory (72.1%) ( Zhang et al., 2026c ) . With the CaP-X harness, it improves from 2.7% to 28.5%. We will release the AgenticRoboRL framework and trained planner checkpoints. 2 Related Work Robot harness agents. Language models can guide robot behavior by selecting learned skills or generating programs over perception and control APIs ( Ahn et al., 2022 ; Liang et al., 2023 ; Singh et al., 2022 ; Huang et al., 2023 ; Mu et al., 2024 ) . In this organization, the planner chooses how to use the available capabilities, while the harness executes its decisions and returns observations. Execution feedback and reusable skill libraries support interaction over multiple turns ( Huang et al., 2022 ; Wang et al., 2023 ) . Hierarchical systems place a language-level reasoning model above a learned low-level policy ( Belkhale et al., 2024 ; Shi et al., 2025 ) . Recent harnesses expose these capabilities to coding agents: Harness VLA combines a frozen VLA with analytic primitives and task memory ( Zhang et al., 2026c ) , while CaP-X provides interfaces for generating executable control code ( Fu et al., 2026 ) . General-purpose coding agents have also been applied to manipulation without robot-specific training ( Kumar, 2026 ; Jia et al., 2026b ) . Other systems improve perception, memory, safety, or skill libraries around the planner ( Li et al., 2026 ; Xu et al., 2026b ; Deng et al., 2026 ; Kagaya et al., 2025 ; Woods and Seifi, 2026 ) . A concurrent training-free approach, RV-ICL, provides on-demand access to a hierarchy of demonstration-video keyframes and clips ( Bao et al., 2026 ) . AgenticRoboRL instead improves the planner through SFT and multi-turn RL while reusing the harness’s execution components. Training planners for embodied agents. RL has been used to improve language and vision-language planners in embodied environments ( Fei et al., 2025b ; Chen et al., 2025 ; Liu et al., 2025 ; Wu et al., 2025 ; Jia et al., 2026a ) . CaP-RL applies RL to a code model that generates a complete control program in a single turn ( Fu et al., 2026 ) . In contrast, AgenticRoboRL trains planners that interact with the harness over multiple turns, and it applies to harnesses based on VLA skills as well as to harnesses based on control code. Closer to our supervised stage, Robo-Harness K1 and World Action Agent train 9B students on teacher trajectories collected within their respective harnesses ( Li et al., 2026 ; Zhang et al., 2026b ) . These methods use supervised training to transfer the capabilities of stronger agents. REAL combines SFT with online RL for mobile manipulation, using a rule-based planner for supervision and a shaped reward ( Mi et al., 2026 ) . AgenticRoboRL instead uses teacher-agent trajectories followed by multi-turn RL with task success as the sole reward. It adapts teacher supervision when the teacher and student have different prompts, tools, or access to memory. Post-training of tool-using agents. Coding-agent training commonly combines supervision from successful teacher trajectories ( Pan et al., 2024 ; Yang et al., 2026 ; Jain et al., 2025 ) with multi-turn RL on verifiable outcomes ( Cao et al., 2025 ) . Related approaches extend to search and computer-use agents ( Jin et al., 2025 ; Chen et al., 2026 ; Wang et al., 2025 ; Lai et al., 2026 ) . Frameworks including Agent Lightning and LEGO-RL separate agent execution from model optimization and construct training data from recorded interactions ( Luo et al., 2025 ; He et al., 2026 ; Du et al., 2026 ) . AgenticRoboRL builds on this approach for robot harnesses: a proxy records planner calls, and harness-specific adapters associate them with episode outcomes. The planner produces harness-native responses, including structured tool calls in RPent, the harness released with Harness VLA ( Zhang et al., 2026c ) , or executable Python code in CaP-X ( Fu et al., 2026 ) . The harness executes these commands and returns observations and execution feedback for subsequent decisions. We update the planner, not the perception modules, motion planners, or VLA executors it invokes. Because VLA skill invocations and generated control programs differ in representation and execution granularity, we place the shared RL interface at the model-call boundary rather than the low-level action boundary. During RL, the training unit is a recorded planner request, not a simulator step or a reconstructed full transcript. A recording proxy captures each request’s context, generated token IDs, and rollout log-probabilities at the model-serving boundary, following recent agent training frameworks ( Luo et al., 2025 ; Du et al., 2026 ; Xu et al., 2026a ) . Images and tool specifications are retained where applicable. This matters because a harness may prune images, omit previous reasoning, or otherwise transform its history between requests. The trainer checks its rendered prompt against the recorded prompt tokens; mismatched samples receive zero optimization weight. Training therefore uses the inputs associated with each sampled response rather than assuming that a final transcript reproduces them. Connecting interactions to outcomes. A harness-specific adapter reports, for every episode, five fields: the task, the initial-state identifier, the attempt index, the reward, and a validity flag. The first two define the group used for within-group comparison; the validity flag separates task failures, which remain reward-zero episodes, from infrastructure failures, which are excluded from optimization. Recorded model calls are then matched to their episode, and the pipeline checks record completeness and policy version before any sample is built. The adapter is plain conversion code with no learnable parameters: it provides a common training representation without imposing a common robot execution interface, and it does not alter the harness’s tools, prompts, or control loop. Appendix B lists the fields for our two harnesses. Policy-versioned rounds. Each round collects episodes under fixed planner weights, constructs training samples from the recorded interactions, and updates the planner before the next collection round. Multiple attempts share a task and initial-state configuration for within-group comparison. Collection, outcome processing, and optimization are separate stages; the planner is not updated during an episode. 3.3 Planner Post-Training 3.3.1 Supervised Fine-Tuning Teacher trajectories provide an initial policy for using the harness (Figure 2 (a)). A training example pairs a teacher response with the context the student would receive at that turn. This context can differ from what the teacher saw, because the two planners may run under different harness configurations or chat templates. How the student context is obtained depends on the harness. RPent. The teacher runs with a memory module that the student does not have. We therefore reconstruct each turn’s student context offline from the recorded episode, removing memory-access calls and their results. A response is flagged as dependent on memory if it contains keywords that refer to the memory, repeats eight consecutive words of the memory text, or contains a number that appears only in a removed memory result. Teacher reasoning and text that refer to memory are rewritten and checked by a judge, while tool-call arguments are kept unchanged. Only rewrites that the judge labels OK become training targets. After this processing, each turn is used as a training target, kept only as history, or dropped. Section 4.5 compares this recipe with excluding memory-dependent responses from supervision. CaP-X. Teacher and student share the same harness configuration, so no memory-related context reconstruction is needed. We take the recorded model calls of successful episodes, keep those that ended normally, and re-render each prompt with the student’s chat template. The teacher’s recorded output tokens are used directly as the target. Our main experiments use RPent, the VLA-calling harness released with Harness VLA ( Zhang et al., 2026c ) , and evaluate planners in it on LIBERO-PRO ( Zhou et al., 2025 ) . We additionally evaluate the base, SFT, and RL checkpoints on the 10,030 configurations of LIBERO-Plus ( Fei et al., 2025a ) to measure robustness without benchmark-specific training. To demonstrate the generality of the framework, we also attach it to a second harness, CaP-X ( Fu et al., 2026 ) ; its setup and results are given in Section 4.4 . Models and comparisons. We use Qwen3.5-9B ( Qwen Team, 2026a ) as the student planner and compare the original checkpoint with its SFT and RL counterparts. Qwen3.8-27B ( Qwen Team, 2026b ) provides teacher trajectories and serves as a larger-model performance reference. The execution components, including the VLA, remain frozen. Memory. Harness VLA provides task-specific memory of successful action sequences and global memory of rules and failure cases shared across tasks. Our 27B teacher uses the released memory files. For RPent, the 9B student is supervised using trajectories from this teacher. During RL rollouts and evaluation, the student does not access external memory. Data split. Each LIBERO ( Liu et al., 2023 ) task has 50 fixed initial states. Our evaluation follows the task-specific experience setting of Harness VLA ( Zhang et al., 2026c ) , where the agent explores each task on initial state 0 to construct memory and is evaluated on initial states 1–10. We retain the same task set and evaluation initial states, while extending this setting with planner post-training. Teacher demonstrations and RL rollouts are collected on states 11–44, which do not overlap with the evaluation initial states. States 45–49 are used only as a validation set for checkpoint and task selection. LIBERO-Plus was run after training settings were fixed. It uses the same underlying LIBERO tasks and adds perturbations that the planner did not see during training. Training. For supervised fine-tuning we use AdamW with a learning rate of 10 − 5 10^{-5} and a batch of 64 target turns, and we train for one epoch, which is 626 optimizer steps with RPent and 37 with CaP-X. RL uses a learning rate of 10 − 6 10^{-6} and a batch of 128 selected responses. Each RL round collects six attempts for each of 64 groups, where a group is one task with one initial state, and then updates the planner. This gives 384 episodes per round. Training up to the reported RPent checkpoint collects 2,304 episodes, selects 26,052 responses, and takes 206 optimizer steps. With RPent the reported RL checkpoint is selected by its success rate on the validation states 45–49. The SFT checkpoint at step 563 is selected among ten checkpoints on the same validation states. With CaP-X the reported planner is trained for 15 rounds. With RPent an episode ends after at most 100 planner turns or 7,200 seconds. To evaluate whether AgenticRoboRL applies beyond VLA skill invocation, we use it to train a planner in CaP-X ( Fu et al., 2026 ) , where the planner generates executable control code. We integrate the released CaP-X harness through the model-call proxy and a harness-specific adapter, reusing the training procedure described in Section 3 and Figure 2 . We compare the original, SFT, and RL checkpoints of the 9B planner within this harness. Following the task selection in CaP-X, we use the Object, Goal, and Spatial suites of LIBERO-PRO under position and task perturbations, comprising 60 tasks. Following the setting of CaP-RL, the RL experiment in the CaP-X paper ( Fu et al., 2026 ) , we use privileged state. The teacher and the original, SFT, and RL planners all use this setting during trajectory collection and evaluation, so the comparisons in Table 3 hold the execution interface fixed. The 27B planner provides teacher trajectories, and neither the teacher nor the student uses external task memory in this setting. We train the 9B planner through SFT followed by RL, using trajectories collected in CaP-X rather than transferring the RPent-trained checkpoints. The first excludes these responses from supervision (mask-only). The second rewrites them and retains those accepted by a judge as training targets (rewrite-and-filter), following the procedure described in Section 3.3.1 . The resulting datasets contain 27,110 and 40,047 target turns, respectively. As shown in Table 4 , after one epoch of training, mask-only improves the original 9B planner’s success rate from 18.1% to 55.2%, while rewrite-and-filter reaches 64.6%. Because the datasets differ in size, one epoch corresponds to 424 optimizer steps for mask-only and 626 for rewrite-and-filter. We therefore also examine their learning curves (Figure 3 ) to compare performance at similar update counts. Rewrite-and-filter achieves 60.2% at step 438, compared with 55.2% for mask-only at step 424. The advantage is thus also observed at comparable update counts, rather than only at the end of the longer training run. However, the two recipes differ in both response content and supervision coverage, so this comparison does not isolate the contribution of rewriting alone. The framework combines SFT on successful demonstration trajectories with multi-turn RL, connecting recorded model calls to episode outcomes while reusing the harnesses’ execution components. Experiments with a 9B planner demonstrate improvements in both VLA skill invocation and control-code generation. On LIBERO-PRO, success increases from 18.1% to 71.0%, and the same trained planner achieves 72.2% on LIBERO-Plus without additional training. These results support post-training the planner as an effective way to improve robot-harness agents without retraining their underlying controllers. We will release the framework, teacher trajectories, and trained planner checkpoints to support further research. Appendix C Training Details C.1 Supervised Fine-Tuning with RPent We fine-tune the 9B planner with AdamW, a learning rate of 10 − 5 10^{-5} , and a batch of 64 target turns. We use β 1 = 0.9 \beta_{1}=0.9 , β 2 = 0.999 \beta_{2}=0.999 , ϵ = 10 − 8 \epsilon=10^{-8} , and no weight decay. The learning rate rises over 10 warmup steps and then follows a cosine schedule that ends at 10% of its initial value. Gradients are clipped to a global norm of 1.0. The language model and the visual merger are updated, and the vision encoder stays frozen. The training set contains 40,047 target turns, so one epoch corresponds to 626 optimizer steps. The main results use the checkpoint at step 563, which is selected among ten checkpoints on the validation states 45–49 and is also the starting point for RL. C.2 Reinforcement Learning with RPent We run nine RL rounds and report the checkpoint after round 6. In each round the planner weights are fixed while rollouts are collected. A round covers 64 groups, where a group is one task with one initial state, and each group is attempted six times, which gives 384 episodes. Rollouts are sampled at temperature 1.0 without truncation of the token distribution. After outcomes and recorded model calls are validated, training samples are built and the planner is updated with several optimizer steps before the next round. We use a learning rate of 10 − 6 10^{-6} and a batch of 128 selected responses. At most 16 responses are selected from each episode. This limit applies to training samples and does not restrict the number of turns during execution. Groups in which all six attempts receive the same reward have zero advantage and contribute no training sample. Over the first six rounds, 2,304 episodes are collected, 26,052 responses are selected for optimization, and the planner receives 206 optimizer steps. The reported checkpoint is selected on the validation states 45–49, which are disjoint from the training and evaluation states. C.3 Training with CaP-X For CaP-X the teacher is the 27B planner in the same harness configuration as the student. We collect teacher episodes on the 26 tasks where the teacher solves at least one of the five validation episodes (initial states 45–49), and obtain 979 successful episodes with 2,370 target turns. Supervised fine-tuning uses the same learning rate, batch size, and warmup as with RPent and runs for one epoch, which is 37 optimizer steps. RL starts from this checkpoint and uses the same configuration as with RPent. Each round again covers 64 groups with six attempts. The groups are drawn from a pool of 35 tasks, which are the tasks where the SFT planner solves between one and four of the five validation episodes. Tasks that it always or never solves are left out because their groups would receive identical rewards. Rollouts on these tasks use initial states 11–44. The 35 tasks include all 26 tasks with teacher data and nine further tasks. The remaining 25 evaluation tasks are not used in training. Of the 35 tasks, 20 belong to the Object suites, nine to Goal, and six to Spatial. The reported planner is the checkpoint after 15 rounds. C.4 Episode Limits and Sampling Settings With RPent an episode ends after at most 100 planner turns or 7,200 seconds. With CaP-X a single response is limited to 32,768 tokens. The same limits are used for teacher collection, RL rollouts, and evaluation. Evaluation with RPent samples at temperature 1.0 with top-p 0.95, top-k 20, and a presence penalty of 1.5.
