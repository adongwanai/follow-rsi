Through a unified robot harness, agents read sensor data, write and execute programs, inspect recorded outcomes, repair failures, and reuse notes and executable skills while keeping their model weights fixed. We also introduce ASENA-VLN, a 4B monocular navigation policy that serves as an optional tool within this programmable system. ASENA-VLN predicts body-frame trajectories for both extended routes and short-horizon behaviors. Its shared vision-language decoder is trained on route instructions, visual question answering, and a newly curated dataset of geometry-derived atomic navigation tasks. As a standalone policy, ASENA-VLN achieves state-of-the-art success rates of 68.7% on R2R and 70.2% on RxR. When integrated with a coding agent, learned navigation improves ASENA’s success rate by 11 percentage points on both agentic benchmarks and reduces execution time. Persistent workspace evolution uses simulator feedback to improve success over ten passes through recurring 100-task subsets. Success increases from 72% to 98% on R2R and from 65% to 89% on RxR. On embodied question answering, ASENA achieves state-of-the-art accuracy with fewer interaction steps. On a Unitree G1, we demonstrate search, visual inspection, spatial reasoning, synthesized gestures, and mobile manipulation combining object pickup, carrying, and handoff without a pre-built map. The gallery illustrates navigation, inspection, grasp planning, object transport, handoff, and gestures across recorded demonstrations. https://research.nvidia.com/labs/gear/asena . \headingfont Abstract \absfont \theabstract 1 Introduction A useful humanoid robot must do more than reach a destination. If asked to check whether a vending machine contains an item and return with an answer, it must decide where to search, recognize the item, remember the user’s location, and communicate what it found. Retrieving an object from a room also requires planning a grasp, picking it up, carrying it back, and handing it to the user. Navigation is therefore only one part of a larger task whose next step depends on what the robot observes. A learned navigation policy provides movement capabilities, but such requests also require deciding what to inspect, how to act on objects, and what to communicate. These procedures depend on new observations and may extend beyond predefined skills. Coding agents can construct and revise them during a mission through programmatic access to sensing, computation, simulation, and action. Physical deployment also requires feedback tied to outcomes and a persistent workspace for retaining useful procedures. We present ASENA, an embodied agent system that gives coding agents programmatic control of humanoid tasks through a unified robot harness (Fig. ASENA: Self-evolving Agents for Embodied Navigation ). The agent can read sensors, derive geometry, inspect visualizations, and write programs that combine navigation, grasp planning, whole-body motion, and user interaction. Linked execution records let the agent inspect outcomes and revise these programs. A persistent workspace stores notes and executable skills. The system can improve through program revision while keeping its model weights fixed. Learned policies can further expand this programmable toolset when suitable training data are available. Delegating motion to a specialized policy reduces repeated agent decisions and supports navigation behaviors that are difficult to specify geometrically. We develop ASENA-VLN, a 4B monocular navigation policy trained on route instructions and geometry-derived navigation atoms. Building on vision-and-language navigation (VLN) [ 2 ; 20 ; 55 ; 8 ; 42 ] , ASENA-VLN predicts body-frame trajectories for both extended routes and short-horizon goals, such as approaching an object or passing through a doorway. We curate a new atomic navigation dataset that directly supervises these reusable, fine-grained behaviors and complements conventional route-level training. The policy remains an optional tool: a program may call it directly, combine it with geometric navigation, or complete a task using other available operations. We make three contributions. First, we introduce a robot harness that lets coding agents program humanoid navigation, manipulation, and interaction while retaining executable skills and experience. Second, we develop a state-of-the-art monocular navigation policy that supports both route following and reusable atomic skills. Third, we show through evaluation that workspace evolution improves task performance while model weights remain fixed. We evaluate navigation and embodied question answering (EQA) in simulation and demonstrate navigation, mobile manipulation, and user interaction on a real-world Unitree G1 robot operating without a pre-built map. 2 Related Work Code as policies Code as Policies [ 22 ] composes perception and control APIs in programs. We show more examples in Figure 6 . 3.1 Grounding Programs in Robot Feedback On G1, ASENA exposes a 360-degree camera, LiDAR, odometry, a body IMU, and joint states, with a calibrated head RGB/stereo camera for manipulation. The coding agent processes and visualizes these inputs to estimate geometry, inspect objects, and monitor execution. When an action differs from its intent, the agent can inspect the recorded evidence and revise its program. Navigation The agent can plan motion with geometric tools or invoke ASENA-VLN for language-conditioned navigation. Geometric tools use LiDAR-based occupancy maps to plan waypoints and check obstacle clearance. ASENA-VLN predicts bounded body-frame trajectories from language and recent monocular observations (Sec. 3.3 ). The agent chooses when to invoke each tool, checks progress through new observations, and revises the plan as needed. Manipulation SAM 2 [ 32 ] object masks and depth measurements ground candidate grasps. The system can supplement geometric proposals with learned candidates from GraspGenX [ 15 ] when additional grasp options are needed. Inverse kinematics and motion planning convert these candidates into trajectories for reaching, lifting, and carrying. Before execution, the system rebuilds arm trajectories from measured joint states and checks joint limits, sampled self-collisions, and scene clearance. These checks include held-object clearance during lift and retraction. A separate controller opens and closes the optional YAM parallel grippers and reports jaw width and controller state. The agent can compose these tools with navigation to program object pickup and handoff. Skill composition and execution ASENA exposes sensing, control, and safety operations as callable atomic skills. The coding agent combines navigation, grasp planning, arm trajectories, and gripper commands with computation and interaction logic to create reusable task programs. It writes and revises task logic and motion plans using execution feedback, while physical execution interfaces remain fixed. The SONIC whole-body controller [ 26 ] executes body motion. Gripper commands use the separate YAM controller, and speech uses the onboard speaker. Execution checks ASENA validates generated gestures online in MuJoCo for pose continuity, joint and motion limits, and sampled self-collision. Failed validation returns the violated constraint to the agent for repair. Physical motion requires validation and operator approval, including motion requested by revised programs. An independent navigation safeguard enforces motion limits and rejects commands when odometry is stale or the battery level is low. These records align sensor and robot states with actions, feedback, code, and visualizations. Replaying this evidence lets the agent identify where execution diverged from its intent and repair the responsible program. After repairing a failure, ASENA can retain the solution for future tasks. A fixed coding model consults this workspace while solving tasks. On G1, execution records and optional operator feedback support skill revision while robot motion is disabled. 3.3 Learning a Reusable Visual Navigation Policy ASENA-VLN reduces repeated agent reasoning on challenging routes. This optional tool predicts bounded body-frame trajectories from language and recent monocular observations. The coding agent decides when to invoke it, checks progress, and combines it with other tools. Policy training expands navigation capabilities within the same programming interface. Policy inputs We extend a lightweight Qwen3-VL-4B-Instruct [ 3 ] with dedicated token vocabularies for trajectories and pixel goals (Fig. 3 ). The model takes up to eight front-view frames and a structured JSON instruction. This interface makes the policy easy to invoke as a callable tool. The instruction specifies a concise navigation command and can optionally include a desired end pose, anchor objects, or motion constraints. Recency-weighted visual tokens preserve temporal context while emphasizing the latest observation. Output representations A shared autoregressive decoder predicts up to eight cumulative body-frame waypoints, each represented as ( x , y , θ ) (x,y,\theta) . Fixed bins along each axis convert trajectory tokens into explicit motion targets without requiring a separate continuous action head. Pixel-goal tokens provide auxiliary supervision by encouraging the model to localize its intended destination in the image. Visual question answering retains the model’s original text vocabulary. A pixel goal is not directly executable and requires an additional motion planner or, in simulation, a shortest-path follower. All evaluations in this paper therefore use trajectory-token predictions rather than pixel goals. Curated atomic-navigation data A callable navigation policy must follow both extended routes and precise local commands. We therefore curate nine atomic navigation tasks in MP3D and HM3D. They cover behaviors such as moving a specified distance, rotating to a target heading, approaching an object from a given direction, aligning with a target, entering a room, passing through a doorway, following a corridor, and moving between floors. We generate and validate each task using geodesic distance, visibility, and scene geometry so that every instruction describes a feasible and measurable motion. Each instruction is paired with a waypoint trajectory and auxiliary pixel-goal supervision. These data directly teach the reusable, fine-grained operations that task programs can invoke and compose. Training mixture We train ASENA-VLN on a mixture of these atomic tasks, short-horizon ObjectNav, and vision-language-navigation data from R2R, RxR, ScaleVLN, and SRDF [ 2 ; 20 ; 40 ; 39 ] . We also include multi-view VQA data [ 4 ] to strengthen the model’s spatial understanding. To match our callable policy interface, we use GPT-5.5 [ 28 ] to re-caption the original navigation instructions into our structured JSON format. The re-captioned instructions include concise navigation commands and, when applicable, end poses, anchor objects, and motion constraints. The reported checkpoint uses fewer than 10K optimizer steps and fewer than 5M training samples, including repeats. Training uses a 3:1 mixture of trajectory prediction and spatial VQA. In each pass, sixteen Claude Sonnet 5 workers at high effort execute the tasks and may retain programs, notes, and prior action sequences in private workspaces. Between passes, an improver uses their traces and feedback to update the canonical workspace. We run campaigns with and without ASENA-VLN on R2R and RxR using ground-truth feedback, while keeping all model, policy, and controller weights fixed. As shown in Fig. 4 , success improves across all four campaigns. Logged worker and improver costs decrease as the workspace evolves. These results show that retained experience can improve recurring-task performance and reduce cost without updating model weights. The variants with and without ASENA-VLN reach similar final success rates on R2R, while the policy retains a clearer advantage on the longer RxR instructions. Tool-equipped workspaces also maintain higher SPL on both benchmarks, showing that ASENA-VLN improves path efficiency even when final success rates converge. We evaluate ASENA on HM-EQA and MT-HM3D using their released initial poses [ 33 ; 51 ] . Following the Explore-EQA teleportation protocol, each episode has a nominal step budget of 3 ​ A 3\sqrt{A} for a scene of area A A . We report answer accuracy and normalized exploration steps, defined as the fraction of this nominal budget consumed by the agent. Hand-designed reference configurations Our EQA agent composes navigation, visual inspection, object search, place memory, and answer-generation tools. We first construct two hand-designed configurations as reference points. The quality configuration prioritizes collecting sufficient evidence to answer correctly and receives no explicit instruction to minimize exploration. The efficient configuration is prompted to treat exploration steps as a limited resource and gather evidence more selectively. On HM-EQA, we give the efficient agent a target budget equal to 30% of the nominal allowance, while retaining the same simulator hard limit for both configurations. These configurations provide manually designed operating points for accuracy and efficiency rather than a controlled ablation of a single component. Workspace-evolution protocol We next study whether the agent can improve this tradeoff by revising its workspace. We construct fixed evolution pools containing 398 HM-EQA questions and 1,183 MT-HM3D questions from training scenes. During each pass, sixteen workers sample 50 questions from each benchmark, execute them using private workspaces, and reflect on their outcomes. A separate improver aggregates their traces and edits to update the canonical workspace, while all model weights remain fixed. Questions not sampled by the workers are used for monitoring, and their aggregate results are also provided to the improver. Workspace evolution improves the tradeoff between cost and accuracy With workspace frozen, pass 17 achieves the highest HM-EQA accuracy (81.2%), while pass 4 performs best on MT-HM3D (66.5%) (Table 5 ). At low reasoning effort, evolved workspaces use steps comparable to the hand-designed efficient configuration while achieving higher accuracy (Table 4 ). Improvements vary across revisions as the workspace adds new routines and refines existing guidance. These revisions produce different tradeoffs between accuracy and exploration efficiency. Learned navigation reduces exploration In a paired ablation on 132 MT-HM3D questions, ASENA-VLN reduces median normalized exploration steps by approximately 19% with little change in accuracy. Consistent with our previous R2R and RxR results, learned navigation improves efficiency by reducing repeated agent interaction. 4.6 Real-World Applications We present four demonstrations of ASENA on a Unitree G1 (Fig. 5 ). All four operate without pre-built maps and combine navigation with search, user interaction, or object delivery. The agent gathers visual and geometric evidence and maintains spatial memory. It writes or revises programs that connect perception and planning with physical actions (Fig. ASENA: Self-evolving Agents for Embodied Navigation ). The three search missions (Fig. 5 A–C) take place in previously unseen environments. Search targets are initially outside the robot’s view. In the restroom mission, the robot locates doors near the elevator lobby. It uses its online map to identify a shorter route from the user and returns with directions. In the pantry mission, it locates the room, inspects a dispenser and brewer, and reports two coffee machines. In the snack-comparison mission, it inspects a reference snack and finds a vending machine. It checks whether the same item is available, then returns to answer the user with a generated whole-body gesture. These tasks combine online search and spatial reasoning with evidence collection, memory, and multimodal communication. The fetch-and-handoff task (Fig. 5 D) demonstrates humanoid mobile manipulation by combining navigation, object pickup, carrying while walking, and handoff. After reaching the pantry, the agent uses a head-camera observation to locate the can and ground a grasp. It inspects an arm-motion plan, then uses a YAM gripper to pick up the can. The robot walks back while carrying it. A separately programmed handoff uses inverse kinematics to position it above the recipient’s hand before releasing the gripper. This qualitative demonstration combines navigation, grasp planning, and arm control through the same programming interface. 5 Discussion and Conclusion ASENA unifies coding-agent programming, robot execution, and persistent skills. It improves recurring-task performance while model weights remain fixed. Our optional 4B monocular ASENA-VLN policy, trained on curated atomic-navigation data, achieves leading R2R/RxR success rates with fewer agent interactions. ASENA also achieves leading EQA accuracy. On G1, online programming extends navigation to search, inspection, and interaction. The agent synthesizes whole-body responses online. Several limitations remain. The G1 demonstrations provide qualitative evidence of capability composition rather than a systematic measure of reliability across objects, layouts, and users. Real-world tasks take 10–20 minutes, making faster reasoning and execution important for practical use. Future work should evaluate retained skills on new tasks, measure navigation and manipulation reliability over repeated real-world trials, and strengthen safeguards for dynamic environments. Another direction is to extend workspace evolution to both learned policy and agent updates. A.2 Jetson Thor Quantization and Runtime To run the policy on the G1’s Jetson AGX Thor, we apply post-training FP8 quantization with NVIDIA ModelOpt. We build inference engines with TensorRT-Edge-LLM. These measurements use an earlier ASENA-VLN checkpoint at step 8,400, separate from the benchmark policy in Table 1 . Every FP8 variant quantizes the language model. Variants labeled “BF16 vision” keep the 415M-parameter vision encoder in BF16. We leave the embedding and output projection unquantized in all variants. Navigation-only engines need to predict motion tokens rather than general text. We therefore reduce the output vocabulary from 152,596 to 768 entries while retaining all 660 trajectory tokens. This removes 388.7M parameters from the output projection evaluated at each decoding step. Measurement protocol All variants use batch size 1, the same eight-frame mixed-resolution history, and 32 greedy decoding steps. BF16 values are warm medians of five runs. Prefill is time to first token minus visual encoding. Decode scales the remaining 31 tokens to 32 steps. TensorRT-Edge-LLM visual and prefill values are 10-run means. Decode is the median of five runs. Measured BF16 end-to-end latency is 2,735 ms. The BF16 model occupies 8.28 GiB of allocated memory after loading. This is not a peak runtime measurement.
