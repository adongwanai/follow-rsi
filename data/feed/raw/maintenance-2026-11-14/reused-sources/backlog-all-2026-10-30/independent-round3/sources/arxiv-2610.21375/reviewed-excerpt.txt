For a frozen LLM, access to this accumulated knowledge is limited to what a memory system places in its context window. However, gathering and combining relevant information needed for each query while keeping the model’s context short remains challenging for existing systems. Here we introduce Memorilla , a memory system that gathers information from an entire document collection into a fixed number of query-dependent ‘memory tokens’ for a frozen LLM. Memorilla encodes documents (such as user chats, book chapters) once into reusable embeddings, then learns to retrieve and place query-specific information in the LLM’s input embedding space. Using only 16 memory tokens, Memorilla achieves the best average performance against baselines including Mem0 and MemoRAG across benchmarks spanning personalization, long-document and knowledge-intensive question answering. Notably, on FactKG, it reaches 84.33% accuracy versus 80.43% with full-context inference, while using 108 × \times fewer tokens to represent the source documents. Furthermore, Memorilla can facilitate continual learning in agentic systems where the document count (the agent’s past turns) increases throughout the trajectory. In a TextWorld environment, we show that Memorilla reduces the agent’s tendency to wander between rooms it has already explored, and improves its average success rate from 18.6% with full-history in-context learning to 24.2%. Personal assistants must recall a user’s history across months of conversations, question-answering systems must reason over documents far longer than the model’s context window, and agents must act on everything they have observed. None of this information exists in the model’s parameters, and a frozen LLM can use it only through its context ( Hu et al., 2025 ) . A memory system bridges this gap by encoding accumulated information, storing it persistently, and retrieving what each query needs into the context ( Wu et al., 2025 ) . The central challenge for such a system is to give a frozen LLM access to an entire, growing collection of knowledge while keeping its context short ( An et al., 2025 ; Du et al., 2025 ) . Existing memory systems address these issues only in part. Agentic memory systems such as MemGPT ( Packer et al., 2023 ) , Mem0 ( Chhikara et al., 2025 ) and A-MEM ( Xu et al., 2025 ) organize past interactions into summaries or structured records, and MemoRAG ( Qian et al., 2025 ) uses a compressed global memory to guide retrieval, but each ultimately places selected text in the context and inherits the limits of selection. Latent compression methods such as ICAE ( Ge et al., 2024 ) , IC-Former ( Wang et al., 2024a ) , AutoCompressors ( Chevalier et al., 2023 ) and ComMer ( Zeldes et al., 2025 ) represent documents as a few soft tokens in the LLM embedding space, but they form these tokens without the query, so the same tokens must serve every question. xRAG ( Cheng et al., 2024 ) incorporates query relevance but only by compressing a single retrieved document. Methods that store model-specific hidden or key–value states, such as LongMem ( Wang et al., 2023 ) , MemoryLLM ( Wang et al., 2024b ) , M+ ( Wang et al., 2025 ) , and Cartridges ( Eyuboglu et al., 2026 ) , tie the memory to one model and require training the LLM, a side network, or a separate cache for each corpus. What is missing is a memory system that will retrieve query-relevant information from document embeddings directly into the input embedding space of a frozen LLM. Benefits of such an approach would be that the frozen LLM can retain all of its capabilities, and rely on only a few query relevant latent embeddings to answer questions or solve tasks instead of processing long textual contexts in a slow and lossy manner ( Liu et al., 2024 ) . In essence, improving the speed and quality of LLM responses and also the decision making in LLM agents based on past experiences. Figure 1: Performance versus context length. Here we introduce Memorilla , a memory system that learns to retrieve query-relevant information from document embeddings directly into the input embedding space of a frozen LLM (Figure 2 ). First, a frozen embedding model encodes each document, such as a user conversation or a book chapter, once into a persistent memory store. Next, for each query, a trainable memory module attends to every embedding in the persistent memory store and performs a query conditioned memory readout for the LLM. Unlike RAG which retrieves a subset of documents as textual tokens, Memorilla learns to recall what matters from the entire collection for a query, and expresses it as K = 16 K=16 latent memory tokens for a frozen LLM, and does not require the documents to enter the context as text. Because the store uses the same embeddings as a dense retrieval index, encoding adds no cost over retrieval, and with 512 documents on one H100, Memorilla has 27 × \times lower end-to-end latency than full context answer generation (0.74s against 19.9s, Appendix F ). Our benchmarks mirror three settings in which deployed LLMs need memory (Figures 1 and 3 ). In personalization, an assistant must adapt to preferences a user rarely states directly, whether answering questions that depend on traits revealed across past conversations (PersonaMem-v2, PersonalizationV4) or writing in the style of the user’s earlier text (LaMP-4, LaMP-7). Because a user’s preferences rarely share wording with the query, similarity-based retrieval struggles to find and combine relevant information. Notably, on LaMP-4, Memorilla reaches 18.15 ROUGE-L against 14.21 for full context while using 474 × \times fewer document tokens. In knowledge-intensive question answering, such as checking a claim against a knowledge base, Memorilla outperforms full context on FactKG (84.33% against 80.43%) with 108 × \times fewer document tokens. In long-document understanding, the answer is buried in thousands of tokens of text and often phrased differently from the question, so a system must find and connect relevant content across the entire document. On TriviaQA, whose questions were written independently of their source pages, Memorilla reaches the highest exact match (57.00) with 743 × \times fewer document tokens than full context. Beyond answering questions, Memorilla allows agents to learn continually from their own experience. In this work, we consider the TextWorld environment ( Côté et al., 2018 ) where an agent must explore rooms, find and use objects, and complete a multi-step goal within 50 turns, which requires remembering where it has been and what it has already tried. After every turn, Memorilla adds that turn to its document store and draws on this experience at the next turn. With our approach, the agent completes 37.5% of held-out games in at least one of three attempts, against 25.0% for the same agent given its full history in context. Overall, Memorilla improves the agent’s ability to escape navigation loops and execute action sequences that are crucial to reaching the target. 2 Memorilla A persistent latent memory must preserve a document collection across queries while recalling different information for each query. Memorilla meets these requirements through three operations: encoding , storage , and retrieval . Given N N document chunks 𝒟 = { d 1 , … , d N } \mathcal{D}=\{d_{1},\ldots,d_{N}\} , a frozen encoder produces a query-independent representation that is stored once. For instance, 𝒟 \mathcal{D} can be a collection of N N user-LLM conversations, chapters of a lengthy book, or health records. For each query q q , a trainable memory module reads this store and returns K K query-conditioned soft memory tokens, which a frozen LLM consumes together with the query text. The loss is applied only to answer positions, not to the prompt or memory positions. 2.5 Memorilla with Qwen3 Based on the formalization above, we instantiate Memorilla with f enc d f_{\mathrm{enc}}^{d} and f enc q f_{\mathrm{enc}}^{q} as a frozen Qwen3-Embedding-4B model. Unless stated otherwise, we fix K = 16 K=16 throughout the paper and use a Qwen3-8B model as the frozen LLM. This gives us 194,123,776 trainable parameters. 2.6 Training Stages We use a three-stage curriculum that moves from general content preservation to diverse language tasks and then to the evaluation domains. See Appendix B.2 for training hyperparameters. Stage 1 trains the memory module on 1.98 million English Wikipedia paraphrase reconstruction examples. Each passage is divided into document chunks, and the module must preserve enough information in its fixed memory budget for the frozen LLM to generate a paraphrase. This stage provides a general initialization before the module encounters task-specific supervision. Stage 2 continues training on 1.34 million examples drawn from ten datasets covering reading comprehension, open-domain question answering, and summarization. The variation in source structure and answer format teaches the module to recall different information from the same type of stored representation. Table 1 lists the component datasets and their sizes. Stage 3 fine-tunes the resulting module on a unified mixture of the training splits from all eight evaluation benchmarks. One multi-task checkpoint is used directly for FactKG, TriviaQA, NarrativeQA, PubMedQA, LaMP-4, and LaMP-7. PersonaMem-v2 and PersonalizationV4 receive additional benchmark-specific fine-tuning because their validation losses required more epochs to plateau, while the other benchmarks plateaued or began to overfit earlier. 3 Experiments 3.1 Baselines We compare Memorilla against RAG approaches based on cosine similarity, Mem0 ( Chhikara et al., 2025 ) , and MemoRAG ( Qian et al., 2025 ) . xRAG ( Cheng et al., 2024 ) and ComMer ( Zeldes et al., 2025 ) (via its reported results, Table 12 ) compress the context into latent input embeddings for the LLM. Finally, we also compare against LLMLingua-2 ( Pan et al., 2024 ) , which is a task-agnostic text based prompt compression method. All baselines we run use a frozen Qwen3-Embedding-4B encoder for document embeddings and a frozen Qwen3-8B decoder for generation. Mem0 and MemoRAG additionally use a frozen Qwen3-4B-Instruct-2507 to build their memories, matching the 4B scale of the encoder with which Memorilla reads the same collections (Appendix C ). 3.2 Benchmarks We evaluate Memorilla on eight supervised benchmarks spanning (a) personalization, (b) long-document QA, and (c) knowledge-intensive QA tasks that demand memory. For personalization, we consider PersonaMem-v2 (PMv2) ( Jiang et al., 2025 ) , LaMP-4, LaMP-7 ( Salemi et al., 2023 ) and our own PersonalizationV4 (PV4) benchmarks as they require integrating information scattered across a user’s prior chats or writing history to form a coherent user representation. For long-document QA, we choose NarrativeQA ( Kočiskỳ et al., 2018 ) and TriviaQA ( Joshi et al., 2017 ) to test the method’s ability to compress long documents in their entirety into a usable representation for downstream QA. Finally, for knowledge-intensive QA, we consider FactKG ( Kim et al., 2023 ) and PubMedQA ( Jin et al., 2019 ) to test factual grounding from structured or semi-structured evidence of varying quantity and format. Full-history in-context learning (ICL) gives the decoder the complete interaction history without memory, and an untrained memory module isolates the contribution of RL. Unlike in the supervised setting, the memory supplements the text rather than replacing it. The re- maining failures concentrate in the longest games, whose quests approach or exceed the 50-turn limit and require backtracking across many rooms. 7 Discussion and Conclusion Memorilla separates persistent knowledge storage from the context required for each query. New documents can be added without updating the LLM, while the memory module learns to extract relevant information through a fixed number of latent tokens. This design supports assistants that draw on growing histories without proportionally increasing the decoder’s context. Our analyses suggest that the learned representations capture relationships across documents and recover personal context beyond lexical similarity. In TextWorld, reinforcement learning improves a frozen agent’s decisions even when the interaction history is already available as text. Together, these findings support learned memory as a means of improving how LLMs use accumulated information, with the memory interface optimized through either answer supervision or environment reward. Conclusion. In this work, we introduced Memorilla , a latent semantic memory system that gives frozen LLMs access to query-dependent information from large corpora as ‘soft’ memory tokens. Memorilla demonstrates that a frozen LLM can use accumulated knowledge through a learned, query-dependent interface, rather than relying only on retrieved text or an expanding prompt. Memorilla leads retrieval, compression and agent memory baselines on average at 20 20 to 4,212 × 4{,}212\times fewer document tokens across personalization, long-document QA, and knowledge-intensive tasks. Additionally, Memorilla also enables continual learning in agentic RL, where training only the memory module teaches an agent a new environment without overwriting prior knowledge. Limitations and Future Work. Memorilla can lose fine-grained factual details, likely because the document encoder was never trained for memory compression. Future work exploring combinations of latent memory and text retrieval could combine the global structure that memory captures with the exact entities that retrieval recovers. Furthermore, encoders trained specifically for compression could close the remaining gap on fine-grained details. Our experiments pair a Qwen encoder with a Qwen decoder, and testing how well the memory mechanism transfers across model families is also an interesting future area of research. Our evaluation covers personalization, long-document QA and knowledge-intensive QA, so Memorilla may not carry over directly to domains such as coding. Nonetheless, for personalization tasks, because the persistent memory store holds only embeddings, a multimodal encoder could extend the same interface to images, audio and video, giving assistants a memory of what a user has seen and heard. Since each user’s memory is a separate store, it can be kept on device or deleted on request, which eases privacy concerns. Finally, because LLM decoding dominates latency, the efficiency gains show up mainly for large collections. Hence one can explore extensions of Memorilla where memory modules could share a single persistent store and inject memory tokens across LLMs of varying sizes. Ethics statement Memorilla stores and recalls information from user conversations, which raises privacy concerns when deployed on real user data. Textual memory keeps source records readable and retrieves relevant records at inference. RAG ( Lewis et al., 2020 ) and REALM ( Guu et al., 2020 ) retrieve passages from a document index. Systems built for longer histories retain the same basic interface while organizing the records differently. MemGPT ( Packer et al., 2023 ) moves information between context tiers, MemoryBank ( Zhong et al., 2024 ) stores conversations and summaries, and Mem0 ( Chhikara et al., 2025 ) and A-MEM ( Xu et al., 2025 ) maintain structured records across sessions. These systems preserve provenance and exact details, but the LLM can reason only over material that retrieval places in its context. Evidence outside the selected set remains unavailable, and widening that set yields limited returns. In-Context RALM ( Ram et al., 2023 ) finds that most question-answering gains come from the first one or two retrieved documents. MemoRAG ( Qian et al., 2025 ) uses compressed global memory to generate retrieval clues, but its final generator still reads selected passages. Textual memory is therefore effective when evidence can be localized, while signals distributed across a collection remain constrained by document selection. Memorilla instead computes a query-conditioned latent state from the full collection, complementing retrieval when exact evidence is needed. Latent compression. Latent compression replaces replayed text with compact continuous state. ICAE ( Ge et al., 2024 ) and IC-Former ( Wang et al., 2024a ) encode a long input into reusable vectors consumed by frozen target LLMs, while AutoCompressors ( Chevalier et al., 2023 ) fine-tune an LLM to produce and consume recursive summary vectors. These representations can be cached because they are computed without a query, but they cannot change what they emphasize for different queries. Gist tokens ( Mu et al., 2023 ) and 500xCompressor ( Li et al., 2025 ) make the same tradeoff using layer-specific key–value states rather than standard input embeddings. xRAG ( Cheng et al., 2024 ) makes the representation query relevant by first selecting a document through retrieval and mapping its embedding to one LLM token, which retains document selection as the access mechanism. A second line improves the alignment between compression and generation. PISCO ( Louis et al., 2025 ) and COCOM ( Rau et al., 2024 ) jointly adapt their compressors and generators, while CLaRa ( He et al., 2025 ) learns reusable document vectors before training a query reasoner with the generator. These methods gain a learned latent interface but require an adapted generator. Other methods obtain reuse within a narrower memory domain. TokMem ( Wu et al., 2026 ) optimizes a separate token for each procedure, while ComMer ( Zeldes et al., 2025 ) , USER-LLM ( Ning et al., 2025 ) , and Embedding-to-Prefix ( Huber et al., 2025 ) construct latent state for user histories. Memorilla instead accepts unseen document collections without further optimization and converts an LLM-independent store into new query-conditioned input embeddings for a frozen LLM. Model memory. Model memory stores information in architecture-specific state. MemoryLLM ( Wang et al., 2024b ) maintains a self-updating latent pool, M+ ( Wang et al., 2025 ) retrieves from long-term storage using the current hidden state, and LongMem ( Wang et al., 2023 ) retrieves cached key–value states through a trained side network. Their shared internal representation supports query-conditioned recall, but also couples the memory and its reader to a particular model. Other methods preserve state during model execution rather than across an independent document collection. LM2 ( Kang et al., 2025 ) updates a gated memory matrix during autoregressive inference. Titans ( Behrouz et al., 2025 ) combines fixed task-level parameters with a contextual neural memory updated while processing a sequence. MELODI ( Chen et al., 2025 ) and Activation Beacon ( Zhang et al., 2025 ) compress state across context windows and transformer layers to extend long-sequence processing. Cartridges ( Eyuboglu et al., 2026 ) makes model-specific key–value caches reusable and composable, but requires offline optimization for each new corpus. These approaches demonstrate the value of persistent latent state, while their architecture-specific interfaces limit reuse across models and collections. Memorilla instead keeps memory external and supplies it to a frozen LLM as input embeddings. Baselines that insert text share one prompt template per benchmark and differ only in the context placed before the question. Closed-book. The decoder receives only the query, which shows how much of each benchmark it answers from parametric knowledge. RAG and Full Context. RAG- k k ranks the chunks of a collection by the cosine similarity between their embeddings and the query embedding, and places the top k k chunks in the prompt as text, most similar first and separated by blank lines. Full Context places every chunk in its stored order. Inputs longer than the enforced 32,768-token limit use YaRN with a scaling factor of 4, which extends the window to 131,072 tokens and applies to part of PMv2, TriviaQA and NarrativeQA and to all of PV4 (Table 10 ). For the 10.8% of evaluated NarrativeQA questions whose books exceed this window, the earliest chunks are dropped. LLMLingua-2. LLMLingua-2 ( Pan et al., 2024 ) is a hard prompt compression method that deletes tokens from the context rather than replacing it with latent vectors. We use the released XLM-RoBERTa-large token classifier. Because the classifier never sees the question, each collection is compressed once and reused for every query, similar in principle to Memorilla . We concatenate the documents of the Full Context input with blank-line separators and compress them as one block, retaining newlines and question marks. The question, answer-format instruction, system prompt and chat template are copied verbatim, so the prompt differs from Full Context only in the compressed documents. We disable the option to discard whole documents, since document selection is retrieval and is already covered by RAG- k k . We set absolute budgets of 32, 64, 128 and 350 tokens rather than a compression rate, which the method treats only as a soft target, and report the best budget for each metric. xRAG. xRAG ( Cheng et al., 2024 ) maps the embedding of the top retrieved chunk to a single soft token in the input space of the decoder through a trained bridge. We reimplement the bridge in our codebase as a layer normalization followed by a two-layer MLP with a GELU activation, which maps the 2,560-dimensional chunk embedding to the 4,096-dimensional decoder input space with 27,276,288 trainable parameters. The chunk is retrieved by cosine similarity with the shared encoder. Only the bridge is trained, from scratch on each benchmark’s training split with the same answer-token loss as Memorilla . We train for 5 epochs with AdamW at a learning rate of 10 − 4 10^{-4} , a weight decay of 0.01, a warmup ratio of 0.1, an effective batch size of 16, a maximum sequence length of 8,192 tokens and seed 23. ComMer. ComMer ( Zeldes et al., 2025 ) compresses user-history documents into latent representations with a learned compressor, merges them and passes them to a frozen LLM for personalized generation. We compare against its reported LaMP-4 and LaMP-7 results in Table 12 . Mem0 and MemoRAG. Mem0 ( Chhikara et al., 2025 ) extracts and consolidates memories at write time, while MemoRAG ( Qian et al., 2025 ) forms clue queries from a global memory to guide retrieval. We run the official implementations with the settings in Table 6 . Both use a frozen Qwen3-4B-Instruct-2507 to write their memory, as the fact extractor of Mem0 and as the memory model of MemoRAG. This matches the 4B scale of the Qwen3-Embedding-4B encoder with which Memorilla reads the same collections, so every method processes the documents with a 4B model and answers with the same frozen Qwen3-8B decoder. MemoRAG runs in its supported long-context memory mode, in which the memory model reads the uncompressed collection rather than a compressed version of it. Its retrieval uses each benchmark’s own chunks and the shared encoder, so the clue mechanism is its only difference from RAG- k k . These benchmarks require combining information spread across a user’s past chats or writing into a picture of the user that no single document provides. • PersonaMem-v2 (PMv2, n = 5,000 n{=}5{,}000 ) ( Jiang et al., 2025 ) . Each user has a long history of conversations with an assistant about everyday tasks, and each question asks for a response that fits the user’s preferences. Most preferences are never stated outright but surface indirectly, for instance in an email the user asks to have polished, so the model must infer them from scattered cues across many sessions rather than look them up. • PersonalizationV4 (PV4, n = 4,237 n{=}4{,}237 ). Our synthetic benchmark gives each user 200 two-turn conversations that reflect a persona without stating its traits (Appendix D.1 ). Each question places the user in a new scenario and requires combining at least two persona facts, which may appear in different conversations. A hard subset ( n = 629 n{=}629 ) keeps the questions that the untrained Qwen3-4B-Instruct-2507 decoder answers incorrectly without documents or with the top retrieved conversation. • LaMP-4 ( n = 1,925 n{=}1{,}925 ), LaMP-7 ( n = 1,500 n{=}1{,}500 ) ( Salemi et al., 2023 ) . LaMP-4 asks the model to write a headline for a new news article in the style of the author’s earlier articles and headlines, and LaMP-7 asks it to rewrite a tweet in the style of the user’s earlier tweets. The challenge is stylistic rather than factual, since style emerges from the whole writing history rather than a single item. Long-Document QA. This axis tests whether memory can compress entire long documents into a usable representation for downstream QA. • NarrativeQA (NQA, n = 10,557 n{=}10{,}557 ) ( Kočiskỳ et al., 2018 ) . Questions concern full books and movie scripts and were written from plot summaries without access to the stories, so they target events, motives and relations described across the narrative rather than sentences that can be matched locally. Answers are free-form text, which rewards understanding the plot over copying a passage. • TriviaQA ( n = 500 n{=}500 from the 17,944 17{,}944 -question validation split) ( Joshi et al., 2017 ) . Questions written by trivia enthusiasts are paired with Wikipedia and web documents collected afterwards. Since the questions were not written against these documents, their wording and structure often differ from the passages that answer them, and an answer may require combining facts across sentences. Knowledge-Intensive QA. These benchmarks test factual grounding from structured or semi-structured evidence of varying quantity and format. • FactKG ( n = 9,041 n{=}9{,}041 ) ( Kim et al., 2023 ) . Each claim must be labeled as supported or refuted by facts from the DBpedia knowledge graph, through one-hop lookups, conjunctions of several facts, existence checks, multi-hop chains or negations. A multi-hop claim such as “AIDAstella was built by a company in Papenburg” requires chaining two facts, neither of which verifies the claim on its own, and a negated claim requires confirming that a relation is absent. • PubMedQA ( n = 100 n{=}100 ) ( Jin et al., 2019 ) . Each question is a biomedical research question based on an article title, answered yes, no or maybe from the article’s abstract with its conclusion removed. The model must infer the conclusion from the reported methods and results, often by interpreting quantitative findings. Each user has one LLM-generated persona profile seeded from the Faithful Persona-based Conversational Dataset ( Jandaghi et al., 2023 ) . The resulting profiles are 10k to 22k characters long (median 15.5k) and describe demographics, personality, work, hobbies, communication style and how preferences change over time. All of the user’s data is derived from this profile through the five steps below, and Table 8 traces one held-out user through each of them. 1. Question categories. GPT-5.1 reads the persona and extracts 10 persona-specific categories that questions can test. 2. Chat topics. GPT-5.1 writes exactly 200 one-sentence scenarios per user in which the user asks the assistant for help, covering every part of the persona. 3. Dialogues. GPT-5-mini expands each topic into one two-turn dialogue with one user turn and one assistant turn. The user embodies the persona implicitly without stating its traits. Exactly 200 dialogues are generated per user and all form the collection that the memory module reads; there is no truncation step. 4. Questions. For each category, GPT-5.1 is asked to write 15 questions from the persona alone. It writes 14 in 1,234 of the 1,490 released category files and 13 to 15 in all but one, which has 5. Each question has a reference answer and four distractors. The instructions in Table 9 require every question to combine at least two persona facts in a new scenario and every distractor to be a plausible preference that matches the reference answer in length, structure and specificity. This gives 133 to 145 questions per user (mean 141.3). 5. Randomization. The reference answer’s position among its distractors is shuffled with a fixed seed of 42. Questions are posed without their candidate answers, and the model answers in free text. The reference answer and distractors are used only by the short-answer scorer, which counts a response as correct when its nearest candidate under the Qwen3-Embedding-4B encoder is the reference answer. We release 149 users: 119 training users and 30 held-out evaluation users, none of whom appear in training. One training user whose generated persona was a refusal is withheld from the release. Every question for these held-out users is evaluated: 139 to 143 per user and 4,237 in total, all in the test split. The PersonalizationV4 dataset is linked on our project website . The hard subset ( n = 629 n{=}629 ) is defined from the untrained Qwen3-4B-Instruct-2507 decoder’s multiple-choice answers and contains questions it answers incorrectly without documents, with the top-1 retrieved document, or in both settings; 299 of the 629 questions are answered incorrectly in both settings. Embed each question in a specific, realistic scenario that requires applying persona knowledge to a novel situation rather than simple recall. The question stem must not hint at characteristics of the answer. Distractors Every choice (A-E) must be a reasonable, professional, or logical preference for a human. Never use obviously wrong, absurd, or incompetent distractors. Ensure distractors include industry-standard best practices that most people in the persona’s role would choose, but which this specific persona rejects. Use information that is true about the persona but applies it to the wrong situation or frequency. All five choices must have the same word count within a tolerance of two words. E.4 Frozen vs. LoRA Training To separate the memory interface from generic adaptation, we train rank-130 LoRA adapters ( Hu et al., 2021 ) on the Qwen3-4B-Instruct-2507 decoder with 268.4M parameters, comparable to the 194.1M parameters of the memory module paired with the 8B decoder. The adapters use the same training rows as Memorilla ’s per-task fine-tuning and receive no documents in context. Figure 11 shows that Memorilla leads on every primary metric, although the PubMedQA and LaMP-7 gaps are within noise. Together with the noise test above, where Memorilla loses 5.93 on FactKG without real documents, this indicates that its gains rely on the stored evidence rather than on adaptation alone. Freezing both backbones keeps the store portable and the decoder untouched, at the cost of an encoder never optimized for compression. Figure 11: Memory versus comparable-budget adaptation. Appendix F Computational Analysis of Memorilla Consider a collection of N N documents serving Q Q queries. Memorilla pays the encoder once on the write path, producing N N embeddings that persist and are reused by every later query. Dense retrieval builds the same index, so this cost is shared rather than added. The two methods differ on the read path. RAG places the selected text in the decoder, so its prefill grows with retrieval depth, while Memorilla runs one cross-attention read over the stored embeddings and always hands the decoder K = 16 K{=}16 tokens. Table 14 reports measurements on one H100-80GB at batch size 1 with a Qwen3-8B decoder. Growing the collection by 512 × \times decreases the memory-module forward time by 0.06 ms and Memorilla end-to-end latency by 1.9 ms, while full-context decoding grows by 19,184 ms and exceeds the enforced 32,768-token limit, requiring YaRN. Transfer stays under 0.04% of query latency because a 200 document collection is 1 MB, and the store is 7,266 × \times smaller than the corresponding KV cache on PV4 (50,455 document tokens at 144 KiB per token for Qwen3-8B in bf16, 6.9 GiB, against 200 embeddings of 2,560 bf16 values). Absolute latency is dominated by decoding rather than by memory, so the benefit is not a faster single query but a serving cost that stays flat as collections grow and amortizes across the Q Q queries that read them. Observations are room descriptions and action outcomes, actions are short text commands, and games span up to 65 rooms. From the second turn on, Memorilla embeds each completed turn as one document, holding its observation truncated to 200 characters and its action (74 tokens on average), reads these documents with the current observation as the query, and places the resulting K = 8 K{=}8 memory vectors before the prompt. The 20 extreme, huge, long and mega test games instead embed one document per five completed turns with full observations, keep the last four documents, and use the mean document embedding as the query.
