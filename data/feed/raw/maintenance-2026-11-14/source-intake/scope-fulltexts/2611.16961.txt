This division has shaped the design philosophy of reasoning in large language models (LLMs) ( Wang, 2025 ) , but the work it has influenced builds either a good System Two or a good System One, and a model that is both remains underexplored. Most current System Two models (like reasoning models) raise their capability through autoregressive test-time scaling, including OpenAI’s GPT-6, Anthropic’s Claude Fable 5 and the open-weight Qwen3.8, which write a chain of thought before the answer, at a cost in tokens and latency on every question. A recent class of System One models, Jev ( TypeSafe AI, 2026 ) and AnyJev ( Nokia Applied Research, 2026 ) among them, takes the strict case, emitting no tokens at inference and producing the answer in a single non-autoregressive pass, each adapting a reasoning-model backbone rather than training a different kind of model. Routing occurs once: the model either returns the cached fast answer or decodes autoregressively with the same backbone. The dashed feedback arrow returns each generated token to the shared context, reusing the KV cache; only the completed answer enters the response. One line of work seeks efficiency inside reasoning models themselves, shortening the chain of thought without losing accuracy ( Snell et al., 2024 ; Muennighoff et al., 2025 ; Zhang et al., 2025b ; Aggarwal and Welleck, 2025 ; Zhang et al., 2025a ) . These methods make the chain cheaper rather than optional: they ask how long the reasoning should run, not whether a given question needs it at all. Another relieves the cost by routing between models, or down a cascade until an answer is accepted ( Chen et al., 2023 ; Ong et al., 2024 ) . Every branch is a model generating an answer, so the choice on offer is between an expensive answer and a cheaper one. Can one model keep both advantages and switch between them when it should, generating nothing at all where that suffices and reasoning where it does not? In this work, we introduce zero-or- T T thinking , an adaptive-inference paradigm that unifies token-free fast decision with full autoregressive reasoning inside a single language model: rather than deciding how much to think, the model decides whether autoregressive thinking is needed at all , and a question costs either no generated token or the T T a reasoning pass takes. Specifically, we define the value of thinking on a question as the utility the slow-thinking mode is expected to add over the fast-thinking one, and a question is escalated only when that value exceeds a price λ \lambda set on the request. We instantiate zero-or- T T thinking in a hybrid decision model (HDM): a fast-and-slow model, its fast-thinking mode producing a decision directly from the implicit thinking with no token generated, its slow-thinking mode the backbone’s own reasoning inherited unchanged, and a learned self-routing block choosing between them before any token is generated. HDM estimates the conditional gain of thinking
from hidden representations the fast mode has already computed, and completes
cost-aware routing before inference begins. We also address how the block is trained. On single-turn questions a gold answer is available, so running both modes constructs the better choice directly and supervision suffices; in episodic tasks the return is decided by many successive actions and no per-decision label exists, so we introduce a PPO-based reinforcement-learning recipe for training HDM, Calibrated Decision Policy Optimisation (CDPO). CDPO maximises the return an episode earns discounted by the escalations it spent, with that one episode-level signal shared by every decision inside it. First , we propose zero-or- T T thinking , a paradigm in which a question costs either no generated token or the T T a reasoning pass takes and one frozen backbone serves both modes, switched by a self-routing block of a few hundred kilobytes that reads representations the fast pass has already computed, so the choice costs no forward pass and no token. Last , we introduce CDPO , which trains the block where no per-decision label exists, from the return an episode earns discounted by the escalations it spent. 2 Method A hybrid decision model is a model f f with two decision modes, f fast f_{\mathrm{fast}} and f slow f_{\mathrm{slow}} , and a policy π \pi that picks one of them for each question q q , which is then answered by f π ⁡ ( q ) f_{\pi(q)} , π ⁡ ( q ) ∈ { fast , slow } , \pi(q)\in\{\mathrm{fast},\mathrm{slow}\}, (1) and is self-routing when π \pi reads only what f f ’s implicit thinking has already produced. In this paper we assume f f is a transformer-based large language model. The slow mode f slow f_{\mathrm{slow}} (or explicit thinking ) generates tokens as normal reasoning LLMs do. The fast mode f fast f_{\mathrm{fast}} (or implicit thinking ) generates no tokens, producing the decision by multi-class classification or numerical prediction, depending on the task type ( Devlin et al., 2019 ) . Switching between the two modes lets a model reason where reasoning helps and respond rapidly where there is no need for thinking, while preserving the advantage of the world knowledge stored in the LLM. Predicting the value of thinking is the key to knowing when to switch. Confidence is no substitute for it: confidence reports how sure the fast answer is, and that is a different question from whether the slow mode would answer differently. The two come apart in both directions: thinking sometimes spoils an answer the fast mode had right, and it adds nothing where both modes would answer correctly. A router therefore needs the two outcomes jointly. Stating the routing problem as an objective. We define the utility a mode earns on question i i as its correctness, u i ​ ( m ) = a i m = 𝟏 ​ [ mode m answers i correctly ] ∈ { 0 , 1 } , u_{i}(m)=a_{i}^{m}=\mathbf{1}\big[\text{mode $m$ answers $i$ correctly}\big]\in\{0,1\}, (2) for m ∈ { fast , slow } m\in\{\mathrm{fast},\mathrm{slow}\} , so running both modes observes one of four outcomes: both right, the fast one only, the slow one only, or neither. Typed input schema. We define a typed general request to carry a prompt s s (text or multimodal media), optional explicit questions q 1 , … , q N q_{1},\dots,q_{N} , and an optional candidate answer set for each; only the prompt is required, so the schema names structure an ordinary request already carries and a bare prompt is already a free-form request. The schema makes the two modes substitutable, since a caller receives an answer of the same type whichever produced it, and it lets HDM serve a choice among candidates, a binary judgement, a graded score and free-form generation with one backbone and one block. 2.1 The hybrid decision model HDM is a frozen f f with one learned block added (Figure 2 ). The policy π \pi has two parts: the self-routing block , a small network on the hidden state 𝒉 i \bm{h}_{i} of one of the backbone’s transformer layers, and the price of thinking λ \lambda , which the user sets per request. One trained block covers the whole cost–accuracy curve, so varying λ \lambda moves the operating point along that curve without retraining and without a second block. 2.1.1 Architecture Given a typed input request as described above, three components run in order (Figure 2 ). This section sets out why a decoder-only backbone can serve as an encoder. Generation is not all a decoder-only forward pass does. Before any token is
produced, the backbone encodes the request: tokens enter a latent space and each
layer abstracts what the layer below it holds. This is thinking the model does without
writing it down , studied as latent or implicit reasoning ( Yang et al., 2024 ; Wang et al., 2024a ; Hao et al., 2024 ) , and the state it
leaves is information the model has already worked over rather than the input in
another form. Our own experiments carry evidence for this. In
Table 2 the fast mode answers most items without generating. In
Table 5 the same state tells the routing block whether thinking
would change that answer, and tells it more than the fast answer’s own output
distribution does. Thinking buys steps of deliberation , each generated token re-entering
the context so that the next pass starts
further along ( Li et al., 2024 ) . Hence the value of
thinking, our estimate of where more of that deliberation would change the
answer. 2.2 Calibrated decision policy optimisation for episodic tasks In a multi-turn agentic task a single question’s correctness usually does not decide whether the task succeeds, and often no per-question label exists to train against. than questions drawn at random. 4 Related work 4.1 Explicit reasoning and its cost Reasoning models gain accuracy from a long chain of thought, and test-time scaling treats its length as a compute knob ( Snell et al., 2024 ; Muennighoff et al., 2025 ) . Work on making that chain cheaper bounds its length ( Aggarwal and Welleck, 2025 ) , condenses traces ( Zhang et al., 2025b ) or allocates depth per token ( Schuster et al., 2022 ) ; all of it shortens thinking, and none lets the model answer without decoding. Song et al. (2026) do answer without decoding, scaling a typed decision model by rerunning its own layers instead of generating, with a stopper that picks a depth per question from readouts the model has already produced. The knob is still how much. Their stopper asks whether the current answer has stopped changing with depth, where ours asks whether reasoning would change it from wrong to right: rather than deciding how much to think, our model decides whether autoregressive thinking is needed at all . 4.2 Fast-thinking models and their readout A model is fast-thinking when it writes no reasoning down, reading the answer from a single pass. A single pass cannot add steps of deliberation , whereas each generated token adds one ( Li et al., 2024 ) , and our two modes sit at the ends of that trade-off. Reading an answer this way is the multi-class protocol of encoder classifiers and zero-shot multiple choice ( Devlin et al., 2019 ; Hendrycks et al., 2021 ; Wang et al., 2024b ) , which Jev ( TypeSafe AI, 2026 ) productised as a typed decision API with zero output tokens, since reproduced in the open ( Zhang, 2026 ; zhihz, 2026 ; Mapika, 2026 ; Nokia Applied Research, 2026 ) . Token-free fast decision is therefore not itself new; what is new here is holding it and autoregressive reasoning in one frozen backbone and switching between them from state the model has already computed. Confidence estimation reads the same activations ( Hendrycks and Gimpel, 2017 ; Geifman and El-Yaniv, 2017 ; Kadavath et al., 2022 ; Azaria and Mitchell, 2023 ; Alain and Bengio, 2017 ) ; we read them for a different target — not whether the answer is right, but whether thinking would make it right. 4.3 Hybrid thinking, mode switching and routing A third line lets one model choose per question: one family trains the backbone to emit a mode token ( Fang et al., 2025 ; Zhang et al., 2025a ; Lou et al., 2025 ; Jiang et al., 2025 ) , another keeps it fixed and adds an external switch on predicted success rates ( Liang et al., 2025 ) , a pre-inference probe ( He et al., 2025 ) or perplexity ( Lu et al., 2025 ) , and a third routes between models rather than modes ( Chen et al., 2023 ; Ong et al., 2024 ; Ning et al., 2026 ) , among them the nearest-neighbour KNN-Router of Pan et al. (2025) . The closest is Nokia Applied Research (2026) , escalating a typed decision on a fixed top-two margin rather than a learned predictor, and from ThinkSwitcher we inherit the frozen backbone, the self-produced labels and the thresholded margin. What separates HDM is that each of these computes its routing signal apart from the answer, and each of the modes they switch between still decodes its answer autoregressively , so what they choose is how much reasoning to write rather than whether to decode at all. All are trained for likelihood where decision-focused learning would train for the decision ( Elmachtoub and Grigas, 2022 ; Wilder et al., 2019 ) , and the quantity we predict already has three names: a value of computation in metareasoning ( Horvitz, 1987 ; Russell and Wefald, 1991 ; Gershman et al., 2015 ) , a treatment effect in uplift modelling ( Gutierrez and Gérardy, 2017 ; Künzel et al., 2019 ) , a deferral decision in learning to defer ( Mozannar and Sontag, 2020 ) . Estimating it for two modes of one network, from a state that network has already produced, is what is new. 5 Conclusion HDM estimates the conditional gain of thinking
from hidden representations the fast mode has already computed, and completes
cost-aware routing before inference begins. The signal it reads is whether thinking would help rather
than whether the fast answer is right, and the two differ wherever thinking
cannot rescue a question or would spoil one it had right. A few hundred
kilobytes of added parameters and no annotation beyond a labelled question set
are enough, and the price is set per request rather than at training time. What we
claim against published systems is competitiveness at a lower token cost and not
dominance: on BANKING77 two of the compared configurations answer more of the
items than we do, and the latencies we quote from other work were measured on
other backends. Where

Appendix D How the fast mode reads its answer The fast mode needs a score per candidate, and we implement two readouts that
produce one. The coded readout maps each candidate to a single-token letter, writes the
letters into the prompt beside the candidates, and reads the model’s
distribution over those letter tokens at one position. Every number elsewhere in
this paper was produced this way. Its weakness is structural: a code is a token,
a token carries a prior, and the prior attaches to whichever candidate occupies
that slot. On MMLU-Pro the positions this readout favours are measurably not where the
answers are, and the favoured position is not the same one on the two backbones. The content readout writes the candidates with no labels at all and scores
each one by its own text, teacher-forced after the same prefix. Nothing is
sampled; the cost is one prefill plus k k short continuations that share it. With
no label there is nothing for a token prior to attach to, though the candidates
are still listed in an order, so a positional effect can survive and is
measured rather than assumed away. A content score needs a normalisation, and three are natural. Writing ℓ o \ell_{o} for the summed log-probability of option o o , | o | |o| for its token count, and ℓ o ∅ \ell_{o}^{\varnothing} for its score after a question with nothing in it to
answer: sum ranks on ℓ o \ell_{o} , mean on ℓ o / | o | \ell_{o}/|o| , and pmi on ℓ o − ℓ o ∅ \ell_{o}-\ell_{o}^{\varnothing} , the last being the standard
correction for surface-form competition ( Holtzman et al., 2021 ) . Only pmi pays for the content-free pass. CDPO optimises a surrogate, not
the episode-level objective itself, and three gaps separate them. The per-decision
importance ratio replaces the trajectory ratio, which is what keeps the weights usable
over tens of steps but biases the estimator in a direction the clip controls rather than
removes. Credit is not assigned: every decision in an episode is scored by that episode’s
return, so a decision is rewarded for what the decisions after it did, and with tens of
decisions an episode this is the weakest assumption in the recipe. And the prices are
redrawn each epoch while the trajectories are not, so the policy is re-scored at prices
the behaviour policy never acted under. We report the effective sample size ( ∑ t ρ t ) 2 / ∑ t ρ t 2 (\sum_{t}\rho_{t})^{2}/\sum_{t}\rho_{t}^{2} beside every reward, since weights worth a fraction of
their count have shown the block little whatever the surrogate says. Algorithm 2 gives CDPO in full. The recipe runs in four steps. Episodes are collected under the policy that is acting. A price is drawn per decision, and an episode’s return is its terminal reward discounted by the escalations it made at that price. The advantage is that return against the mean return over episodes at the same prices, shared by every decision of the episode. The block is then updated by the clipped surrogate of PPO on the per-decision importance ratio.
