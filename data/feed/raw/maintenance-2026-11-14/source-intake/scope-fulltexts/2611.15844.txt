 valeo.ai Yuki M. Asano Abstract Recent work suggests that pretrained image generators encode real-world understanding beyond image synthesis. Vision Banana exploits this by framing vision tasks as conditional image editing. However, its data, weights, code, and implementation details are not public. We present Open Vision Banana (OVB), a fully open and reproducible recipe for converting pretrained generators into unified multi-task perception systems.
Our analyses identify the design choices that matter most for generalization, including color encoding, prompt design, parameter adaptation, and task balancing. These choices interact, so individually helpful choices can hurt when combined with others. Starting from 4B and 9B parameter open-weight base models and using 2.1M–3.8M training pairs from public datasets, OVB surpasses Vision Banana’s reported Cityscapes zero-shot performance (73.9 vs. 69.9 mIoU) and rivals state-of-the-art affine-invariant depth estimators. Its non-zero-shot variants come within five points of Vision Banana on referring and reasoning segmentation but remain further behind on instance segmentation. All models largely retain the base model’s image-editing abilities.
With legend ensembling, we introduce a test-time scaling method for generator-based perception. It segments an image under several class–color legends and fuses the results by majority vote, correcting unstable color–class bindings and improving mIoU by up to 8.7 8.7 points on Cityscapes and 15.0 15.0 points on COCO-Object without retraining.
We release the dataset construction and processing pipeline, the training and evaluation code , as well as the final, intermediate, and ablation checkpoints . F.1 ). 1 Introduction Image generation models have become increasingly capable of producing realistic and coherent visual content [ 44 , 102 ] . A growing line of work argues that this capability reflects general visual understanding that can be utilized for perception tasks [ 40 , 39 , 124 , 35 ] . Vision Banana [ 23 ] demonstrates that a sufficiently capable image generator can be adapted into a generalist visual perception model by rendering predictions as RGB images.
It rivals domain specialists on segmentation and geometry while largely keeping the generator’s editing abilities. However, its base model, data and code are proprietary, so it is unclear which components account for these results. Does the paradigm transfer to publicly available image generators, and how do design choices not elaborated in the Vision Banana report affect the resulting model? We introduce Open Vision Banana (OVB) , a fully reproducible recipe and set of models for generative visual perception.
To derive this recipe, we systematically study the design choices that turn an image generator into a perception model. As shown in Fig. 1 , the analysis spans the type and composition of training data, target representations and prompt design, the choice of parameters to adapt, and inference-time readout (decoding generated RGB raw output to task specific final format). Our experiments show that these choices have large effects and can depend on one another. A model may locate the right region yet score poorly because it paints the wrong color or breaks an output convention. In particular, low-level decisions such as the palette and prompt wording strongly affect accuracy. Supervision for one task can help or hurt others, and choices that help individually may no longer help when combined (Appendix E.2.4 ). Finally, we introduce legend ensembling , which segments an image under several randomly drawn color legends and fuses the passes by majority vote. Without retraining, it improves the zero-shot 9B model by up to 8.7 mIoU on Cityscapes and 15.0 mIoU on COCO-Object, with gains mostly from fixing colors bound to wrong classes. Open Vision Banana makes four main contributions: • A fully open recipe for adapting public image generators to four segmentation tasks, depth estimation, and surface normal estimation. The models are trained exclusively on public data, and we release the complete data pipeline, training code, and model checkpoints. • Controlled experiments on performance-critical design choices, with an analysis of failure modes. • Legend ensembling , a training-free test-time scaling method for generator-based segmentation. • Competitive open models that surpass Vision Banana on Cityscapes, come close to it on referring and reasoning segmentation, perform well on depth and surface-normals, and largely retain their editing abilities. 2 Open Vision Banana Recipe OVB turns a pretrained image generator into a perception model without task-specific heads: given an input image x x and an instruction p p , it generates an RGB image y y that a deterministic, task-specific readout converts into a prediction. 2.1 Base Generators We release fine-tuned FLUX.2-Klein models at 4B and 9B scale [ 44 ] , open-weight generators that condition on an input image. All transformer parameters are trained, from the input and context embedders to the output layers. The VAE and text encoder stay frozen. 2.2 RGB Task Modeling Each task has a deterministic encoder that renders an annotation as an RGB target and a decoder that reads a generated image back into a prediction. Both use per-sample metadata such as the color legend, depth scaling and resizing. 2.2.1 Color Mapping for Segmentation Tasks Prompts specify colors as RGB triplets, hexadecimal codes (64 most-separated colors of a 200-color palette, Sec. 4.1 ), or as one of 37 common color names. Black is reserved for background. Prompt templates and color notation vary across samples. Semantic segmentation. The prompt lists the requested classes with their colors. Colors are assigned at random for each sample, using the same procedure during training and inference.
Given the classes present in an image, training examples request a random subset in 70% of cases, all present classes in 15%, and a subset augmented with absent negative classes in the remaining 15% ( Fig. 9 ). Negative classes teach the model not to hallucinate absent masks. The target paints each prompted class in its assigned color and leaves all other pixels black. At inference, each generated pixel is assigned to the nearest prompted color or to background. Instance segmentation. Each prompt names one category and lists 32 colors. We keep the 32 largest instances of the category, sort them by their leftmost pixel and paint the i i -th instance in the i i -th color (Appendix E.1.2 ). The fixed order makes training targets unique for each image and prompt. Evaluation matches predicted and ground-truth instances by overlap without penalizing alternative color assignments. The readout follows Vision Banana, adding color snapping, gap filling, and GrabCut refinement (Appendix B.2 ). Referring segmentation. Each prompt pairs the referring expression with a color sampled independently from the named palette. The model renders the referred region in that color, which is converted to a binary mask during readout. 2.2.2 Color Mapping for Geometry Tasks Depth. Following prior work [ 6 , 38 ] , depth is encoded as affine-invariant inverse depth: valid values are normalized per image to the RGB range and replicated across channels, so nearer points are brighter (figures use a spectral colormap for readability). At inference, the prediction is mapped back to inverse depth and evaluated after per-image affine alignment. Surface normals. Normals are converted to a common camera-space convention and each vector component is mapped linearly to one normalized RGB channel.
At inference, the RGB prediction is mapped back to camera-space vectors and normalized to unit length. For both depth and surface-normal tasks, the prompts explicitly state the expected output representation.
Further geometric encoding details are provided in Sec. B.1 . 2.3 Public Data Mixture Vision Banana fine-tunes a proprietary base model on proprietary vision data mixed with the base model’s original training data. We only use public datasets.
We mix Perception data for the above tasks with replay data from public text-to-image, image-editing, and identity-reconstruction datasets.
The resulting pools contain 2.1M training pairs for the zero-shot models and 3.8M for the non-zero-shot models (Appendix C.2 ).
Appendix Tables 20 and 21 give the sampling weight for each task and the datasets and their shares within each task. 2.4 Training Because all targets are RGB images, we train with the base generator’s rectified-flow objective [ 55 ] . Each epoch draws 1M samples with replacement, split across tasks according to Appendix Table 20 . Training thus spans about 19 epochs. Final models use weight-space averaging of a few late transformer checkpoints (Appendix C.1 ). The non-zero-shot runs took about 73 h on 16 NVIDIA GH200 GPUs (4B) and 79 h on 32 (9B). 2.5 Evaluation Protocol and Data The evaluation protocol adopts standard metrics for each task and is specified in Appendix C.3 . Each pass is read out with its own legend, and the resulting class maps are fused
by per-pixel majority vote (see Fig. 4 ).
A black pixel is a vote for the background class on COCO-Object and no vote on Cityscapes, which has no background class. For instance segmentation, each pass permutes the 32 instance colors. Since these colors carry no class identity, voting operates on the refined binary masks of each pass (Appendix B.2 ). Masks from different passes that overlap with IoU ≥ 0.5 \mathrm{IoU}\geq 0.5 are grouped into one instance. An instance is kept if it appears in at least half of the passes, and its final
mask contains the pixels covered by at least half of them. No ground-truth is used. Figure 4 : Test-time scaling via legend ensembling. Each analysis varies one factor and keeps other settings as described below. Training. The analyses use two reduced setups, one for segmentation and one for geometry. Each variant fine-tunes F2K9B Base with the full-scale 9B setup ( Sec. 2.4 ) for 37.5K steps, at a global batch size of 64 (segmentation) or 8 (geometry). A segmentation run takes about
370 GPU-hours on GH200 GPUs (23 h on 16 GPUs), and a geometry run about 80 GPU-hours on
H200 GPUs (20 h on 4 GPUs). Data. Training examples follow the segmentation and geometry mixtures in Appendix Table 20 . Each epoch draws about 250K (segmentation) or 160K (geometry) samples, so the 2.4M and 300K samples seen during training amount to 9.6 and 1.9 epochs. Segmentation sampling is without replacement; geometry sampling follows source quotas and uses replacement when a source is too small (Appendix C.2 ). Evaluation. Segmentation variants are evaluated on the segmentation benchmarks in Appendix Table 21 . For the geometry ablations, we additionally report five evaluations of other tasks to check whether a gain in depth or normals comes at the cost of the model’s other capabilities: Cityscapes mIoU (CS), COCO-Stuff mIoU (CO), RefCOCOg cIoU (RS), SA-Co/Gold-14K cgF1 (IS), and the ImgEdit UGE score (IE).
Cityscapes and RefCOCOg use the full validation splits, and COCO-Stuff and SA-Co/Gold use fixed subsets ( C.4 ). Appendix C.3 gives the full evaluation protocol. 4.1 Task Definition We first study how to express the tasks as RGB images. Additional analysis can be found in Appendix E . RQ-S1. Which class–color mappings let the model generalize and follow the prompt? Setup. To test whether a model memorizes a fixed class–color mapping ( e.g. , ‘car’ → \rightarrow blue) or learns to follow the colors given in the prompt, we vary the mapping at training and evaluation time, using the 19 Cityscapes classes shared by all datasets in this experiment. Fixed colors (#1) always lists all 19 classes with fixed color–class correspondences, random colors (#2) lists all 19 classes with new colors for every sample, and random subset (#3) lists only a random subset of present classes, leaving unlisted regions black ( Fig. 9 ). Random colors are drawn from the 100 most-separated colors of our palette with a minimum pairwise color difference of Δ ​ E = 25 \Delta E=25 (Euclidean distance in CIELAB, CIE76), relaxed when too few colors satisfy it, or from the 37-color named palette when a prompt uses color names ( Sec. 4.1 ). Distance requirement is relaxed when fewer than required colors satisfy the filtering criteria. Each variant fine-tunes F2K9B Base for 6K steps at batch size 64 on a 40K-sample pool of 25% semantic segmentation (BDD100K and ACDC), 25% identity reconstruction and 50% image editing. Analysis. As shown in Tab. 12 , training with fixed colors performs well under the same evaluation protocol (53.9 mIoU), but collapses when the colors are varied at inference (7.1), indicating rigid memorization of the mapping. Training with random colors (#2) avoids this collapse and reaches 51.0 mIoU with unseen color assignments. In the set protocol, the prompt lists only a subset of the classes and unrequested regions are not scored (Appendix C.3 ), so it tests whether the model follows the legend. ( 4.3 ). Updating more transformer parameters substantially improves segmentation and normal estimation. Depth accuracy is highest when only the embeddings remain frozen. 5 Related Work Pretrained image generators are increasingly used for visual
perception, either by extracting their semantic and geometric features [ 125 , 108 ] or by framing
vision tasks directly as image prediction [ 4 , 95 , 96 , 27 ] .
Specialized models such as Marigold and Lotus further exploit
generative priors for dense geometric prediction [ 38 , 32 ] , but do not aim at preserving the general-purpose generation abilities. More closely related are generalist models that unify generation and
perception. DICEPTION [ 124 ] , Jodi [ 109 ] , OneDiffusion [ 46 ] , and PixWizard [ 50 ] adapt
diffusion-based generators to multiple vision tasks, while SenseNova-Vision [ 31 ] and MODUS [ 113 ] build on unified multimodal architectures.
Vision Banana [ 23 ] demonstrates strong multi-task
perception through instruction-tuning a proprietary image generator
while retaining its generative capabilities. Other studies find that frozen generators can already solve some perception tasks out-of-the-box [ 111 , 54 ] .
OVB differs from these works in that every component is public and in its controlled analysis of critical design choices. An extended discussion is provided in Appendix A . 6 Conclusion Open Vision Banana is a fully open recipe for turning pretrained image generators into unified segmentation and geometry models while largely preserving their editing abilities.
Controlled experiments favor randomized, well-separated color palettes, relative inverse depth, full transformer adaptation, and highlight a trade-off between perception accuracy and retained generation quality.
The resulting models are competitive across tasks, improve further with training-free legend ensembling, and yield stronger frozen features for object discovery and correspondence.
Their main limitation is the weaker perception of open base models relative to proprietary generators such as Nano Banana Pro.

Image generators have evolved from text-to-image synthesis systems into flexible image-to-image engines through latent diffusion, transformer-based diffusion backbones, instruction tuning, and controllable conditioning [ 77 , 71 , 8 , 123 , 104 ] .
This has motivated a growing line of work that reuses generative priors to solve perception tasks instead of training separate discriminative models.
Early diffusion-perception methods such as VPD [ 125 ] , ODISE [ 108 ] , and TADP [ 42 ] showed that pretrained diffusion features and denoising pipelines contain spatially aligned semantic and geometric information useful for segmentation, depth, and dense prediction. These methods typically train perception heads on the extracted features or modify the architecture, so the prediction is not produced by the generator itself. Vision tasks as image generation. A second line of work frames vision tasks directly as image generation. Early methods show that masks, depth maps, and other perception outputs can be represented as RGB images [ 96 , 98 , 27 , 24 ] .
More recent contributions exploit strong visual priors acquired by generative foundation models during large-scale pretraining for dense prediction, mostly depth and surface normals [ 38 , 39 , 28 , 22 , 112 , 106 , 32 , 33 , 94 ] .
Several concurrent works study segmentation-specific uses of generative models [ 92 , 1 , 40 , 117 ] .
These models usually address one or a few tasks and do not try to preserve or evaluate general image generation. Unified generation and understanding. The idea of unifying heterogeneous vision tasks through a shared image-space prediction interface predates the recent wave of generative foundation models. Early works such as Visual Prompting via Image Inpainting [ 4 ] and Painter [ 95 ] formulated diverse computer-vision tasks as image prediction. More recently, this idea has been revisited in the context of pretrained generative models that unify generation and understanding.
DICEPTION [ 124 ] is one of the closest open baselines, using color-encoded perception targets in a diffusion model. Vision Banana [ 23 ] demonstrates that instruction-tuning Nano Banana Pro on vision-task data can turn a generator into a strong generalist perception model without sacrificing its original generation abilities. Generally, unified multimodal systems differ mainly in the generative backbone they adapt. Jodi [ 109 ] , OneDiffusion [ 46 ] , PixWizard [ 50 ] , and UniPercept [ 126 ] build on diffusion- or flow-based image generators and model perception outputs as images, labels, or task-specific visual representations. SenseNova-Vision [ 31 ] and MODUS [ 113 ] instead adapt BAGEL-style [ 16 ] unified multimodal decoders, combining autoregressive text generation with a shared flow-matching visual generation pathway for producing dense RGB outputs through VAE latents. Relatedly, RINO [ 111 ] and other recent works [ 54 , 18 ] show that off-the-shelf image generation or editing models already possess substantial dense-prediction capabilities without perception-specific adaptation or retraining, though they typically underperform tuned approaches and rely on adjusted evaluation protocols to become competitive. OVB adapts pretrained flow-matching generators using only public data, releases its training code and weights, and ablates the design choices that proprietary systems leave unspecified. B.2 Instance-segmentation inference and readout Training targets. When the queried category is present in a training example, we keep the 32 largest instance masks of that category (the cap applies only to training targets), rank them left-to-right by their first foreground pixel with ties broken top-to-bottom, and paint the i i -th mask in the i i -th prompt color on a black background. Prompt and target therefore always agree on which instance gets which color. Negative examples without the queried category use the same 32-color prompt with an all-black target. The exact datasets used for evaluation are listed in Table 21 . Generation. We compare each final model with its base generator using matched inference and judging settings, with 28 steps and guidance 3.5. GenAI-Bench [ 47 ] uses VQAScore with the CLIP–FlanT5 [XXL] judge, for the final models and the geometry ablations alike (IG-C, Table 31 ); ImgEdit-Bench [ 114 ] uses ImgEdit-Judge. Both results are averaged over three generation seeds. Editing uses a fixed assignment to 16 logical shards because the noise generator advances between examples within each shard. Semantic segmentation. Mean intersection-over-union (mIoU), computed as the arithmetic mean of the per-class IoUs is used for evaluation. We consider three evaluation protocols. Fixed uses the complete dataset taxonomy with its canonical class–color mapping. Random-draw ( rd ) retains the complete taxonomy but samples a new class–color mapping for each image, thereby measuring generalization across colors. Set requests a random subset of the classes present in each image and assigns them random colors. Its size is drawn uniformly between 1 and one fewer than the number of present classes, or is 1 if only one class is present. Only the requested classes are scored and pixels of other classes are ignored, so this protocol measures how accurately the model paints the requested classes, without penalizing painting in unrequested regions. Unless otherwise stated, we use random-draw evaluation throughout the paper. Referring segmentation. Following LISA [ 45 ] , we report cumulative IoU (cIoU), the summed foreground intersection divided by the summed foreground union over all queries, and gIoU, the mean per-query foreground IoU. cIoU weights queries by their union area, whereas gIoU gives every query equal weight. Instance segmentation. We use the official SA-Co/Gold evaluator of SAM 3, as Vision Banana does. It retains only queries that are instance-exhaustive in all three oracle annotations. Each decoded instance ( Sec. B.2 ) is exported as a binary COCO RLE mask with confidence 1.0, so the evaluator’s 0.5 score threshold discards nothing. Queries that the VLM presence gate judges absent receive no prediction, Vision Banana filters queries the same way with Gemini 3.1 Flash-Lite. For each query, we score the same predictions against all three annotations and keep the result with the highest local F1, averaged over the IoU thresholds from 0.50 to 0.95 in steps of 0.05. An empty prediction for an empty target counts as perfect. Evaluation uses all ground-truth instances, without the training cap of 32. Positive micro-F1 (pmF1) measures instance matching and mask localization on positive queries. Image-level Matthews correlation coefficient (IL-MCC) measures category-presence accuracy. E.2.4 Combined choices and seed variation Table 29 (c) starts from a separately trained 50K-step reference using the duration-study recipe: 20/10 allocation, all five sources, uneroded validity masks, pixel-explicit depth and concise normals. We add the listed changes cumulatively. Neither switching to 10/20 nor then adding erosion improves geometry. The full combination also removes Replica depth and Synscapes normals; all three seeds lower normal error but raise depth error. Only this combination was repeated, so the normal gain cannot be separated from variation between reference runs. E.2.5 Replay and perception-data diversity RQ-D2. How much replay and perception-data diversity are required? Table 31 compares two 37.5K-step studies. The first varies the replay fraction from a 40% reference, keeping generation, editing and identity at a 3:3:2 ratio and allocating the remaining probability to perception tasks. The second varies the perception pool size through deterministic nested subsets at fixed task probabilities. Lower replay improves depth relative to 40%, but editing declines at 1% and the preferred fraction varies by metric. The full perception pool gives the lowest depth AbsRel and normal mean error, while some retention metrics favor smaller pools. Appendix F Prompt Definitions This section records the model-facing prompt families used across tasks. F.1 Prompts for 2D tasks Semantic segmentation. Each prompt begins with [TASK: SEMANTIC_SEGMENTATION] , followed by
one of ten templates sampled with equal probability. The complete prompt therefore reads [TASK: SEMANTIC_SEGMENTATION] ⟨ \langle sampled template ⟩ \rangle Six dictionary-style templates embed the class–color mapping as a legend {legend} of the form {"road": "sky blue", "car": "red", ...} : 1. Generate a semantic segmentation visualization of the input image, using this color mapping: { legend } Color each pixel of a listed class with its color and leave everything else black. Output only the segmentation visualization image. 2. Segment only the following classes, using exactly these colors: { legend } All other pixels must be black. Output only the segmentation image. 3. Produce a segmentation mask that highlights only these classes with the given colors: { legend } Everything not listed must be black. Output just the mask image. 4. Using the color legend below, paint each named class in its color and leave the rest black: { legend } Output only the segmentation visualization image. 5. Generate a semantic segmentation visualization image, using this color mapping: { legend } . 6. Generate a visualization image of semantic segmentation, using this color mapping: { legend } . Four sentence-style templates consist of a lead-in followed by one clause per
requested class: 1. This image is a per-pixel class labeling of the input. The { class } are represented by { color } . … 2. Generate a semantic segmentation visualization of the input. The { class } is { color } . … 3. Produce a per-pixel semantic segmentation of the image. The { class } should be colored { color } . … 4. Color the input image by semantic class. Paint the { class } { color } . … Each prompt writes all of its colors in one notation: an everyday
color name (e.g., sky blue ), an RGB list (e.g., [220,30,30] ),
or a hexadecimal code (e.g., #DC1E1E ). In dictionary legends, names
are quoted, whereas RGB and hexadecimal values are not. The notation is sampled
uniformly per prompt; names are unavailable when the legend exceeds the
37-color named palette. Only the first four dictionary templates state that
unlisted pixels are black, but the target renders them black for every
template. The released per-example manifest stores the fully rendered prompt. Referring segmentation. Each prompt begins with [TASK: REFERRING_SEGMENTATION] , followed by
one of three templates sampled uniformly. So, the complete prompt structure is [TASK: REFERRING_SEGMENTATION] ⟨ \langle sampled template ⟩ \rangle Here, {expression} is the referring expression, {color} a
color name sampled from the 37-color named palette, and {rgb} its RGB
value (e.g., [220,30,30] ): 1. Given the referring expression “ { expression } ”, produce only the mask image: paint the target region { color } ( { rgb } ), and leave everything else black ([0,0,0]). 2. Segment the region referred to by: “ { expression } ” Output only a binary segmentation mask with the referred region in { color } RGB { rgb } and all background pixels black RGB [0,0,0]. 3. Create a binary mask for “ { expression } ” Use { color } for the referred object or region and black for the background. Output only the mask image. All three templates specify a black background; the third names the
foreground color without its RGB value. Instance segmentation. Each prompt begins with [TASK: INSTANCE_SEGMENTATION] , followed by
one of four base templates (sampled uniformly) and the instance mapping ⟨ \langle instance mapping ⟩ \rangle . Each “ { category } ” is colored differently. Leave everything else black [0, 0, 0]. 4. This image is a segmentation task derived from the input. The “ { category } ” instances are each represented by a unique, solid color on a black [0, 0, 0] background. ⟨ \langle instance mapping ⟩ \rangle : Instances are numbered by where their mask first
appears in a left-to-right scan of the image (ties broken top to bottom). The

F.2 Exact geometry prompts Full-scale models use pixel-explicit inverse depth and concise normals for
both training and evaluation. Depth: concise inverse. Create a dense relative inverse-depth map of the input as neutral
grayscale (R=G=B): closer points are brighter and farther points are darker.
Use one global mapping across the full image, preserve thin structures and
sharp occlusion boundaries, keep smooth surfaces coherent, and return only the
registered depth map. Depth: pixel-explicit inverse. Estimate a dense relative inverse-depth map for the input image. Produce
exactly one output value for every input pixel at the same pixel location, with
closer points brighter and farther points darker. Encode the result as neutral
grayscale (R=G=B) using one consistent mapping over the complete image.
Preserve object silhouettes, thin structures, occlusion boundaries, smooth
surfaces, and small depth changes. Do not alter the scene or add texture,
shading, color, text, labels, legends, borders, or objects; return only the
registered depth map. Depth: scene-preserving inverse. Generate the dense depth representation corresponding to the input
image. Return a pixel-aligned neutral grayscale inverse-depth map (R=G=B), with
nearer geometry brighter and farther geometry darker under one image-wide
mapping. Preserve the input composition and fine boundaries, and output only
the depth map without text, labels, legends, or additional objects. Depth: scene-preserving metric RGB. Generate a dense metric projective camera-depth visualization
corresponding to the input image. Encode camera-z depth in meters with the
declared bounded RGB depth transform, maintaining exact pixel-to-pixel
registration and crisp depth boundaries. Return only the RGB depth
visualization without text, labels, legends, or additional objects. Normals: concise. Create a dense camera-space unit surface-normal map registered to the
input. Use +x image-right, +y image-up, +z toward the camera and encode (x,y,z)
as R=(1-x)/2, G=(1+y)/2, B=(1+z)/2. Preserve planes, curved surfaces, thin
structures, and sharp orientation boundaries; return only the RGB normal map. Normals: pixel-explicit. Estimate a dense camera-space unit surface normal for every input pixel
at the same pixel location. Use +x image-right, +y image-up, and +z toward the
camera. Encode physical (x,y,z) as R=(1-x)/2, G=(1+y)/2, B=(1+z)/2. Preserve
planar and curved geometry, thin structures, and sharp orientation
discontinuities. Do not copy image texture, change the scene, or add text,
labels, legends, borders, or objects; return only the registered RGB normal
map. Normals: scene-preserving. Generate the dense camera-space surface-normal representation
corresponding to the input image. Use +x image-right, +y image-up, +z toward
the camera and encode the unit vector as R=(1-x)/2, G=(1+y)/2, B=(1+z)/2.
Maintain pixel alignment and surface boundaries, and return only the RGB
normal map without text, labels, legends, or additional objects. Appendix G Additional Qualitative Results This appendix collects further qualitative examples for the selected models
