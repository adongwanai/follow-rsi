# HexaShell v3 独立边界复审

2026-11-13。仅阅读已归档的 v2/v3 原文；无新网络、付费调用、canonical 修改或 Git 操作。

**可完成新版的有限范围建议：技能策略更新分支归 `harness/component`，同时保留具身与经验属性。** 固定通用 API、agent loop、sandbox 的工程迁移不属于自演化。v2 的旧接受决定和旧刊保持。

| 对象 | 独立判断 | 原文定位 |
| --- | --- | --- |
| 通用 API、循环、沙箱 | 固定共享实现，不能作为反馈演化证据 | v3 §2 |
| 技能的 Flow、工具调用和失败修正规则 | 根据执行证据改变后续行为，属于可复用策略文件中的控制指令 | v3 §2.4、§3.4、附录 H、I.3 |
| 技能的观测事实、数字、episode 计数 | 经验内容；不能单独凭这些内容认定 Harness 更新 | v3 §2.4、E.6 |
| 技能生成与修改 | 分析 Agent 读轨迹起草，人逐份复核；RoboDojo 开发轮次中有四版，RoboTwin 另有 v1→v2 | v3 §2.4、E.6、D |
| 技能保留 | 在后续新 episode、新布局、种子和指令模板使用；未证明同一技能迁移至新任务种类 | v3 A.1、§5 |
| 旧 TaskTools | 反馈驱动改工具的历史分支仍成立，但必须保留退化、捷径与人工输入边界 | v2 §3.4、D；v3 §3.4 |

这不是因为文件叫 skill 或使用 Markdown 就纳入。原文明确列出有序动作、调用什么工具、失败时改走哪条路线、何时禁止重复执行。例如插充电器技能要求先对两臂作 dry run，无臂能水平插入时先移动插线板；按数按键技能要求每次只计一次，禁止“再按一次确认”。这些是控制策略。另一方面，作者将技能类比为 Reflexion 的语言教训，技能中的事实和参数仍有经验属性，不能将整套系统全部标为自演化。

分析 Agent 起草、人工逐份审核、脚本检查可观察性与格式，这三者必须分开。论文没有量化人工改写比例，也没有给出无人参与的自动采纳/淘汰闭环。上述未知限制自主性主张；已明确的四版迭代和后续 episode 复用足以完成当前“后续任务或改进轮次保留”口径下的有限范围建议。不得把新布局复用写成新任务类别迁移，作者明确新任务仍从通用组件起步。

旧反证保留如下：

- TaskTools 冻结后在开发回放中仅通过 **152/420（约 36%）**；七个任务的工具存在从场景复制对象尺寸的捷径。另一处 **157/420** 是公共 episode 对照，口径不同，不混写。
- 旧分支也有人类 checker 笔记、人工重建工具以及同事用其他 coding agent 写的工具种子；不能描述为完全从零自主。
- TaskTools 的官方隐藏 seed 评测与新版公开测试协议不同；loop、感知、运动与 prompt 同时更换，不能把跨分支差异全部归因于技能。
- RoboTwin 的技能 v1→v2 比较明确标为 **in-sample**。RoboDojo 的 R0→R1 同时加入技能和新运动规划器。
- make-toast 技能在三个杂乱布局限制了原本成功的双臂交接路线；技能并非单调改善。
- 技能中还有 `untested` 项，episode 引证可重复；本次未重跑检查脚本或复现实验。
