Web-facing AI agents repeatedly access webpages, documents, repositories, and tool responses, yet reading interfaces often expose entire objects when only sparse evidence is needed. This over-reading increases token and latency costs and can dilute relevant evidence. We present SparseRead, a reusable reading control layer that governs content admission without modifying the agent model. Its Read Intent Protocol tracks evolving needs and source coverage; Adaptive Reader Backends select how evidence is located and exposed; and the Budgeted Read Gate bounds cumulative raw exposure per episode with faithful full-view fallback. A unified Reader interface supports interchangeable evidence acquisition across heterogeneous resources. Across six models, including Claude Opus 5, and five scenarios, SparseRead reduces total tokens by up to 92.9% and wall time by up to 89.0%, preserving or improving task quality in 97% settings. On Web deep-search tasks, it reduces tokens by 31.0–43.0% and task completion time by 23.0–37.0%. Ablations validate the three designs, while integration with three agent frameworks demonstrates portability. Keywords: LLM agents, sparse reading, reading control, evidence acquisition, token efficiency 1. Introduction Large language model (LLM) agents have extended the scope of language models from single-turn generation to long-horizon task execution ( Yao et al., 2023 ; Liu et al., 2024a ) . By coupling reasoning with tool use and access to external artifacts, agents support increasingly complex applications across software engineering, scientific analysis, and interactive environments ( Yang et al., 2024 ; Boiko et al., 2023 ; Zhou et al., 2024 ) . For Web agents, these artifacts include webpages, online reports, code repositories, and structured responses from Web APIs. This capability, however, introduces a markedly different inference profile: each step adds new observations that may remain in subsequent model calls, causing token consumption, latency, and serving cost to grow rapidly with trajectory length. This raises a question for agent infrastructure: what should an agent read from a Web resource before its next decision? Reading constitutes a major source of this growth. Prior work reports that external observations account for 60–80% of the tokens processed in agent trajectories ( Wang et al., 2026a ) . Yet an agent may receive an entire page, file, or tool result when its next decision requires only a few source passages. Paired executions further show that unmodified agents can consume up to 17.3 × \times more tokens without achieving higher task quality. Excess content is not necessarily benign; by diluting relevant evidence, it can induce erroneous tool use, source confusion, and failures to stop. We refer to this mismatch as over-reading: external artifacts are accessed at object granularity, although each decision often requires only a bounded evidence slice. Existing techniques address parts of this problem without jointly controlling artifact reading. Long-context architectures and KV-cache compression reduce the compute and memory overhead of context, but do not decide which source content the model should see ( Zaheer et al., 2020 ; Li et al., 2024 ) . ACON and observation masking reduce tool observations or their persistence in the trajectory ( Kang et al., 2026 ; Lindenbauer et al., 2025 ) . Retrieval, including iterative and agentic approaches, can acquire passages on demand ( Asai et al., 2024 ; Xu et al., 2023 ; Guu et al., 2020 ) , but does not by itself provide a common artifact-level contract for evolving read intents, explicit source coverage, bounded exposure, and full-view fallback. A general mechanism is still needed to govern artifact access before unnecessary content enters the agent context. Human reading provides a natural abstraction for this missing capability. Human readers first clarify their purpose, inspect an artifact’s structure when needed, focus on relevant passages, and revisit unresolved details. We call this capability Sparse Reading: the agent reads only what its current reasoning requires and expands the read only when additional evidence is needed. Turning this pattern into an agent mechanism raises two challenges. First, information needs change as an agent works through subgoals and verification steps. Each partial read must clarify its purpose, record what has been inspected and what remains uncovered, and use an appropriate way to acquire evidence from the current artifact. Otherwise, the agent may repeatedly revisit the same source. Second, sparse access is not always economical. Small objects and requests that require a complete model-visible view may make repeated partial reads more costly than direct access. These challenges call for explicit evidence state, flexible evidence acquisition, and online control over when to continue reading or fall back to a full view. We present SparseRead , a framework that controls artifact admission before broad content enters the model context. The agent states its per-access needs through a Read Intent, and the reading layer returns an EvidencePack containing bounded, source-anchored evidence and explicit coverage; the agent decides whether the evidence is sufficient. SparseRead combines a Read Intent Protocol, Adaptive Reader Backends, and a Budgeted Read Gate. SparseRead can be integrated into existing agent frameworks and used with existing LLMs, without changes to model parameters or a separate generative compression model. This paper makes the following contributions: • Read Intent Protocol. We introduce a cooperative protocol that turns broad artifact access into a bounded and stateful reading process. It makes per-access evidence needs and source coverage explicit, while leaving sufficiency and stopping decisions to the agent. • Adaptive Reader Backends. We separate reading control from evidence acquisition through a unified Reader interface. Reader configurations combine artifact-specific location or processing methods with exposure forms, selected using calibrated evidence reliability and estimated reading costs. • Budgeted Read Gate. We introduce an inference-time controller that regulates when sparse reading is attempted and when a full view is preferable. An episode-level exposure budget bounds cumulative raw artifact exposure while retaining an explicit full-view fallback. • Evaluation. We compare SparseRead with strong native agents and static and agentic RAG across five scenarios, and examine the contribution and effective regime of each component. 2. Quantifying the Cost of Over-Reading We first quantify the sparsity of annotated supporting evidence, then examine how broad exposure accumulates across later calls. Together, these observations make over-reading a measurable agent execution problem. Comparison of task quality and token use for sparse and full reading. Figure 3. Quality-efficiency comparison. Sparse reading matches or improves task quality while using fewer tokens than full reading. More exposed context does not automatically produce better answers. Comparison of task quality and token use for sparse and full reading. 2.1. Useful Evidence Is Sparse Figure 2 shows reading-budget breakdowns across representative workloads. For long-document QA, annotated supporting evidence covers a median of 3.17% of source tokens per question and 2.89% across five questions from one document in LooGLE; the share is about 5.8% for analyzed answerable Qasper questions with evidence annotations. These annotation ratios differ from the figure’s exposure shares and do not measure the reading needed to locate and verify evidence. Moreover, different questions may require evidence from different parts of the same document. This motivates evidence acquisition guided by the current information need rather than a fixed summary of the entire source. This observation also highlights three distinct quantities: processing scope, model exposure, and evidence coverage. Processing scope describes how much source content a Reader examines or computes over, whereas exposure measures what enters the model context. A Reader can scan an entire table to compute a column sum while exposing only the result, row count, and source. Coverage, in turn, records which slots in the current Read Intent have supporting evidence and which remain unresolved, without judging sufficiency. These quantities need not scale together. In particular, reducing model exposure does not require reducing the amount of source content processed, allowing Sparse Reading to benefit both localized retrieval and exact whole-object operations. Over-Reading Compounds Across Model Calls The cost of a broad read can extend beyond its initial admission. Content exposed at step i i may remain in later model calls. Let e i e_{i} denote newly exposed content and R i R_{i} the number of subsequent calls retaining it. The resulting replay-weighted exposure is C exposure = ∑ i | e i | ​ R i C_{\mathrm{exposure}}=\sum_{i}|e_{i}|R_{i} . This measures logical context replay, not billed tokens or physical prefill work; prefix caching can lower their marginal costs without removing retained content. If broad reading always improved quality, over-reading would be a cost-only problem. Figure 3 shows otherwise. In paired high-sparsity runs, full-read agents spend up to 17.3 times more tokens than SparseRead while failing to improve task score. Across model and task groups, selective reading preserves or improves score while reducing exposed context. The result does not imply that less context is always better; it shows that broad context is not a free substitute for reading control. These observations show why reading should be controlled, but not what evidence an agent should seek, how its coverage is tracked, or when to switch to a full view. 3. Why Retrieval or Compression Alone Is Not Enough Problem formulation. At step t t , let o o denote the current external artifact and h t h_{t} the current Read Intent. The core challenge is to choose the content x t x_{t} exposed to the model before its next decision, while preserving task-relevant evidence, tracking coverage of h t h_{t} , and controlling the cost of subsequent reads. Retrieval can locate passages, including through iterative queries, while compression can reduce the content admitted to context. Yet neither alone establishes a common reading contract across heterogeneous artifacts. Two challenges remain: tracking evolving evidence needs and deciding when selective reading is no longer economical. 3.1. Challenge 1: Evolving Needs and Uncertain Evidence Coverage An agent’s information needs evolve during execution. The opening request establishes a session-level objective, but subsequent steps introduce subgoals, follow-up questions, and verification needs. Each access therefore requires an intent specific to the current decision. Iterative retrieval can also update queries; the missing abstraction is a consistent intent and evidence record across artifact types and access tools. Figure 4 (a) shows that protocol repair reduces total model tokens by 2.1–6.3 × \times across long-book QA, multi-file audit, PDF report QA, and Web search. Without a record of inspected regions and unresolved evidence slots, an agent may reopen artifacts or continue searching unnecessarily. Coverage records what has been inspected or found, rather than declaring the evidence sufficient. Source-anchored evidence and explicit coverage help the agent decide what to read or verify next, and when to stop. Evidence acquisition also depends on the artifact. Figure 4 (b) shows that the best evidence location method varies across artifact types: dense hybrid retrieval works best for long text, while column queries and key-path lookup are more effective for tables and JSON/logs, respectively. Locating evidence and deciding how much to expose are separate choices, motivating configurable Readers rather than a single retrieval pipeline. 3.2. Challenge 2: The Regime Boundary Is Unknown Before Reading Sparse Reading is well-suited for tasks that require extracting localized information from large artifacts. Long-document QA, PDF comprehension, and audit bundles exhibit this characteristic. However, some tasks favor a full view: small objects may fit directly into context, and some requests require full model-visible access. For these tasks, sparse reading may add overhead without reducing token usage. In contrast, an exact whole-table operation can process the full source yet expose only a compact, verifiable result. Figure 4 (c) illustrates this boundary. Sparse Reading reduces token consumption by 80–88% on high-sparsity QA and audit tasks, while forced sparse reading increases tokens by 309% for global statistics and 210% for a rule-coding task, where repeated selective access outweighs its savings. Sparse Reading should therefore have an explicit fallback rather than being applied uniformly. This boundary cannot always be determined before reading: the evidence needed for a decision and the cost of subsequent refinement remain uncertain. Object size or type alone is insufficient. Rather than predicting the optimal regime in advance, an online controller can attempt sparse reading while limiting cumulative exposure against the cost of a faithful full view, switching before the next batch exceeds the budget. Design implication. Together, these challenges show that Sparse Reading needs more than retrieval or compression. The Read Intent Protocol tracks evolving needs and evidence coverage, Adaptive Reader Backends choose how evidence is located and exposed, and the Budgeted Read Gate controls exposure and full-view fallback, forming a unified reading loop. 4. SparseRead Design SparseRead separates reading control from evidence acquisition. The control plane interprets an agent’s reading intent, selects among eligible Reader configurations, maintains the evidence record, and governs what enters the model context. The evidence plane contains Readers that declare their supported artifact types, actions, and execution costs. Readers acquire evidence but do not decide when they are invoked. Figure 5 illustrates the architecture. Throughout the design, we distinguish the scope processed by a Reader, the content exposed to the model, and the evidence coverage of the current intent. The two planes share a common contract: Read Intent → \rightarrow EvidencePack . It covers targeted passages, faithful compact views, and results of exact source operations without changing the agent-facing interface. Ordinary sparse reads leave preceding turns intact, allowing exact-match prefix reuse. A subsequent fallback may retire earlier sparse observations to avoid further replay, potentially losing prefix-cache reuse from the edited point onward. Read Intent Protocol SparseRead treats reading as a sequence of evidence requests guided by the agent. At each access, the agent supplies a structured Read Intent describing what it needs for its next decision. This access intent takes precedence over a session intent derived from the user’s opening request. The session intent fills in unspecified details rather than overriding a new subgoal or follow-up question. An actionable intent proceeds directly to evidence acquisition; an underspecified one receives a bounded Object Preview for refinement. The agent can also request the same preview explicitly through scout . Each read returns an EvidencePack with source-anchored evidence, the scope examined or processed, the amount exposed, and coverage for individual evidence slots. Coverage identifies which needs have supporting evidence and which remain unresolved. It does not establish whether the evidence is sufficient to answer the task. The agent decides whether to answer, refine, or verify; neither the protocol nor the Reader declares completion. The protocol also maintains the validity and relevance of prior evidence. A SHA-256 fingerprint identifies the artifact version; when it changes, evidence and coverage recorded for that artifact are invalidated. On an unchanged version, earlier spans remain valid but may not cover a new intent. Lightweight validation checks for identifiable slots and consistent scope requirements using structural signals rather than task-specific rules. Vague intents trigger an Object Preview, while inconsistent scope requests are flagged and resolved according to their stated coverage requirements. The agent interacts through five stable actions, 𝒜 = { scout , focus , collect , refine , verify } \mathcal{A}=\{\mathrm{scout},\allowbreak\mathrm{focus},\allowbreak\mathrm{collect},\allowbreak\mathrm{refine},\allowbreak\mathrm{verify}\} . The selected Reader maps each supported action to operations over its artifact type, so adding Readers does not expand the agent’s action set. A reading episode is a sequence of accesses to one artifact version under a single reading objective. Refinement and verification within an episode share its evidence record and exposure budget, even as the access intent changes. A distinct objective starts a new episode. Adaptive Reader Backends A Reader is defined by the artifacts it handles, not by a particular retrieval algorithm or evaluation scenario. Each Reader registers its supported artifact types, agent actions, and cost profile behind the unified interface. Within a Reader, evidence acquisition has two related choices: how to locate or process evidence , and what to expose to the agent . For example, a text or PDF Reader may locate passages using lexical matching, BM25 windows, or hybrid retrieval. A structured Reader may select columns or key paths, or execute an exact computation; a collection Reader may gather evidence across files. These are location or processing methods within Readers, not separate Reader types. The exposure choice is distinct. Depending on the intent, a Reader may return anchored snippets, a lossless compact view of the entire artifact, or the result and provenance of an exact operation. Not every method supports every exposure form. We define a Reader configuration r r as a supported combination of a registered Reader, its evidence location or processing method, and an exposure form. All configurations produce the same EvidencePack contract. This separation allows both new artifact types and improved location methods to be introduced without changing the agent’s reading interface. The evidence matching differences across artifact types in Section 3 motivate selecting configurations rather than imposing one retrieval pipeline. SparseRead adapts this choice to the artifact type, size range, and Read Intent. Average evidence recall alone is not a probability of valid evidence. When no configuration meets the reliability requirement, the system falls back to a full view rather than silently relaxing the threshold. Read outcomes can further inform cost estimates: repeated access or escalation indicates extra reading work, whereas a verification request is not itself a failure. Such behavioral signals do not establish evidence correctness. Likewise, source anchors and fingerprints establish provenance, not relevance or sufficiency. This division keeps reliability calibration separate from cost adaptation. Specialized Readers and new evidence methods continue to use the same interface. 4.3. Budgeted Read Gate The Read Gate determines when selective access is worthwhile and when to fall back to a complete view. Let f ⁡ ( o ) f(o) be the least expensive faithful full view available for the current request. It may be the original native read or a lossless compact representation of the entire artifact, provided it preserves the access required by the intent. Let L = | f ⁡ ( o ) | L=|f(o)| be its exposed length. Thus, a compact full view offered by a Reader can lower the Gate’s budget. The selected f ⁡ ( o ) f(o) and L L remain fixed within an episode; switching to a different full view starts a new episode. Both L L and the cumulative sparse payload E E use the same unit, character length in our implementation, rather than disk size or replay-weighted tokens. The Gate follows three rules. First, it uses full-view access when the model must inspect the complete content or no suitable Reader is available. Second, it bypasses sparse reading for small artifacts. Otherwise, it begins with sparse evidence and enforces E ≤ L E\leq L . Before delivering a batch, it compares its estimated size with the remaining budget. Serialization then checks the actual payload against the same limit. If the next batch cannot fit intact, it is withheld and the Gate delivers f ⁡ ( o ) f(o) instead. Evidence is never truncated in a way that breaks its meaning or source anchors. Full source processing does not necessarily require full model exposure. A table Reader, for example, can scan every row to calculate a sum and expose only the result, row count, and provenance. The Gate admits this operation to the Reader path because the exposed result is small, even though the processing scope is complete. When a full view has been delivered as evidence, subsequent fallback reuses that view rather than exposing it a second time. Proposition 4.1 (Native-relative exposure bound). Consider a reading episode on a fixed artifact version with a fixed full view f ⁡ ( o ) f(o) of length L L . If the Gate admits at most L L of cumulative unweighted sparse payload and delivers at most one full view on fallback, the episode’s total unweighted artifact exposure is at most 2 ​ L 2L , excluding separately bounded preview and protocol metadata. The argument is immediate: sparse batches contribute at most L L and a full view adds at most L L (proof in Appendix A ). When an ordinary native full read is among the admissible representations, L L is no greater than its length, so the bound is also at most twice the exposure of that native read. The bound limits the downside of selective reading; savings arise when the agent can finish with much less than L L evidence. It is not a bound on replay-weighted context, billed tokens, task latency, or performance against an oracle that already knows where the answer lies. On fallback, earlier sparse observations are retired from later prompts to avoid continued replay, although their previous cost cannot be recovered. The guarantee applies per episode, not across an entire agent session. 5. Implementation and Agent Integration Agent harness integration. The SparseRead core is a shared

RQ1 examines whether SparseRead improves reading efficiency across models and scenarios without sacrificing task quality. RQ2 compares SparseRead with retrieval and context compression in both token cost and end-to-end latency. RQ3 examines the effects of intent handling, Reader location methods, and Gate budget checks on evidence quality and reading efficiency. RQ4 evaluates whether the same SparseRead design transfers across agent frameworks. Tasks and scenarios. We organize the main evaluation around five scenarios, with task sources specified separately for each. Long-context reading uses document-comprehension tasks from LooGLE and PinchBench, together with a fact-extraction task adapted from Workspace-Bench-Lite ( Li et al., 2023a ; Kilo, 2026 ; Tang et al., 2026 ) . Multi-file audit and diagnosis uses QwenClawBench tasks that require locating and reconciling evidence across workspace files ( Qwen Team and Alibaba Data, 2026 ) . Structured analysis combines QwenClawBench tasks with spreadsheet-manipulation tasks adapted from SpreadsheetBench Verified ( Qwen Team and Alibaba Data, 2026 ; Ma et al., 2024 ) . Web deep search draws tasks from FRAMES and BrowseComp-Plus, requiring iterative search and evidence synthesis across multiple documents ( Krishna et al., 2025 ; Chen et al., 2025 ) . AI for Science uses LAMMPS script-generation tasks adapted from MDGYM ( Kumar et al., 2026 ) , with scientific script libraries serving as reading resources. Appendix B gives detailed source and adaptation descriptions. Native-fit controls are treated separately in Appendix C , rather than as a main scenario. Models. Related Work Prompt and KV compression. Selective Context, LLMLingua, Gist Tokens, AutoCompressors, and ICAE reduce prompt text or learn compact representations ( Li et al., 2023b ; Jiang et al., 2023 ; Jiang et al., 2024 ; Pan et al., 2024 ; Mu et al., 2023 ; Chevalier et al., 2023 ; Ge et al., 2024 ) ; KV methods optimize cached attention states ( Zhang et al., 2023 ; Xiao et al., 2024 ; Li et al., 2024 ; Cai et al., 2024 ; Liu et al., 2024c ; He et al., 2024 ; Liu et al., 2024b ) . SparseRead governs external artifact access and complements these inference optimizations. Ordinary sparse accesses preserve preceding turns, enabling prefix reuse ( Gim et al., 2024 ) . Agent observations and histories. SWE-Pruner and Squeez prune tool outputs according to task needs ( Wang et al., 2026a ; Kovács, 2026 ) ; SWE-Pruner Pro selects lines using the agent’s internal representations ( Wang et al., 2026b ) . CoACT, AgentDiet, TACO, ACON, and AgentFold reduce observations or histories ( Chen et al., 2026 ; Xiao et al., 2026 ; Ren et al., 2026 ; Kang et al., 2026 ; Ye et al., 2025 ) , while observation masking drops older observations ( Lindenbauer et al., 2025 ) . SparseRead provides a reading control layer above individual compressors: its pluggable Reader interface lets SWE-Pruner and Squeez serve as compression backends. The Read Intent Protocol coordinates these backends through versioned evidence records linking intent, source coverage, and unresolved needs across refinement and verification. Active reading and retrieval. ReadAgent combines gist memories with selective lookup ( Lee et al., 2024 ) ; IRCoT and Self-RAG interleave retrieval with reasoning or reflection ( Trivedi et al., 2023 ; Asai et al., 2024 ) ; Adaptive-RAG routes retrieval by question complexity ( Jeong et al., 2024 ) . Retrieval is one acquisition method under SparseRead’s unified evidence contract, alongside structured projections and exact source operations. Processing scope and model exposure are controlled separately : a Reader may scan an entire table yet expose only the result and provenance. Its Budgeted Read Gate adapts classical ski rental budgeting ( Borodin and El-Yaniv, 1998 ) to cumulative raw exposure across reads, checking each batch before delivery and retaining a faithful full view as fallback within 2 ​ L 2L per episode. 8. Conclusion SparseRead provides a reusable reading control layer between agents and external artifacts. Its stateful protocol, pluggable Readers, and Budgeted Read Gate coordinate evolving evidence needs, separate source processing from model exposure, and bound raw exposure while retaining a faithful full view as fallback. The unified interface lets retrieval and compression methods serve as replaceable backends, so advances in evidence acquisition can strengthen the framework across agent implementations. Evaluations show token and latency savings even for leading models, with task quality preserved or improved in most settings; ablations support the complementary roles of the three designs. Appendix C Native-Fit Controls and Gate Economics Native-fit controls are drawn from QwenClawBench ( Qwen Team and Alibaba Data, 2026 ) and include finding the largest file in a directory, implementing a user-discount calculator, and writing a SPARQL query. They probe settings in which direct tool use or a short native read can already be appropriate. They are excluded from the five main scenarios. In the original five-scenario matrix, including these controls, SparseRead reduces token volume and wall time in all 30 model–scenario cells and preserves or improves score in 26. The corresponding results for the four retained scenarios, excluding Web deep search, preserve or improve score in 22 of 24 cells. Economic boundary of selective reading. The Gate checks whether sparse access is worthwhile before invoking a Reader. When native tools or a short native read already suit the request, it retains that path instead of forcing preview, retrieval, or refinement. This bypass aims to avoid the protocol tax of sparse reading; it does not require the native agent to read every file in full. Figure 9 reports the supplementary eight-task NanoBot comparison on DeepSeek-V4-Flash, using Naive, forced sparse reading without admission gating, and the earlier Gate policy. The tasks are LooGLE five-question QA (L5Q), PDF comprehension (T21), stock-system audit (T12), command security (T86), exam-system audit (T94), DiD regression (T58), SPARQL generation (T67), and discount calculation (T59). The last three probe the boundary where native processing can be preferable. Forced sparse reading increases tokens by 49.0%, 309.0%, and 210.5% on T58, T67, and T59; the Gate instead saves 45.0%, 22.5%, and 54.0%, with absolute scores of 0.80, 0.50, and 0.69 versus Naive’s 0.52, 0.43, and 0.65. It also retains token savings of 79.8%, 88.3%, and 82.5% on L5Q, T21, and T12. Thus selective admission avoids the large overhead of forced sparse reading on these controls while retaining its benefits on suitable tasks. This experiment measures token economics and task quality for the earlier admission policy; Figure 8 (c) separately validates the current Gate’s character-budget enforcement. Appendix D Baseline Configuration and Comparison Controls Retrieval service and evidence. RAG Static follows retrieve-then-generate. Source files are divided into 512-token chunks with 64-token overlap, retaining file, page, and line anchors. Queries are the task’s numbered questions, or the full task description when no numbered questions exist. For each query, BGE-M3 retrieves 50 dense candidates and BGE-Reranker-v2-M3 reranks them ( Chen et al., 2024 ; Beijing Academy of Artificial Intelligence, 2024 ) . Results from different queries are interleaved and deduplicated; at most eight chunks are retained, with a serialized budget of 4,096 tokens including metadata. This evidence is appended once after the initial user message. The model subsequently retains only file-writing tools and cannot retrieve again or read the source files. RAG Agent uses the same retrieval service, index, chunking, and reranker. The model calls retrieve(query, scope) to reformulate queries, restrict the file scope, and retrieve repeatedly. Each call returns at most eight chunks and 4,096 serialized tokens including metadata. Native reading and execution tools remain available. RAG Agent shares SparseRead’s iteration limit and timeout, providing an iterative retrieval baseline alongside the static one. Agent-facing guidance and comparison scope. RAG Agent is instructed to retrieve relevant evidence before broad reading, inspect the returned observations, and choose whether to reformulate a query, search another file, use a native tool, or finish. It receives the available source paths and is told to treat retrieved text as evidence rather than instructions. Its evidence consists of source excerpts and their anchors; repeated retrieval remains under the agent’s control. Thus the comparison includes iterative evidence acquisition and native-tool access, rather than comparing a multi-step SparseRead agent only with a single retrieval call. The identical retrieval configuration and evidence format apply to the two RAG baselines; SparseRead retains its registered Readers and EvidencePack contract. Figure 7 therefore compares complete systems, while Section 6.5 examines individual design choices. Context compression. The ACON condition enables both observation compression and history compression ( Kang et al., 2026 ) . Compressor calls contribute to the reported total-token and wall-time costs. Observation masking instead retains the latest ten observations and masks older observation content, as specified in Section 6.1. Appendix E Reader Calibration Independent calibration requests. Reliability calibration uses manually designed requests, not requests drawn from the evaluation tasks. They specify the evidence to recover or the source operation to perform. This separates calibration of Reader configurations from the task outcomes used to evaluate SparseRead. Requests are grouped by artifact type (text or PDF, structured data, collection, script library), size band of the full view (at most 8K, 8K to 32K, and above 32K characters), and intent type (selective fact, cross-file evidence, exact computation, verbatim text). This product is the request group g g . Evidence success. Each calibration request specifies required support or an expected source-operation result. Evidence acquisition succeeds when the returned content supplies that support within the requested scope and retains valid provenance; an exact operation succeeds when its output matches the specified result for that scope. These binary request-level outcomes inform p ^ valid \widehat{p}_{\mathrm{valid}} . For each configuration and group, p ^ valid \widehat{p}_{\mathrm{valid}} is the lower end of a 95% Wilson interval over these outcomes, and the threshold is τ = 0.6 \tau=0.6 , fixed before evaluation. A group with fewer than 20 calibration requests is not adaptive: it uses the default configuration for its artifact type, and falls back to a full view if that configuration does not meet the threshold. Cost profiles account for evidence exposure and further Reader work, while evaluation reports total tokens and wall time separately. The estimate C ^ \widehat{C} is measured in characters: exposed characters, a fixed per-call overhead for Reader execution, and the mean follow-up exposure observed for the group during calibration. Reliability is calibrated once; evaluation updates only cost estimates.
