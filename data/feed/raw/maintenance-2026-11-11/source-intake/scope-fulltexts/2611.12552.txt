The selected harness and lessons guide the next round. 1.  Introduction We propose SciMARS, a framework for multi-agent recursive self-improvement through task-local harness adaptation in closed-loop scientific discovery, linking in silico analysis with simulated experimental validation.
Scientific discovery advances through cycles of hypothesis generation, experimental design, analysis, and validation. Closed-loop systems connect computational decisions with experimental feedback, so each new observation can inform the next experiment. Multi-agent systems divide this work among specialized roles ( Wu et al., 2023 ; Hong et al., 2024 ) . As evidence changes, these roles must preserve useful findings, communicate constraints, and revise their next steps. Two problems limit this process: evidence becomes isolated across agents, and fixed execution rules repeat mistakes despite access to that evidence. The first problem is the lack of shared memory. An observation or failed check may remain in one agent’s history without reaching another agent whose decision depends on it. A planner may repeat a rejected experiment, or a coder may miss a constraint that the verifier has identified. We address this gap with a shared evidence graph inspired by Mycelium’s active context graphs ( Choudhury et al., 2026 ) . The graph records observations, findings, plans, and unresolved questions with provenance. Retrieval and subscriptions route these records to roles beyond the current handoff. The second problem is a fixed execution harness. Retaining a failed check does not ensure that a planner acts on it, a coder changes its procedure, or a verifier retrieves the right record. Role instructions may omit a required check, handoffs may drop its result, and memory policies may retrieve irrelevant notes. The system must adapt how agents work, exchange information, and use retained evidence. Memory contents and policy serve distinct purposes: records preserve observations; policies govern their use in later decisions. We introduce SciMARS , a unified framework for task-local harness adaptation in closed-loop scientific discovery. Recent methods improve agent harnesses and workflows from execution feedback ( Xu et al., 2026 ; Lee et al., 2026 ; Feng et al., 2026 ) . SciMARS decomposes this adaptation into separate role and coordination proposals. Each editor starts from the same reference execution and proposes a change within its own scope. The controller probes the candidates, composes a successor from their evidence, and selects a harness for the next round. Retained lessons guide later revisions within the same task. This is recursion over the execution harness; the meta-level optimizer does not rewrite itself. Figure 1 illustrates the role–coordination loop. We study two adaptation settings. SciMARS updates role procedures and coordination contracts. SciMARS + Memory adds the shared graph and a third independent editor for memory policy. This editor changes how roles record, retrieve, and receive evidence while preserving the graph’s provenance rules. Candidate probes let the composer assess each proposed component before combining changes; a new combination receives its own probe. A fixed-policy Multi-Agent + Memory control distinguishes access to shared evidence from adaptation of its use. All adaptation decisions use public execution evidence, with official benchmark scores reserved for final evaluation. We evaluate the discovery interface through experimental-data replay and a digital twin in Autonomous Science Bench ( Wen and Liu, 2026 ) . Its six campaigns span biology, chemistry, and materials science. This protocol tests decisions under simulated experimental feedback rather than new physical wet-lab execution. ScienceAgentBench ( Chen et al., 2025 ) evaluates scientific programming, and AppWorld ( Trivedi et al., 2024 ) evaluates interactive execution across tools and application state. We compare the base multi-agent team, fixed memory, integrated workflow search, SciMARS, and SciMARS + Memory. The study covers GLM-5.3 variants ( Z.ai, 2026 ) and a GPT-6-Astra discovery cohort, with the base team as the common reference for the headline results. Our contributions are threefold: (i) A unified framework for task-local adaptation for closed-loop scientific discovery. We use execution evidence to adapt multi-agent systems for scientific analysis and experimental design, evaluating the interface through experimental-data replay and a digital twin. A shared evidence graph carries observations, checks, and unresolved questions across roles and task steps. (ii) Separate adaptation of roles, coordination, and memory use. SciMARS assigns role procedures and coordination contracts to distinct editors. SciMARS + Memory adds an independent editor for memory policy. We probe the proposals and use their evidence to compose and select a successor, rather than revising all components in one integrated proposal. (iii) Experimental results across scientific and interactive tasks. SciMARS + Memory resolves 12/18 GPT-6-Astra and 2/18 GLM-5.3 attempts on Autonomous Science Bench, compared with 8/18 and 1/18 for the base multi-agent team. It solves 14/38 ScienceAgentBench tasks and 11/20 AppWorld tasks, compared with 11/38 and 5/20 for the base team. Overall, these results show that combining shared memory with SciMARS improves multi-agent performance. 2.  Related Work We review related work on multi-agent systems, agentic scientific discovery, and recursive self-improvement to position our approach to task-local harness adaptation. Multi-agent systems. Language-model agents support complex workflows through reasoning, tool use, and execution feedback ( Lee et al., 2026 ; Nam et al., 2026 ) .
Multi-agent frameworks organize these agents into specialized roles with explicit interaction patterns. AutoGen ( Wu et al., 2023 ) coordinates agents through conversation, while MetaGPT ( Hong et al., 2024 ) assigns role-specific procedures. More recent methods adapt the workflows connecting these roles: AFlow ( Zhang et al., 2025b ) uses execution feedback to optimize workflows, and MASS ( Lee et al., 2026 ) searches over roles and information routes. DS-STAR ( Nam et al., 2026 ) provides a data-science agent pipeline and serves as the basis for our execution harness. We introduce the shared memory to multi-agent team ( Choudhury et al., 2026 ) and extend this team with task-local adaptation. Agentic systems for scientific discovery. AI models support scientific applications ranging from genomics and single-cell analysis ( Wang et al., 2025 ; Wang et al., 2026 ; Wu et al., 2025a ; ElSheikh et al., 2026 ; Wu et al., 2025b ; Zhou et al., 2024 ) .
Scientific agents use language models to address different parts of scientific discovery. Our framework targets the coordination of computational design and experimental feedback; we study this interface through data replay and a digital twin. ScienceAgentBench ( Chen et al., 2025 ) evaluates agents on data-driven scientific workflows, while Autonomous Science Bench ( Wen and Liu, 2026 ) evaluates budgeted experimental-design campaigns using experimental-data replay and a digital twin. Recent work such as ADAPT for Science ( Feng et al., 2026 ) evolves scientific optimization procedures from simulation feedback.
We test computational decisions under simulated wet-lab experimental feedback. Recursive self-improvement. Self-Refine ( Madaan et al., 2023 ) and Reflexion ( Shinn et al., 2023 ) use feedback or retained lessons to improve subsequent attempts, while program-improvement methods such as STOP ( Zelikman et al., 2023 ) and the Darwin Gödel Machine ( Zhang et al., 2025a ) revise programs or agent implementations. Recent frameworks extend this idea to agent harnesses and multi-agent workflows: Harness 2 ( Xu et al., 2026 ) uses a task-level propose–probe–compose loop and a cross-task experience mechanism, while MASS ( Lee et al., 2026 ) combines workflow search with model fine-tuning.
These methods act on different adaptation surfaces, from feedback and workflow structure to agent code. SciMARS focuses on task-local execution-harness adaptation. It separates role and coordination edits; its memory extension adds a separate policy editor without changing the graph service or the optimizer. 3.  SciMARS SciMARS adapts a team through execution, scoped proposals, candidate probes, composition, selection, and reflection. It builds on the propose–probe–compose principle of Harness 2 ( Xu et al., 2026 ) . We first define the team and shared memory, then describe one adaptation loop for two settings: SciMARS edits roles and coordination; SciMARS + Memory also edits memory. Table 1 summarizes the loop. 3.1.  Problem and accessible evidence A task provides an instruction x x , public inputs D D , and a resource allowance B B . An execution harness H H governs the team. The executor E E produces a program or action trajectory p p , an execution trace τ \tau , output artifacts or environment state a a , and resource use c c : o = ( p , τ , a , c ) = E ⁡ ( H , x , D ) . o=(p,\tau,a,c)=E(H;x,D). (1) The optimizer seeks a harness that helps the team satisfy the task within B B . It observes public inputs, tool responses, candidate programs, and generated artifacts. It cannot query the official evaluator V V during revision. A host process calls V V after final commitment. A runnable program, completed tool call, or recorded finding does not establish task correctness. Public probes guide revision; official evaluation measures the final outcome. 3.2.  Team harness and editable components SciMARS represents the harness at round t t as H t = ( P t , C t ) , P t = { p t , r : r ∈ ℛ } . H_{t}=(P_{t},C_{t}),\qquad P_{t}=\{p_{t,r}:r\in\mathcal{R}\}. (2) The role set ℛ \mathcal{R} contains an analyzer, planner, coder, verifier, router, debugger, and finalizer. They inspect inputs, plan steps, implement them, check results, route work, repair failures, and prepare deliverables. These are logical responsibilities. They may use the same model, and an adapter may group responsibilities into fewer execution agents. The coordination component C t C_{t} contains routing flags and contracts for existing handoffs. A contract specifies a version, shared fields, a sender instruction, and a receiver instruction. A planner–coder contract can require observed array dimensions in the handoff. A role procedure can instead require the coder to check its inputs. The former changes handoffs; the latter changes role procedures. The seven-role implementation exposes eight interfaces: analyzer–planner, planner–coder, coder–verifier, verifier–router, router–planner, verifier–planner, verifier–finalizer, and coder–finalizer. Available fields include the question, filenames, file descriptions, plans, code, execution output, verification, and routing state. An editor cannot add a field that the executor does not provide. Contract versions track revisions, not quality. A separate meta-level optimizer invokes the editors, composer, selector, and reflector. These are not executions of the seven-role team. The optimizer’s prompts, validators, selection algorithm, tools, and official evaluator remain outside the editable surface. The controller retains the current harness, task-local lessons L t L_{t} , and traces T t T_{t} . Accepted edits govern later rounds of the same task; they do not become a shared learned harness for later evaluation tasks. 3.3.  Shared memory: evidence contents and usage policy Our shared memory draws on Mycelium’s active context-graph design ( Choudhury et al., 2026 ) . It lets a role retrieve evidence recorded by another role beyond the current handoff. We distinguish graph contents G t G_{t} from a memory policy M t M_{t} . The graph holds observations, interpretations, findings, hypotheses, plans, and unresolved questions. The policy determines what roles record and which records reach them. New findings change G t G_{t} ; retrieval rules belong to M t M_{t} . Records and provenance. The graph uses six namespaces: context, work, decisions, status, procedures, and log. Records have keys, types, authors, and versions. Typed edges express support, contradiction, derivation, and dependency. Agent notes link to existing records; source observations can name public files or execution events. Dataset and observation records cannot be overwritten. Host validation enforces the schema and provenance links. These checks preserve an evidence trail but do not certify a claim’s truth. Writing and retrieval. The host records public context and execution observations. Roles add grounded notes through the adapter’s memory interface. A handoff supplies policy-filtered records and a feed of new records from other roles. Retrieval uses node types, namespaces, a query hint, and a record limit. Lexical relevance ranks records, with recency breaking ties. A verifier can link a failed shape check to its execution. The planner retrieves this finding to revise its plan. The extended harness is H t = ( P t , C t , M t ) , M t = { ( w t , r , q t , r , s t , r ) : r ∈ ℛ } , H_{t}=(P_{t},C_{t},M_{t}),\qquad M_{t}=\{(w_{t,r},q_{t,r},s_{t,r}):r\in\mathcal{R}\}, (3) where w t , r w_{t,r} specifies recording duties, q t , r q_{t,r} controls retrieval, and s t , r s_{t,r} lists subscribed record types. The default policy retrieves up to six records per logical role. The graph is scoped to an execution or trial. Where an experiment uses a fixed development-derived store, each trial receives a fresh copy of that seed; evaluation-task writes do not flow into other trials. Fixed versus adaptive memory. Multi-Agent + Memory runs ( P 0 , C 0 , M 0 ) (P_{0},C_{0},M_{0}) without outer harness revision, while its graph grows through execution. SciMARS + Memory uses the same graph interface but permits edits to M t M_{t} alongside P t P_{t} and C t C_{t} . Memory contents and policy must therefore remain distinct in both the method and its controls. The policy editor does not rewrite stored measurements, graph provenance rules, or the memory service. 3.4.  Independent component proposals and probes The controller executes H t H_{t} to obtain reference evidence o t 0 o_{t}^{0} . Each editor receives the same current harness, task requirements, reference evidence, and retrieved lessons. No editor reads another editor’s proposal. SciMARS has two candidates: H t P = ( P t ′ , C t ) , H t C = ( P t , C t ′ ) . H_{t}^{P}=(P_{t}^{\prime},C_{t}),\qquad H_{t}^{C}=(P_{t},C_{t}^{\prime}). (4) The role editor changes role procedures while preserving coordination. The coordination editor changes at most one existing route or contract while preserving roles. Endpoint guidance belongs to the contract. An editor can retain the harness when evidence does not support change. The third editor in SciMARS + Memory. This setting invokes a separate memory-editor LLM call with its own scope and prompt. It can use the same underlying model as the other editors: H t P = ( P t ′ , C t , M t ) , H t C = ( P t , C t ′ , M t ) , H t M = ( P t , C t , M t ′ ) . H_{t}^{P}=(P_{t}^{\prime},C_{t},M_{t}),\quad H_{t}^{C}=(P_{t},C_{t}^{\prime},M_{t}),\quad H_{t}^{M}=(P_{t},C_{t},M_{t}^{\prime}). (5) The memory editor receives a summary of the available graph and revises recording duties, retrieval filters, query hints, retrieval limits, or subscriptions. It preserves roles and coordination. The validator requires a version increase for changed policies and bounds retrieval limits between zero and twelve. These edits change access to evidence, not the evidence itself. A validator checks each proposal’s schema, component ownership, permitted fields, versions, and required evidence citations. Adapter-specific checks can require an expected behavior and an executed public check. A rejected proposal falls back to the current harness, with the rejection retained in the trace. Validation establishes protocol compliance, not a gain in task performance. Let A = { P , C } A=\{P,C\} for SciMARS and A = { P , C , M } A=\{P,C,M\} for SciMARS + Memory. The controller probes every validated candidate under matched public inputs and limits: o t j = E ⁡ ( H t j , x , D ) , j ∈ A . o_{t}^{j}=E(H_{t}^{j};x,D),\qquad j\in A. (6) Probes use isolated workspaces or environment snapshots. Memory-enabled branches start from the same permitted seed and keep their writes separate. A public train–validation probe excludes held-out labels from the graph as well as from model inputs. Earlier live notes cannot enter such a probe if they encode those labels. Candidate probes provide evidence for comparison; stochastic executions do not establish a causal effect from one trial. 3.5.  Evidence-guided composition and execution reuse The composer receives reference and candidate evidence, proposals, and lessons. (10) There are up to four choices for SciMARS and five for SciMARS + Memory. Reused executions count once. The selector may retain an individual proposal instead of the composed successor. Unselected programs from earlier rounds are ineligible; earlier traces and lessons can still guide revisions. The current reference is a new execution of the previously selected harness. Section 4.2 identifies the historical archive-selection setting in the scientific-programming results. Selection uses public requirements and observed outcomes. Adapters expose either execution checks or public validation objectives. The scientific selector can inspect code, replay observations, and output summaries and request bounded checks; its multi-candidate protocol requires an executed structured check. A campaign adapter can instead compare objectives computed on a public validation panel. These mechanisms do not expose hidden targets or official scores to the optimizer. Invalid decisions, missing checks, and resource or tool failures trigger the adapter’s fallback. A fallback is not evidence that its candidate is best. Current-round selection cannot recover an ineligible earlier program. (11) For interactive campaigns, the accepted harness governs subsequent live turns; probe artifacts do not replace the team’s acquired data. Composition and retention are distinct decisions. A proposed edit counts as retained only when selection adopts its harness. 3.7.  Reflection, iteration, and resource control The reflector uses execution evidence and proposal, composition, and selection records. It returns a grounded lesson with a cue, procedure, cited events, and limitations, or no lesson: L t + 1 = Reflect ⁡ ( L t , T t , H t + 1 ) , T t + 1 = T t ∪ { events from round ​ t } . L_{t+1}=\operatorname{Reflect}(L_{t},T_{t},H_{t+1}),\qquad T_{t+1}=T_{t}\cup\{\text{events from round }t\}. (12) Lessons guide the outer editors; the shared graph carries evidence among execution roles. Neither mechanism changes the optimizer itself. A new evaluation task resets adaptation state. A fixed development seed does not transfer evaluation-task updates. The controller allocates the task allowance among rounds and stages. Execution, editors, probes, selection, reflection, rejected calls, and retries all consume that allowance. A prefix rule lets later stages use unused resources from earlier stages. A SciMARS round needs three team executions if it reuses the successor and four if it probes a new successor. SciMARS + Memory needs four or five, respectively. These counts exclude editor and reflection calls. The extra memory proposal consumes the same task allowance as other components. 4.  Experiments We introduce the benchmarks, baselines, and evaluation protocol, then compare the base team, fixed memory, integrated workflow search, SciMARS, and SciMARS + Memory across scientific discovery, scientific programming, and interactive tasks. 4.1.  Benchmarks We use Autonomous Science Bench, ScienceAgentBench, and AppWorld to provide comparisons with an unchanged multi-agent team and integrated workflow search. Autonomous Science Bench. We include the six campaigns listed in the benchmark paper ( Wen and Liu, 2026 ) : nuclease and biosensor engineering in biology, propylene and Suzuki reaction campaigns in chemistry, and oxygen-evolution and coercivity campaigns in materials science. Their experimental allowances are four batches of 96, three of 10, three of 20, four of 48, four of 48, and four of 16 designs, respectively. Success requires passing both discovery and held-out learning gates. ScienceAgentBench. The evaluated ScienceAgentBench ( Chen et al., 2025 ) snapshot contains 102 verified tasks. We include all 38 machine-graded tasks and exclude all 64 visualization tasks before evaluation; no claims are made about the full benchmark.
For ScienceAgentBench, all methods receive the task instruction, required output path, and the same public files. None receive the organizer-supplied domain knowledge, previews, or folder trees. AppWorld. AppWorld evaluates interactive programs through tests on simulated app state ( Trivedi et al., 2024 ) . We use package version 0.1.3.post1 and data version 0.1.0 .
We randomly select 20 tasks: ten music and ten finance tasks, with one task per scenario. A seeded hash order selects tasks within each category.
Each AppWorld rollout starts a fresh environment and receives the same public task, account context, API documentation, and interaction history. 4.2.  Baselines and system controls Base Multi-Agent. The base team uses the initial executor with planning, verification, routing, debugging, finalization, and clean replay. It uses no outer harness revision, composition, or cross-round archive selection. The model backend follows the cohort specification. Multi-Agent + Memory. The base team uses the shared task-local graph with a fixed memory policy and no outer harness revision (Section 3.3 ). Multi-Agent + Integrated Search. This baseline uses the released MASS workflow-search/RHI component ( Lee et al., 2026 ) , with reference/champion selection and two workflow-revision iterations. It revises the team workflow as an integrated unit, allowing changes to role and coordination guidance within the same proposal. SciMARS. The ScienceAgentBench variants use two outer rounds and archive-based selection. AppWorld uses two rounds and current-round selection. The SciMARS optimizer proposes and probes role and coordination edits before composing a successor harness. SciMARS + Memory. This variant runs three independent editors for roles, coordination, and memory policy (Section 3.4 ). It uses the same graph interface as fixed memory; graph contents grow in both settings, but only this variant edits how the team writes and retrieves records. Autonomous Science Bench reports separate GPT-6-Astra and GLM-5.3 cohorts. ScienceAgentBench and AppWorld use z-ai/glm-5.3-flashx , pinned to the Z.AI endpoint through OpenRouter with low reasoning effort and no provider fallback. Within each benchmark and model cohort, method–task runs share the same total model allowance, including execution, edits, probes, and selection. Autonomous Science Bench protocol. We evaluate five methods on six campaigns, with three runs per method and campaign (90 attempts per model cohort). The GLM-5.3-Flash comparison uses matched public task information, a 60-minute agent limit, the official measurement allowance, and equal API allowances. A worker and reviewer cover the logical roles in Section 3.2 . Repeated runs measure variation on fixed fixtures, not independent campaign samples. 4.3.  Main results We compare the five methods on Autonomous Science Bench, ScienceAgentBench, and AppWorld. The framework addresses two problems: evidence can remain isolated across agents, and fixed execution rules can repeat mistakes despite access to that evidence. A shared graph preserves observations, findings, and unresolved questions for use across roles. SciMARS adapts role procedures and coordination contracts through separate editors, candidate probes, composition, and selection. SciMARS + Memory adds a third editor for how agents record, retrieve, and receive shared evidence. This design separates retaining evidence from adapting how the team uses it within a task. Across the evaluated cohorts, SciMARS + Memory improves on the base multi-agent team. It resolves 12/18 GPT-6-Astra and 2/18 GLM-5.3 attempts on Autonomous Science Bench, compared with 8/18 and 1/18 for the base team. It solves 14/38 ScienceAgentBench tasks and 11/20 AppWorld tasks, compared with 11/38 and 5/20 for the base team. These results show that combining shared memory with SciMARS can improve multi-agent performance across scientific and interactive tasks. Limitations and future work. The discovery evaluation uses experimental-data replay and a digital twin, not new physical wet-lab execution. Computational cost limits our evaluation to the tested language models, DS-STAR-based multi-agent configurations, and subsets of the benchmarks. Future work should evaluate additional base language models and multi-agent systems, as well as more complete benchmark suites, to assess the generality of the framework. References Chen et al.
