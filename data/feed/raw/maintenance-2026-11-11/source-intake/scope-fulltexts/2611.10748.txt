Informatics, University of Oslo, Norway Affiliation: Simula Research Laboratory, Norway Affiliation: Department of Computer Science, Aalborg University, Denmark Abstract Agent harnesses—runtime scaffolds that wrap an LLM’s reasoning loop with tool dispatch, verification, and persistent memory—have become the standard substrate for deploying LLMs as autonomous agents, as demonstrated by Claude Code and Codex in software engineering. In trajectory planning, however, this paradigm has not taken hold: existing LLM-based trajectory planning methods either keep the LLM in the decision loop, exceeding the millisecond-level control budget, or offload it to offline rules or training-time supervision—leaving the runtime planner non-evolving. Intermediate hybrids still lack the verification-and-consolidation loop that makes harnesses reliable. We ask: what runtime harness would let an LLM planner meet real-time constraints while self-evolving into a deployable one? We propose REINS , a harness built on three LLM–planner couplings: LLM outputs are (i) grounded to a learned variable-level dynamics model, (ii) verified via calibrated predicates and forward rollout, and (iii) consolidated into an indexed rule memory that serves future scenes in 𝒪 ⁡ ( log ⁡ n ) \mathcal{O}(\log n) without re-invoking the LLM. The harness closes a self-evolution loop: familiar scenes resolve by memory lookup; novel scenes invoke the LLM, whose verified outputs enrich the memory. Without modifying LLM weights, REINS attains 98%+ compliance, nearly 50% collision reduction, and 1.9–4.6 ms latency on simulated and real-world benchmarks at the tactical decision layer, with LLM invocation rate monotonically declining as memory matures. The LLM utterance “keep a safe distance” is (1) grounded to physical state variables (TTC, THW, DHW), (2) verified by forward rollout over a multi-step horizon, and (3) consolidated as an indexed rule keyed by these variables for instant reuse. Trajectory planning is the safety-critical core of autonomous driving: each decision must respect traffic rules, anticipate other agents, and complete within a millisecond-level control budget (e.g., 50 ms at 20 Hz) ( Zhang et al., 2021a ; Falcone et al., 2007 ; Lenz et al., 2016 ; Li et al., 2024b ; Montgomery, 1983 ) . Recent work shows that large language models (LLMs) bring rich semantic priors over traffic norms, agent intent, and safety reasoning that classical planners lack ( Manas et al., 2025 ; Fu et al., 2024 ; Mao et al., 2024 ; Sha et al., 2023 ; Cai et al., 2024 ; Li et al., 2024a ) , yet integrating their reasoning into the runtime loop is bottlenecked: each LLM query takes seconds—orders of magnitude over the control budget—and naive integration leaves the planner either too slow to act or unable to adapt as deployment proceeds. This is precisely the kind of deployment problem—running a stochastic LLM inside a low-latency, safety-sensitive loop—that the agent harness paradigm has recently addressed in software engineering. An agent harness wraps the LLM with a thin runtime layer of tool dispatch, intermediate-result verification, persistent memory, and safety enforcement—as exemplified by systems like Claude Code, Codex, and Cursor-Agent. On Terminal-Bench ( Merrill et al., 2026 ) , harness design has emerged as a primary driver of ranking, with automatic harness optimization surpassing hand-engineered baselines ( Lee et al., 2026 ) . Trajectory planning, however, is a sharp test of the paradigm: its millisecond-level control budget is much tighter than the seconds-to-minutes scale at which coding harnesses operate, and the safety stakes are higher. In this regime, the harness’s generic functions specialize into three couplings between LLM and planner, illustrated in Figure 1 : when an LLM suggests “keep a safe distance” in a car-following scene, the runtime must (i) ground the suggestion to physical state variables (TTC, THW, DHW), (ii) verify the resulting maneuver via forward rollout over a multi-step horizon, and (iii) consolidate the verified maneuver into an indexed rule memory. Existing LLM-based trajectory planning methods span two extremes plus intermediate hybrids, none of which constitutes a harness in the above sense: runtime invocation methods keep the LLM in the decision loop but exceed the millisecond-level budget by orders of magnitude ( Fu et al., 2024 ; Mao et al., 2024 ; Sha et al., 2023 ) ; offline extraction methods discard the LLM at runtime and freeze the planner against scenarios the offline corpus did not anticipate ( Li et al., 2024a ; Tang et al., 2025 ) ; and hybrid designs partially orchestrate the LLM at runtime but stop short of a full harness, lacking explicit verification of LLM commitments and consolidation of verified ones into reusable structure ( Cui et al., 2026 ; Zhang et al., 2025 ) . Across all three, the LLM’s reasoning is either too slow to act on or too detached from the loop to evolve with deployment. This raises our central question: what runtime harness would let an LLM planner satisfy real-time constraints while self-evolving into a deployable one? Each of the three couplings is non-trivial under real-time control: grounding requires bridging natural-language commitments to the planner’s threshold semantics ( Wang et al., 2025 ; Zhai et al., 2025 ) ; verification must catch stochastic, occasionally unsafe LLM outputs before they reach control ( Manas et al., 2025 ; Zeng et al., 2025 ) ; and consolidation must escape per-call LLM latency ( Fu et al., 2024 ; Mao et al., 2024 ) via a memory pattern emerging in agentic AI ( Wang et al., 2023 ; Zhao et al., 2024 ; Ma et al., 2024 ) but not yet transferred to real-time planning. The three are also jointly necessary: without grounding, verification has nothing to check; without verification, consolidation stores unverified content; without consolidation, every scene re-pays the LLM latency cost. When all three are addressed, a self-evolution loop emerges: familiar scenes resolve from the consolidated memory in 𝒪 ⁡ ( log ⁡ n ) \mathcal{O}(\log n) time, novel scenes invoke the LLM, whose verified outputs enrich the memory, and reliance on the LLM decreases monotonically as memory matures, with no LLM weight update. We propose REINS , a concrete realization of this harness pattern, instantiated for trajectory planning in driving, that addresses each coupling as follows. Grounding. We learn a world dynamics model over a factored variable space, fusing LLM-derived semantic priors with data-driven dependency discovery. Group-weighted ridge regression selects each variable’s parents, and a per-variable Transformer predicts its evolution under the discovered graph. Every LLM output can then be projected onto this variable space and rolled out under the learned dynamics. Verification. We compile each LLM-proposed maneuver into calibrated predicates with thresholds derived from data (z-score, quantile, or absolute). Predicates are evaluated against the rollout produced by the dynamics model, and only commitments whose predicted trajectory satisfies all guards are released to control. Hallucinated or unsafe commitments are filtered before any maneuver is issued. Consolidation. We persist verified commitments in an indexed rule memory backed by a graph database, keyed by the grounding variables that triggered them. At runtime, parameterized graph queries retrieve scene-relevant rules in 𝒪 ⁡ ( log ⁡ n ) \mathcal{O}(\log n) time without any LLM call. Recurring scenes are thus served by memory lookup, and the LLM is invoked only on a miss. Together, the three close the self-evolution loop: at each scene the planner first consults the memory; on a miss the LLM is invoked, its output grounded against the dynamics model, verified by rollout, and—if it passes—committed to memory for the next encounter. We provide an empirical demonstration that, under such a harness, an LLM planner monotonically reduces its own LLM-call rate while preserving safety and compliance. Our contributions can be summarized as: • We extend the agent-harness paradigm to real-time trajectory planning, identifying three couplings —grounding, verification, consolidation—any such harness must enforce, and instantiate it for driving; only the variable schema and the action space are domain-specific (Appendix D.1 ). • We design REINS , a harness that instantiates the three couplings via a learned world dynamics model, calibrated predicates with rollout verification, and an indexed rule memory. • We provide the first empirical evidence of self-evolution in real-time LLM trajectory planning: LLM invocation rate decreases monotonically over deployment with no LLM weight update. • We evaluate REINS on simulated and real-world driving benchmarks at the tactical decision layer, achieving 98%+ compliance, nearly 50% collision reduction, and 1.9–4.6 ms planning latency—well within the real-time control budget. 2 Related Work LLM-Based Trajectory Planning. Recent LLM-based trajectory planners fall along three lines, each realizing some couplings while leaving others open. Runtime invocation methods keep the LLM in the decision loop. DiLu ( Fu et al., 2024 ) pairs LLM reasoning with an experience-replay memory; Agent-Driver ( Mao et al., 2024 ) treats the LLM as an orchestrator over perception and planning tools; LanguageMPC ( Sha et al., 2023 ) feeds chain-of-thought outputs into MPC. These systems gain semantic flexibility, but each LLM query takes seconds, and any output that reaches the planner is implicitly trusted, lacking the calibrated checks proposed for stochastic LLM outputs in safety-critical settings ( Manas et al., 2025 ; Zeng et al., 2025 ) . Offline extraction methods sit at the opposite end. LLaDA ( Li et al., 2024a ) extracts location-specific rules from driver handbooks, DriReg ( Cai et al., 2024 ) retrieves regulatory text via RAG, and Plan-R1 ( Tang et al., 2025 ) distills LLM-shaped rewards into a reinforcement-learning policy. Removing the LLM at runtime buys real-time inference, but the planner becomes static, unable to consolidate new commitments against learned driving dynamics ( Wang et al., 2025 ; Zhai et al., 2025 ) or to adapt to scenarios the offline corpus did not anticipate. Hybrid designs partially orchestrate the LLM at runtime. C-TRAIL ( Cui et al., 2026 ) runs a closed-loop Recall–Plan–Update cycle with trust-weighted MCTS injection; LeAD ( Zhang et al., 2025 ) pairs an end-to-end planner with a redundant LLM reasoning track. These improve over either extreme but lack explicit verification of LLM commitments and consolidation of verified ones into reusable structure; none grounds, verifies, and consolidates LLM outputs jointly under a real-time harness. Agent Harnesses for LLM Deployment. Outside trajectory planning, the deployment of LLMs into real-world tasks has converged on the agent harness pattern: a thin runtime layer that wraps the LLM with tool dispatch, intermediate-result verification, persistent memory, and safety enforcement. In autonomous coding, systems such as Claude Code and Codex turn general-purpose LLMs into reliable software engineers, and harness design has become a primary driver of ranking on Terminal-Bench ( Merrill et al., 2026 ; Lee et al., 2026 ) . In open-ended decision-making, Voyager ( Wang et al., 2023 ) accumulates a skill library of executable code through curiosity-driven exploration; Eureka ( Ma et al., 2024 ) iteratively refines reward functions by evolutionary search over LLM proposals; ExpeL ( Zhao et al., 2024 ) distills task-specific experience into a retrievable knowledge base. These harnesses share three structural elements with REINS—grounding into a domain primitive space, verification of LLM outputs, and persistent reuse of verified ones—but none operate under millisecond real-time budgets nor expose their LLMs to the safety-critical constraints. 3 Preliminaries We formalize the harness’s primitives: a factored variable space (Section 3.1 ); a world dynamics model for grounding (Section 3.2 ); an executable rule representation for verification and consolidation (Section 3.3 ); and the problem definition (Section 3.4 ). Appendices C and D report trajectory accuracy, sensitivity, extended self-evolution traces, a case study, the rule database, and the fairness and robustness studies. 5.1 Experiment Setting Datasets and Protocols. We evaluate REINS on four highway-env ( Leurent, 2018 ) scenarios—Highway, Merge, Roundabout, Intersection (100 steps at 5 Hz, 15 observable vehicles per episode)—and two drone-captured real-world datasets ( Krajewski et al., 2018 ; Krajewski et al., 2020 ) : highD (German highway, 4,237 vehicles, 578 lane changes) and rounD (German roundabouts, 2,156 vehicles, 423 yield/merge events). Surrounding vehicles in simulation are reactive (IDM car-following ( Treiber et al., 2000 ) with MOBIL lane changes ( Kesting et al., 2007 ) ), so they brake, yield, and change lanes in response to the ego. The real-world datasets run in closed-loop replay : one recorded vehicle is controlled by the planner while the others follow their recorded trajectories, so these rows reflect human behavior rather than a simulator’s; a collision is registered when bounding boxes overlap or the ego leaves the drivable lane. A reactive-replay variant following the nuPlan protocol ( Caesar et al., 2021 ) is in Appendix D.6 . All methods observe clean factored variables; perception, tracking, and map errors lie outside the evaluated layer (Section 6 ). Evaluation Metrics. Compl. (Rule Compliance) is the fraction of steps at which all active rules hold, measured for each method against its own executable rule set; an audit of all methods against REINS’s compiled set as a common reference leaves the ordering unchanged (Appendix D.2 ). RE (Risk-aware Efficiency) is task reward minus a TTC-based risk penalty. CR (Collision Rate) is the fraction of episodes with at least one contact among the 15 vehicles over 100 steps, an episode-level rate in deliberately stressed traffic. PE (Planning Efficiency) is the mean wall-clock ms of the synchronous action-selection computation per step for every method; for REINS it excludes the asynchronous rule-acquisition pipeline, profiled separately in Appendix D.8 . TTC and THW, which underlie the guards and the RE penalty, are the surrogate safety measures of traffic engineering ( Gettman and Head, 2003 ) , and Compl. and CR echo the rule-conformance and collision outcomes reported in scenario-based safety assessment ( Riedmaier et al., 2020 ) . Results are averaged over five seeds; formal definitions in Appendix B.2 . Baselines. We compare with eight baselines covering the regimes from Section 2 plus classical anchors:
(i) classical (MPC ( Falcone et al., 2007 ) , MCTS ( Lenz et al., 2016 ) );
(ii) runtime invocation (DriveSpeak ( Cui et al., 2024 ) );
(iii) offline extraction (LLaDA ( Li et al., 2024a ) , DriReg ( Cai et al., 2024 ) , Plan-R1 ( Tang et al., 2025 ) );
(iv) symbolic/hybrid (PDDL ( Guan et al., 2023 ; Liu et al., 2023 ) , SymAgent ( Liu et al., 2025 ) ).
All methods share the observation space, action space, episodes, and LLM backbone (GPT-4o, temperature 0); descriptions, the shared and unshared conditions, and a matched re-run of PDDL and DriReg over REINS’s vocabulary and calibration pipeline are in Appendices B.3 and D.2 . Effectiveness Analysis. (i) REINS beats all baselines, improving over Plan-R1 by 2.4%–3.6% Compl., 3.06–5.48 RE, and 49%–56% CR reduction—validating that grounding, verification, and consolidation act jointly. (ii) All methods incur higher CR on complex scenarios (Roundabout, Intersection) than structured ones (Highway, Merge); REINS degrades least, owing to context-aware retrieval. (iii) On highD and rounD, REINS maintains Compl. above 0.98 with 6.6–9.0-point CR reduction over Plan-R1, transferring to naturalistic driving without domain-specific tuning. (iv) Executable rule methods (PDDL, DriReg, SymAgent, Plan-R1) beat language-guided ones (DriveSpeak, LLaDA, with 22%–44% CR for ungrounded rules), yet their static thresholds and uniform activation still trail REINS’s data-driven calibration and variable-indexed retrieval; a matched re-run over REINS’s vocabulary and calibration narrows PDDL’s and DriReg’s CR by 3–5 points but leaves the gap intact (Appendix D.2 ). (v) Classical planners (MPC, MCTS) are fast but unsafe (CR 14%–28%); Plan-R1 is the best baseline but plateaus under uniform rule application. Efficiency Analysis. REINS completes planning in 1.9–4.6 ms per step, up to 58% faster than runtime LLM baselines (DriveSpeak, LLaDA) and 15–33% faster than Plan-R1. Two factors contribute: (i) variable-indexed retrieval activates only 2–3 rules per step via O ⁡ ( log ⁡ | ℛ | ) O(\log|\mathcal{R}|) queries, and (ii) learned dynamics enable closed-form rollout without iterative LLM calls. PDDL makes no runtime LLM call either, yet re-grounds every precondition at each step (3.71 of its 4.95 ms on Highway; Appendix D.3 ), exactly the cost that indexed consolidation removes. The evaluation sits at the tactical decision layer: perception is assumed as clean factored variables, highD and rounD run in replay (reactive-replay variant in Appendix D.6 ), and occlusion, tracking, and map errors are absent; the five meta-actions are the standard interface of this layer and of all eight baselines, and continuous maneuvers would change only the scorer’s output head. The claims are harness results at this layer, not a deployable AV stack, and the episode-level collision rates of 5.7–9.5% in deliberately stressed traffic are not deployment grade; the supported claim is relative (49–56% below the best learned baseline). Correlational dynamics. The learned dynamics are prior-constrained but not causally identified; verification is conservative, so misattribution degrades toward rejecting actions rather than accepting unsafe ones, yet its quality depends on dynamics fidelity (constant-velocity propagation raises CR by 48–49%; 3 of the 57 acquired rules were over-specific in audit, Appendix D.5 ). Limited zero-shot cross-domain reusability. Zero-shot cross-domain reusability of the compiled memory is limited: a memory compiled solely from highD/rounD begins at an 86.2% call rate on highway-env, indicating that many target-domain encounters still require online acquisition. REINS is accordingly scoped to the self-evolution loop rather than assuming universal cross-domain memory transfer (Appendix D.7 ). Scope. The monotone miss-rate property assumes a stationary scene distribution, and the implementation is specialized to driving: only the variable schema and the action space must be re-authored for another domain (Appendix D.1 ). 7 Conclusion We present REINS, a self-evolving agent harness that adapts the agent-harness paradigm from software engineering to real-time, safety-critical trajectory planning through three LLM–planner couplings: grounding, verification, and consolidation. Familiar scenes resolve from an indexed rule memory in 𝒪 ⁡ ( log ⁡ | ℛ | ) \mathcal{O}(\log|\mathcal{R}|) time, while memory misses trigger LLM-driven rule acquisition that grounds, verifies, and writes back new rules, closing the self-evolution loop without any LLM weight update. At the tactical decision layer, REINS attains 98%+ compliance, nearly 50% collision reduction, and 1.9–4.6 ms latency, with gains that survive matched baselines, observation noise, reactive replay, and cross-domain memory transfer. Future work will couple the harness to perception uncertainty and continuous maneuvers, extend it to multi-agent coordination, and move the learned dynamics toward interventional identification with incremental updates. Appendix A More Details about REINS A.1 Variable Definitions We define macro and micro variables shown in Table 4 . The macro variables represent high-level semantic categories, while micro variables are the specific measurable quantities used in the world dynamics model and rule system. The variables are organized into five functional groups: Environment variables capture external conditions (weather, visibility, road surface, speed limits) that affect driving but are not directly controllable. Traffic variables describe spatial and temporal relationships with surrounding vehicles, including headway distances, relative speeds, TTC, and lane density metrics. Ego variables represent the controlled vehicle’s kinematic state (position, velocity, acceleration, orientation). Action defines the discrete action space: five high-level maneuvers executed by low-level controllers. Outcome variables measure action consequences, including safety (collision risk), comfort (jerk-based), and task completion indicators.

A.2 Rule Templates Seven rule templates are defined to capture different logical structures for driving knowledge: • IF-THEN : Conditional implication for basic conditional relations. Example: IF TTC < < 2s THEN decelerate • AND-THEN : Conjunctive trigger requiring multiple conditions. Example: IF visibility < < 50m AND raining THEN reduce_speed_by_30% • THRESHOLD : Numeric constraint with calibrated boundaries. Example: IF speed > > speed_limit THEN violation = true • PRIORITY : Decision hierarchy for conflicting actions. Example: yield ≻ \succ accelerate (yield takes priority) • MULTI-ACTION : Compound actions under one condition. Example: IF collision_risk = high THEN brake AND steer_away • WEIGHTED-ACTION : Weighted action selection. Example: IF crash_risk THEN { brake: 0.7, steer: 0.3 } • TEMPORAL-CHAIN : Temporal constraints between triggers. Example: IF obstacle_detected THEN brake within 1.5s A.3 Rule Conflict Resolution When multiple rules are activated simultaneously, conflicts may arise if they recommend different actions. REINS resolves conflicts through a three-level arbitration mechanism: Priority-based ordering. Rules are assigned priority levels based on their functional category: Safety > > Compliance > > Navigation > > Efficiency. When rules from different categories conflict, the higher-priority rule takes precedence. For example, if an Efficiency rule (consider lane change) and a Safety rule (maintain gap) both fire, the Safety rule overrides. Confidence-weighted aggregation. For rules within the same priority level, REINS aggregates their scores using the noisy-OR formula (Eq. ( 5 )). This allows multiple supporting rules to reinforce an action while remaining robust to individual noisy predictions. The action with the highest aggregated probability is selected. Dynamics-based verification. When the aggregated action prior is below a confidence threshold ( τ = 0.7 \tau=0.7 ), REINS falls back to dynamics-based verification. The top- M M candidate actions are simulated via forward rollout using the world dynamics model, and the action yielding the safest predicted trajectory is selected. This hierarchical approach ensures that safety-critical rules are never overridden by efficiency considerations, while still allowing flexible action selection in non-critical situations. Under stationarity of the scene distribution, the per-state miss rate is non-increasing as ℛ \mathcal{R} accumulates coverage, since any state s s that triggered a miss and produced an accepted r ~ \tilde{r} is now matched by a rule keyed on the variables active at s s . We validate this behavior empirically in Section 5.4 and Appendix C.5 . A.5 Prompts We provide three prompt templates used in REINS’s offline compilation pipeline. B.3 Baseline Descriptions We select baselines from three categories to comprehensively evaluate REINS: (i) classical planners (MPC, MCTS) that represent traditional optimization and search-based approaches without rule guidance; (ii) LLM-based planners (DriveSpeak, PDDL, LLaDA, DriReg) that leverage language models for driving decisions but differ in how they integrate linguistic knowledge; and (iii) hybrid methods (SymAgent, Plan-R1) that combine learning with symbolic reasoning. This selection covers the spectrum from rule-free to rule-guided planning, enabling analysis of how different rule representation and retrieval strategies affect safety and efficiency. • MPC [ Falcone et al., 2007 ] : Classical optimization-based planner solving finite-horizon control under kinematic and safety constraints. We use a 5-step horizon with quadratic cost on acceleration and jerk. • MCTS [ Lenz et al., 2016 ] : Sampling-based planning via tree search and rollout evaluation. We use 1000 simulations per decision with UCB exploration. • DriveSpeak [ Cui et al., 2024 ] : LLM-based method mapping natural-language scene descriptions directly to driving actions. Uses GPT-4o with scene prompts at each timestep. • PDDL [ Guan et al., 2023 , Liu et al., 2023 ] : the LLM writes the domain’s symbolic preconditions and effects once offline; at runtime a classical STRIPS solver (Pyperplan [ Alkhazraji et al., 2020 ] ) is invoked in process at each decision step with no LLM call. Its runtime profile is in Appendix D.3 . • LLaDA [ Li et al., 2024a ] : LLM interpretation of region-specific traffic rules from driver handbooks. Uses pre-extracted rule sets with LLM-based rule matching. • DriReg [ Cai et al., 2024 ] : RAG-based traffic regulation retrieval with LLM reasoning for action legality. Retrieves top-5 regulations per query using embedding similarity. • SymAgent [ Liu et al., 2025 ] : Neural-symbolic agent integrating LLMs with structured knowledge graphs. Uses the same Neo4j backend as REINS for fair comparison. • Plan-R1 [ Tang et al., 2025 ] : Two-stage learning-based planner with rule-shaped rewards and reinforcement learning. Trained on the same 50k episodes as REINS’s world model. All baselines use identical observation spaces, action spaces, episodes, and evaluation protocols. For LLM-based methods, we use GPT-4o (2024-08-06) with temperature 0 for deterministic outputs. Hyperparameters for each baseline follow their original papers or are tuned on a held-out validation set. The conditions that are shared with REINS and those that each rule-based baseline keeps by design, together with a matched re-run and a common-reference compliance audit, are documented in Appendix D.2 . C.1 Training Convergence We train the world dynamics model for 300 epochs using the Adam optimizer with a learning rate of 2 × 10 − 4 2\times 10^{-4} and batch size 64. Each variable-specific dynamics function f i f_{i} is implemented as a two-layer Transformer with four attention heads. Training is conducted on 50k episodes collected from four scenarios (Highway, Intersection, Merge, and Roundabout) using NVIDIA A100 GPUs. The model learns 20 variable-specific dynamics functions, including ego-state variables ( ego_speed , ego_acceleration , ego_vx , ego_vy , ego_x , ego_y , yaw_rate , jerk , lane_id ), traffic-related variables ( lead_ttc , lead_thw , lead_rel_speed , rear_rel_speed , lane_density_left , lane_density_right , cutin_risk ), and outcome variables ( risk_score , comfort_score , violation_flag , energy_consumption ). Figure 7 shows the training loss curves for all dynamics functions across the four scenarios. The results suggest that the learned world dynamics are scenario-adaptive not only in difficulty but also in structural composition: different scenarios activate and learn different subsets of variable-specific dynamics functions. Interaction-heavy variables such as cutin_risk , lane_density_left/right , and rear_rel_speed are prominent in Merge and Intersection, where lane changes and merging behaviors are frequent, but are weakly activated or effectively absent in Highway, where traffic flow is comparatively stable. Conversely, lateral-motion variables (e.g., ego_vy , yaw_rate ) become substantially more relevant in Roundabout due to persistent curvature, while contributing marginally in straight-road scenarios. This indicates that the model does not impose a fixed global mechanism set across environments, but instead learns scenario-specific mechanism structures, supporting structural adaptability to heterogeneous traffic contexts. Beyond these structural differences, the loss curves exhibit consistent convergence patterns. Most variables converge within 100–150 epochs. Simple kinematic variables (e.g., ego_x , ego_y , lead_thw ) converge within 50 epochs, whereas interaction-intensive outcome variables (e.g., risk_score , violation_flag ) require longer training. Highway achieves the lowest final loss due to simpler lane-following dynamics. Roundabout exhibits higher loss for lateral variables because of curved trajectories, while Intersection shows higher variance in violation_flag due to diverse right-of-way interactions. Safety-related variables (e.g., lead_ttc , cutin_risk ) converge rapidly in early training when relevant interactions are present, indicating strong dependency signals. In terms of final loss magnitude, continuous variables (e.g., ego_speed , ego_acceleration ) achieve losses below 0.5, whereas discrete or binary variables (e.g., violation_flag , lane_id ) stabilize at higher loss due to their classification nature. C.2 Trajectory Accuracy We evaluate trajectory accuracy using Average Displacement Error (ADE), Final Displacement Error (FDE), and cumulative episode reward (Reward) across four driving scenarios: Highway, Merge, Roundabout, and Intersection. ADE and FDE measure the mean and final Euclidean distance between predicted and executed trajectories, respectively, while Reward reflects overall driving efficiency and safety. All methods are evaluated under identical environment settings with the same observation space, action space, and rollout horizon. Table 6 reports the mean performance over all evaluation episodes. REINS consistently achieves the best performance across all scenarios in terms of both trajectory accuracy and cumulative reward. In Highway, REINS reduces ADE and FDE to 15.9 and 20.5, respectively, outperforming the strongest baseline (SymAgent) by 12.2% in ADE and 16.3% in FDE, while also achieving the highest reward. Similar improvements are observed in Merge and Roundabout, where REINS yields substantial gains in both short-horizon and long-horizon prediction accuracy, indicating more stable multi-step trajectory generation. The performance gap becomes more pronounced in complex interaction scenarios. Across all scenarios, higher trajectory accuracy strongly correlates with higher episode reward, confirming that more accurate future state prediction leads to safer and more efficient planning. Methods relying primarily on language-based reasoning (LLaDA) exhibit the largest errors, especially in high-speed or curved-road settings, highlighting the limitations of planning without explicit dynamics modeling. MPC improves performance by incorporating learned motion predictors, while SymAgent further benefits from symbolic constraints. REINS combines symbolic rule guidance with learned world dynamics, enabling both structured action filtering and predictive verification, which explains its consistent superiority across heterogeneous traffic scenarios. C.4 Sensitivity to Temporal Lag Length The temporal lag length L L determines how many historical timesteps the world dynamics model uses when predicting future states. Table 7 reports results on both simulated and real-world scenarios. When using small lag lengths ( L ≤ 2 L\leq 2 ), the model fails to capture cumulative temporal patterns such as sustained tailgating or gradual lane drift, leading to substantially higher collision rates. On the simulated Highway scenario, the collision rate increases from 5.67% at L = 6 L=6 to 9.34%, corresponding to a 65% relative increase. A similar degradation is observed on the real-world highD dataset, where the collision rate rises from 6.12% to 10.12%. These results indicate that short-term observations are insufficient to infer latent interaction states, such as risk accumulation and driver intent, which are critical for safe planning. In contrast, large lag lengths ( L ≥ 10 L\geq 10 ) introduce excessive historical noise and dilute recent dependency signals, reducing the effective signal-to-noise ratio for short-horizon prediction. Consequently, collision rates increase by approximately 40% on simulated scenarios compared to the optimal setting. This suggests that overly long histories may impair the model’s ability to focus on immediately relevant dynamics, particularly in rapidly evolving traffic situations. Overall, L = 6 L=6 achieves the best and most consistent performance across both simulated and real-world domains, corresponding to approximately 1.2 seconds of historical context at a sampling rate of 5 Hz. This time window appears sufficient to capture short-term interaction dynamics while avoiding the accumulation of outdated or irrelevant information, thereby supporting stable multi-step rollout and reliable safety verification in downstream planning. C.7.1 Rule Database Statistics Table 8 shows the distribution of variables by macro-group and rules by template type in REINS’s Neo4j graph database. The post-deployment database contains 1,023 rules covering six driving scenarios (four simulated: Highway, Merge, Roundabout, Intersection; two real-world: highD, rounD). IF-THEN and AND-THEN templates dominate due to the prevalence of conditional and multi-condition reasoning in driving. Intersection scenarios contain the most rules due to complex right-of-way interactions, while Highway scenarios require fewer given simpler lane-following dynamics. This scale is comparable to industrial rule-based systems while remaining tractable for O ⁡ ( log ⁡ n ) O(\log n) graph database retrieval ( < < 1 ms per query). Figure 8 visualizes the graph structure of 200 randomly sampled rules from the database. Gray nodes are variables, blue nodes are rules, and pink nodes are the five discrete actions. Edge colors match source node colors: gray edges represent Variable → \to Rule, while blue edges represent Rule → \to Action. Several structural patterns emerge from this visualization:
(1) Variable sharing : A small set of variables (e.g., TTC, THW, speed) triggers a large number of rules, indicating that safety-critical variables serve as common preconditions across diverse driving scenarios.
(2) Action concentration : The majority of rules converge to SLOWER and IDLE , which exhibit the highest in-degree among all five actions. This reflects the safety-first design principle where conservative actions are recommended under uncertain or risky conditions. In contrast, LANE_LEFT , LANE_RIGHT , and FASTER receive fewer rule connections, as these actions require more stringent preconditions.
(3) Rule diversity : Despite action concentration, rules maintain diverse trigger conditions from different variables, enabling fine-grained context-aware activation rather than uniform rule application.
These patterns support REINS’s retrieval strategy: variable-indexed queries efficiently activate relevant rule subsets, while action aggregation via noisy-OR naturally prioritizes safety-critical recommendations. C.7.2 Representative Rules Table 11 lists 15 representative rules from REINS’s compiled rule database. The full post-deployment Neo4j database contains 1,023 rules across six driving scenarios, from which context-relevant subsets are retrieved at runtime via parameterized Cypher queries. These rules are automatically compiled from LLM-generated linguistic descriptions and calibrated using the threshold calibration mechanism described in Section 4.1.2 . For fair comparison, Plan-R1 applies the same 15 representative rules uniformly at each step, while REINS selectively activates 2–3 context-relevant rules via the retrieval mechanism. The 15 rules cover six of the seven template types defined in Definition 3.5 : (1) THRESHOLD rules (R01, R02, R06) enforce numeric boundaries on physical variables such as TTC and speed; (2) IF-THEN rules (R03, R07) implement basic conditional logic with disjunctive guards; (3) AND-THEN rules (R04, R05, R11–R15) require multiple conditions to be satisfied simultaneously; (4) PRIORITY rules (R09) establish decision hierarchies for right-of-way scenarios; (5) MULTI-ACTION rules (R10) trigger compound actions under critical conditions; (6) TEMPORAL-CHAIN rules (R08) encode time-sensitive constraints for upcoming events.
The complete definitions of all seven rule template types are provided in Appendix A.2 , and the conflict resolution mechanism is described in Appendix A.3 . D.3 Runtime Profile of the PDDL Baseline The PDDL baseline follows the pipeline in which the LLM writes the domain’s preconditions and effects offline and a classical solver executes at runtime [ Guan et al., 2023 , Liu et al., 2023 ] . The solver is Pyperplan [ Alkhazraji et al., 2020 ] , a Python STRIPS planner invoked in process at each decision step; there is no per-step LLM call. Its 4.95 ms per step on Highway (Table 1 ) decomposes into grounding 3.71 ms, search 0.94 ms, and plan extraction 0.30 ms. The solver re-instantiates every precondition against the current state at every step with no indexing, so grounding takes roughly three quarters of the budget. REINS avoids exactly this cost: variable-indexed retrieval touches 2–3 rules in under 1 ms, followed by a fixed-size rollout at H = 5 H{=}5 . This is the architectural payoff of consolidation with indexing. D.4 Robustness to the LLM Backbone and to Prompt Variation The LLM produces the dependency priors, the rule structures, and the Cypher queries, so we regenerate the whole offline pipeline with two further backbones and with three paraphrases of the dependency and rule-extraction prompts (Table 16 ). Rule structure varies mildly across backbones and paraphrases, while the calibrated thresholds and the final behavior barely move. The LLM picks variables, templates, and actions; calibration re-anchors every numeric threshold to data, so backbone differences wash out at the threshold level. Malformed or unsafe proposals never reach memory, because rollout verification rejects them regardless of which backbone or prompt produced them. D.5 What Rollout Verification Filters On the 1000-episode Highway deployment of Section 5.4 , applying the windowed call rates of Table 3 to the 100,000 deployment steps yields roughly 39,000 logged proposals (an arithmetic consequence of the call rates, not an independent count). Of these, 2.1% failed schema validation, 18.0% were rejected by rollout verification, and 79.9% were accepted. Acceptances overwhelmingly hash-collide with rules already in memory (Eq. 8 ) and only update confidences; they deduplicate to the 57 unique rules that grow the memory from 88 to 145. A manual audit of the 57 unique rules judged 54 consistent with domain guidelines; the three flagged rules were over-specific and never activated again. Episodes in which at least one acquired rule fired show no elevated collision rate against episodes in which none fired (5.4% against 5.8%). Three properties of the design bound what a plausible but incorrect proposal can do. Verification errs toward rejection: a rule is accepted only if every calibrated predicate holds along the predicted horizon (Eq. 7 ), so dynamics error costs availability rather than safety in the common case. Accepted rules never bypass the runtime loop: every executed action is re-verified by rollout at decision time (Section 4.2.1 ), so a wrongly accepted rule must also survive the per-step check before it can affect control. Finally, the residual dependence on dynamics fidelity is stated in Section 6 . D.6 Reactive Replay and Observation Noise Reactive replay. In the four simulated scenarios the surrounding vehicles already react to the ego through IDM car-following with MOBIL lane changes. D.9 Retrieval and Aggregation at Deployment Scale As memory grows, retrieval and multi-rule aggregation must stay within the control window. The stress test runs on Highway and varies only the database size, inflating it with synthetic rules generated as variable and threshold perturbations of compiled rules that preserve the schema and the trigger-degree distribution (Table 20 ). On the online planning path, the database-size-dependent cost therefore concentrates in retrieval; index maintenance and write costs sit on the acquisition path, off the control loop.
