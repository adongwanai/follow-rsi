I.1 Case study for overfitting License: arXiv.org perpetual non-exclusive license arXiv:2611.10787v1 [stat.ML] 07 Nov 2026 Trustworthy Recursive Self-Improvement with Statistical Guarantees Zihe Gao Zhengling Qi Yifan Cui Zhejiang University George Washington University Abstract Recursive self-improvement offers a promising path toward AI agents that improve through experience by refining their own harnesses without retraining their underlying large language models (LLMs). Making this self-improvement process reliable, however, requires more than generating new updates: agents must decide which changes are worth keeping. A greedy gate that accepts updates based solely on higher validation scores can mistake an observed gain for genuine progress and lead to performance degeneration, whereas overly conservative statistical gates may reject beneficial updates and hinder performance improvement. We introduce Trustworthy Recursive Updates with Statistical Testing (TRUST), a framework that adapts an online multiple hypothesis testing procedure to control the rate of false evolution across rounds, with an LLM analyzing historical context to help determine how much evidence is required to update the incumbent. Under interpretable assumptions, we prove that TRUST limits the proportion of accepted updates that result in unacceptable performance loss. We further derive a lower bound on the final performance gain. Across the benchmarks HotpotQA, DROP, and APPS with the models DeepSeek-V4-Flash and Qwen-3.8-Flash, TRUST reduces the average ratio of accepted inferior updates from the greedy gate’s 45.59% to 2.78%, while achieving higher final scores than the state-of-the-art statistical gate baselines for recursive self-improvement. These findings demonstrate that TRUST strikes a balance between statistical reliability and performance gain in recursive self-improvement. 1 Introduction Recursive self-improvement (RSI) has attracted growing interest for its potential to enhance agents’ capabilities without retraining their underlying language models ( Ren et al., 2026 ; Chen et al., 2026 ) . In a self-improvement loop, agents modify their own prompts, memory, tools, and workflows to improve task performance ( Madaan et al., 2023 ; Shinn et al., 2023 ; Wang et al., 2024 ) . This loop can be organized into three components: a solver that executes tasks, a proposer that generates candidate updates, and a gate that decides whether to accept them ( Wang et al., 2026 ; Ren et al., 2026 ) . Figure 1: Gain trajectories of TRUST and Greedy on HotpotQA with DeepSeek-V4-Flash. Details are in Section 6.1 . Figure 2: Recursive self-improvement with our trustworthy gate TRUST. TRUST combines noninferiority, overlap correction, e-value testing and error budget allocation with FER control across rounds. Existing work has explored mechanisms for generating better candidate updates, while less attention has been paid to deciding when to accept them. A common acceptance approach is to use a greedy gate, which accepts a candidate whenever its score on a fixed validation set exceeds the incumbent’s ( Shawn, 2026 ) . Figure 1 illustrates how early gain under greedy acceptance can be lost in subsequent rounds. Noise from finite samples and overfitting from reusing validation data can both make inferior updates appear beneficial and pass a greedy gate ( Dwork et al., 2015 ; Rogers et al., 2016 ) . Accepting a harmful update can reduce the agent’s current performance. The resulting loss may persist through subsequent rounds, ultimately limiting the gain for self-improvement. Recent work has begun to focus on the acceptance gate ( Wu et al., 2025 ; Shawn, 2026 ; Sengupta, 2026 ) . RSEA uses an extra validation set separate from the proposal generation set to select candidate updates ( Nguyen et al., 2026 ) . PACE provides a safety guarantee for each candidate update through an e-process test in a single round instead of the entire recursive self-improvement process ( Shawn, 2026 ) . However, controlling the probability of any false acceptance across rounds can make statistical gates conservative and hinder beneficial updates ( Wu et al., 2025 ; Sengupta, 2026 ) . A key challenge, therefore, remains: retaining opportunities for useful improvement while controlling acceptance errors across rounds under limited validation resources. We introduce Trustworthy Recursive Updates with Statistical Testing (TRUST), a general statistical acceptance framework. Motivated by false discovery rate (FDR) control ( Benjamini and Hochberg, 1995 ; Xu and Ramdas, 2024 ; Zhang et al., 2025b ) , we define the false evolution rate (FER) as a safety criterion for recursive self-improvement. FER measures the expected proportion of accepted updates that cause an unacceptable performance loss, thereby quantifying the gate’s false acceptance risk. To control FER, we formulate the sequential acceptance decisions as an online multiple testing problem. We also use an LLM to analyze historical context and help the error budget allocator assign less restrictive testing levels to promising candidates. We further draw on noninferiority testing to improve statistical power by allowing a possible loss tolerance ( Blackwelder, 1982 ; Da Silva et al., 2009 ; Schumi and Wittes, 2011 ) , and use overlap correction to account for bias from reusing validation samples across rounds ( Dwork et al., 2015 ; Rogers et al., 2016 ) . Figure 2 summarizes how TRUST makes recursive self-improvement trustworthy. Our contributions. We make the following three main contributions: (a) Our framework builds on online multiple hypothesis testing with interpretable parameters, including the error budget, loss tolerance, and overlap correction strength. It naturally incorporates LLM guidance based on diverse forms of historical context. (b) We establish statistical guarantees under explicit assumptions, including FER control, power consistency for improving candidates, and a lower bound on deployment gain. These results connect hypothesis testing criteria to performance gain in recursive self-improvement. (c) We evaluate TRUST in a closed-loop self-improvement harness across HotpotQA, DROP, and APPS with DeepSeek-V4-Flash and Qwen-3.8-Flash. Averaged across these settings, TRUST achieves the highest final gain of 24.84 pp. Compared with the greedy gate, TRUST reduces the mean FER 0 from 45.59% to 2.78% and the mean maximum drawdown from 4.963 pp to 0.047 pp, demonstrating high performance gains with few erroneous acceptances and small drawdowns. 2 Related Work Recursive self-improvement and agent harness. An agent harness includes tools, context management, and execution control ( Shi et al., 2026 ) . Recursive self-improvement agents use feedback to improve various harness components. Promptbreeder evolves task prompts ( Fernando et al., 2024 ) . Reflexion, ExpeL, and Voyager convert experience into reflections, insights, and reusable skills, respectively ( Shinn et al., 2023 ; Zhao et al., 2024 ; Wang et al., 2024 ) . CoEvo-Mem improves memory retrieval ( Ye et al., 2026 ) . AFlow and Flow refine agentic workflows ( Zhang et al., 2025a ; Niu et al., 2025 ) . AgentSquare defines a modular design space with planning, reasoning, tool use, and memory components ( Shang et al., 2025 ) . These works focus on proposing effective candidates, while we study whether a new candidate should be accepted to make recursive self-improvement trustworthy. Additionally, we design a harness with diverse editable components in our experiments to evaluate how different gates affect performance and risk. Hypothesis testing methods. Multiple hypothesis testing procedures are primarily based on two error criteria: the familywise error rate (FWER) and the FDR ( Benjamini and Hochberg, 1995 ; Wang and Ramdas, 2022 ; Robertson et al., 2023 ) . FWER control is generally more conservative than FDR control. Many popular online FDR methods with p-values rely on independence across tests ( Ramdas et al., 2018 ; Robertson et al., 2023 ) . This independence can be difficult to satisfy when agents evolve based on past feedback. The e-value is an alternative test statistic with a betting interpretation ( Shafer, 2021 ) . The e-BH and e-LOND procedures allow arbitrary dependence among valid e-values while controlling FDR ( Wang and Ramdas, 2022 ; Xu and Ramdas, 2024 ) . Drawing on e-GAI ( Zhang et al., 2025b ) and contextual online testing ( Chen and Kasiviswanathan, 2020 ) , TRUST constructs an e-value and allocates the testing levels with context. In RSI, SGM uses statistical tests to decide updates to control FWER across rounds ( Wu et al., 2025 ) , while PACE uses an e-process to control the probability of false acceptance in a single round ( Shawn, 2026 ) . TRUST provides FER control across rounds and achieves higher final scores than these statistical baselines in our experiments. 3 Problem Formulation Let 𝒟 \mathcal{D} denote the distribution of tasks and let u ⁡ ( x , s ) ∈ [ 0 , 1 ] u(x,s)\in[0,1] denote the score of output s s on task x x . Assumption 1 . For any t = 1 , … , T t=1,\ldots,T and i = 1 , … , n i=1,\ldots,n , suppose 𝔼 [ Y t , i ∣ ℋ t , i − 1 , Q t , i = 1 ] ≤ p ε + β , if H t 0 is true and ζ t , i > 0 . \mathbb{E}[Y_{t,i}\mid\mathcal{H}_{t,i-1},Q_{t,i}=1]\leq p_{\varepsilon}+\beta,\quad\text{if }H_{t}^{0}\text{ is true and }\zeta_{t,i}>0. We provide a detailed case study in Appendix H.2 showing how the LLM analyzes context and assigns different LLM multipliers to influence acceptance decisions. 7 Conclusion and Limitations TRUST applies online multiple hypothesis testing to control FER across rounds in self-improving agents, with LLM guidance and interpretable parameters for adjusting gate behavior. Our theoretical analysis and experiments show that the framework helps balance useful improvement and acceptance error control under limited validation resources. It extends existing statistical methods and provides a flexible statistical foundation for future work on recursive self-improvement. We discuss this point further in Appendix A.2 . Overall, we show that TRUST strikes a balance between statistical reliability and performance gains in recursive self-improvement. The present study does not address how to identify an exact value of overlap correction strength from data or how to optimally tune other parameters. The noninferiority margin provides an interpretable tolerance for loss, but the theoretical guarantee can be conservative and only partly explains practical behavior. The LLM allocator can occasionally make mistakes when judging candidate updates, which may lead to poor choices of LLM multipliers. Optimizing the gate to maximize gain while keeping safety metrics within target ranges is also a promising direction. Appendix Appendix A Supplementary Discussion A.1 Interpretation of the overlap correction We do not develop a complete model of validation data reuse in this work. Detailed studies of adaptive data analysis can be found in prior work ( Dwork et al., 2015 ; Rogers et al., 2016 ; Russo and Zou, 2016 ; Xu and Raginsky, 2017 ) . Instead, we state sufficient conditions for valid e-values and focus on a framework for FER control across RSI rounds. The interpretation of β \beta is related to how historical validation information, including feedback summarized in C t C_{t} , is used in candidate construction and selection. Greater reliance on information from previously evaluated samples may increase optimism when those samples are reused. For example, later rounds may use a few failed cases from the previous round or summaries of common error types. These forms of feedback reveal different information about the validation data and may lead to different degrees of optimism bias in subsequent evaluation. The parameter β \beta specifies an allowance for this optimism under the null hypothesis. A stronger correction requires stronger validation results to reach the acceptance threshold, making the gate more conservative and potentially limiting both false acceptances and the acceptance of useful updates. Our sensitivity results in Section 6.2 and Appendix H support the practical value of an appropriate correction strength. In the reported ablation, an appropriate β \beta achieves a higher mean final gain than no correction, whereas larger values make the gate overly conservative and reduce final gains. A.2 Relation to Existing Statistical Methods TRUST adapts FDR control in multiple hypothesis testing to the acceptance of candidates in self-evolving agents. It provides a framework covering the validation protocol, correction for data reuse, noninferiority testing, construction of test statistics, and allocation of testing levels. Within this framework, an LLM analyzes the candidate and historical context to guide allocation, while statistical guarantees hold under the stated assumptions. Existing statistical studies ( Zhang et al., 2025b ; Chen and Kasiviswanathan, 2020 ) compare testing procedures on specified hypotheses and observation streams in their numerical experiments. In our RSI setting, the proposer constructs candidates using historical information. Different gates can produce different acceptance decisions and incumbents, leading to different histories and subsequent candidates. Our experiments follow this closed loop and use update operators motivated by prior work on RSI agents. This allows us to compare how different gates affect both acceptance decisions and subsequent search on real tasks. Our theoretical analysis follows the same adaptive process and connects a lower bound on final gain to the testing levels and other parameters of the gate. It thus provides a statistical foundation for analyzing both acceptance risk and improvement along the trajectory induced
by the gate. ∎ Appendix F Harness Design with Four Components and Operators This appendix describes the operators used in our experiments. Operator names remain fixed across benchmarks. The specific details of the operators are adapted to suit different benchmarks. F.1 State representation Inspired by modular agent design and automated agent search in AgentSquare and ADAS ( Shang et al., 2025 ; Hu et al., 2025 ) , we organize the mutable agent state into four editable components: reasoning, routing, memory, and workflow. The four-component representation and the specific operator definitions below are implementation choices of our harness. The mutable harness state is 𝖧 = ( 𝖱 , 𝖯 , 𝖬 , 𝖶 ) , \mathsf{H}=(\mathsf{R},\mathsf{P},\mathsf{M},\mathsf{W}), where 𝖱 \mathsf{R} is the reasoning strategy, 𝖯 \mathsf{P} is the context router/provider, 𝖬 \mathsf{M} is episodic memory, and 𝖶 \mathsf{W} is workflow. These components determine the instructions and context for a single solver call. A proposed transition has the structured form o t = ( κ t , operator , target , parameters ) , o_{t}=(\kappa_{t},\texttt{operator},\texttt{target},\texttt{parameters}), where κ t ∈ { 𝖱 , 𝖯 , 𝖬 , 𝖶 } \kappa_{t}\in\{\mathsf{R},\mathsf{P},\mathsf{M},\mathsf{W}\} identifies the component to modify; operator specifies the operation to perform; target identifies the rule, memory entry, or configuration field to which the operation applies; and parameters supplies the values or content required by that operation. For example, refining an existing reasoning rule uses κ t = 𝖱 \kappa_{t}=\mathsf{R} , operator = REFINE_RULE , the rule identifier as target , and the revised procedure in parameters . F.2 Reasoning operators Motivated by prior work on modular reasoning, decomposition, self-refinement, and prompt scope ( Zhou et al., 2023 ; Madaan et al., 2023 ; Fernando et al., 2024 ; Chen et al., 2024 ) , we represent the reasoning strategy as an explicit and editable rule set. The corresponding operators allow reasoning rules and decomposition policies to be added, revised, generalized, reprioritized, or removed based on closed historical feedback. The particular typed rule schema and operator definitions are implementation choices of our harness. The reasoning component stores the base analysis protocol, decomposition policy, and a bounded collection of specialist rules. It is compiled into the mutable analysis instruction of the existing solver and does not alter the fixed role prompt. Table 2: Reasoning operators in the operator registry. Operator Function ADD_SPECIALIST_RULE Add a local, cluster-level, or global rule with a trigger, exclusions, and executable steps. REFINE_RULE Rewrite only the procedure of an existing rule. SET_DECOMPOSITION_POLICY Set a general decomposition policy, such as identifying comparison entities before extracting their attributes. GENERALIZE_RULE_SCOPE Broaden a rule by relaxing its trigger, removing exclusions, or expanding scope. PROMOTE_RULE_TO_DEFAULT Raise a rule’s scope or priority toward default behavior. DELETE_RULE Remove an obsolete or harmful specialist rule. F.3 Routing operators Motivated by retrieval-augmented generation, adaptive retrieval, evolving retrieval policies, and selective context construction ( Lewis et al., 2020 ; Asai et al., 2024 ; Huang et al., 2026 ; Ye et al., 2026 ; Li et al., 2023 ) , we treat routing as an editable pre-solver information-access policy. Its operators control how available context is selected, ranked, expanded, truncated, or restored before the solver call. The routing component controls how the existing Wikipedia provider selects and orders passages before the single solver call. It cannot write memory, inspect labels from the current unfinished round, or trigger an additional model call. Table 3: Routing/provider operators in the operator registry. F.4 Memory operators Drawing on episodic reflection, experiential learning, reusable procedural memory, and adaptive memory retrieval ( Shinn et al., 2023 ; Zhao et al., 2024 ; Wang et al., 2025 ; Ye et al., 2026 ) , we treat memory as a persistent editable experience bank whose entries can be added, revised, selectively triggered and prioritized, or removed across evolution rounds. The memory component maintains a retrievable active bank. The current protocol does not expose exact or global as proposer-selectable episodic triggers: new episodic memories enter a common cluster-ranking path. F.5 Workflow operators Drawing on automated and evolutionary workflow optimization ( Zhang et al., 2025a ; Zhao et al., 2026 ) , we treat the within-call execution workflow as an editable state that can evolve across rounds through changes to verification, evidence alignment, stopping, and fallback policies. The workflow component specifies a plan → \rightarrow reason → \rightarrow check → \rightarrow finalize policy within the same completion. It does not add a second verifier or a hidden model call. Routing selects the evidence paragraphs shown to the solver for the current question, while memory provides retrieved cases and feedback from previous tasks. Their interaction involves both a shared context budget and different retrieval modes, which affect which evidence paragraphs are selected and how many are retained.
