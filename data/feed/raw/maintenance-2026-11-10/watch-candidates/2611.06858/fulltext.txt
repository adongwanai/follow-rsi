CompressionBench: How can your coding agents compress LLMs?

Recursive self-improvement requires AI systems to improve the models
and infrastructure used by subsequent systems. LLM compression offers
a concrete efficiency objective: retain a pretrained model’s behavior
within a smaller model storage budget. We study whether coding agents can
carry out this step autonomously. We formulate compression as a terminal
task in which an agent receives a source checkpoint, storage limit,
inference environment, and time budget, then constructs compressed
weights and executable inference code. The agent controls its algorithm
and experiments; perplexity feedback guides search, and independent
verification checks the final model. Across six agents and six
model–size settings, 29 of 36 submissions pass verification. Selecting
the lowest-perplexity agent design per task yields an average 3.4%
perplexity increase over BF16 and 77.33% downstream accuracy, compared
with 79.56% for BF16. Recorded experiments reveal how agents achieve
these outcomes and where improvement breaks down. Agents lower PPL in 21 of 24 revisions at nearly fixed storage;
complete-model feedback reverses 17 of 79 prior local rankings;
and generation and inference tests expose failures that likelihood alone
misses. The results identify representation design, experimental
judgment, and capability validation as central to agent-driven model
compression, a measurable component of efficiency-oriented
self-improvement.

1 Introduction

Large language model (LLM) inference is increasingly bounded by memory
traffic rather than arithmetic: in autoregressive decoding, every
generated token reads the model weights from GPU memory, and an off-chip
memory access costs far more energy than the arithmetic it feeds ( Horowitz, 2014 ) . Compression that preserves a model’s
behavior within a smaller storage budget therefore reduces both the
memory a deployment occupies and the energy spent on every token it
generates, making models cheaper to serve and runnable on smaller
hardware ( Frantar et al., 2023 ; Lin et al., 2024 ; Lin et al., 2025 ) . Constructing
such a model remains substantial experimental and systems work, the
kind of work that coding agents increasingly undertake ( Novikov et al., 2025 ; Zhang et al., 2026 ) . An agent that compresses
models would improve the efficiency of the AI systems that follow it, a
concrete step toward recursive self-improvement. We therefore ask: can coding agents autonomously construct compressed LLMs that
remain useful within a given storage budget?

Existing compression methods provide a rich set of building blocks,
but no single method yields a useful model under an arbitrary storage
limit and hardware target. To construct one autonomously, an agent
needs three abilities:

• Coordinating coupled numerical decisions. A storage
budget ties together representation, precision allocation, and
parameter retention: bits spent on one component are unavailable to
the rest, and pruning releases bytes but removes capacity. Even at the
same nominal precision, clipping, rounding, calibration, and metadata
change the quality of a representation ( Frantar et al., 2023 ; Shao et al., 2024 ) . The agent must judge
feasible combinations rather than optimize each choice independently.

To evaluate these abilities without prescribing how agents compress,
we formulate LLM compression as a terminal task ( Figure 2 ), following the outcome-based evaluation of
Terminal-Bench and Harbor ( Merrill et al., 2026 ; Harbor Framework Team, 2026 ) .
A coding agent reads papers, writes code, constructs checkpoints, and
runs experiments within a fixed time budget. Three designs support this
evaluation. 1. Task: a complete model under a storage limit. Given source
weights, a storage limit, a GPU, and a pinned runtime, the agent may
combine quantization, mixed precision, pruning, low-rank
representations, and distillation, and must implement the inference
operations its representation requires ( Section 2.1 ). 2. Feedback: complete-model likelihood. A supplied evaluator
returns the source-to-compressed perplexity (PPL) ratio on
continuations sampled from the source model; the expected excess
cross-entropy equals the next-token KL divergence from the source
( Section 2.3 ). Evaluations share the agent’s time budget, so the
agent decides when local evidence suffices and when a complete-model
measurement is worth its cost. 3. Validation: the executable artifact. Independent
verification runs the submitted weights through the submitted inference
code on held-out contexts. Both the saved package and the resident GPU
weights must fit the limit; GSM8K, HumanEval, and TriviaQA accuracy must
retain 80% of BF16; and review checks integrity. Decode speed is
reported separately ( Section 2.4 ). Only verified models
receive a score.

In Section 3 , we evaluate the models that six coding agents
deliver for three source models with two storage limits each. Of the 36 resulting models, 29 pass verification, including
all 18 produced under the looser limits. Selecting the lowest-PPL agent
design per task yields an average 3.4% PPL increase over BF16 and
77.33% downstream accuracy, compared with 79.56% for BF16
( Section 3.2 ). In Section 4 , we analyze the
agents’ recorded searches to explain how they improve compression and
where improvement breaks down, yielding three findings. Representation design creates room at fixed storage. In 21 of 24
revisions that change package size by at most 0.01 GiB, agents lower
PPL by improving the quantizer or redistributing precision
( Section 4.1 ). Complete-model feedback changes selection. Reward feedback
reverses 17 of 79 prior local rankings, leading agents to revert
candidates or revise their local validation
( Section 4.2 ). Likelihood alone does not validate a model. Intermediate models
gain and lose correct answers at nearly unchanged PPL, and consistency
tests expose inference bugs that likelihood misses
( Section 4.3 ).

2 Compression as a Terminal Task

A compression task asks an agent to produce a model that approximates
a source LLM under a specified storage allowance. Its output includes
both the numerical representation and the code that runs it. The task couples
model approximation with implementation and experimental search.

2.1 Task Specification and Search Space

A task specifies a source model p p with its tokenizer, a storage limit C C , a hardware allocation, a pinned inference runtime, and a wall-clock
budget T T . The agent works in an offline container with read-only source
weights, starter inference code, searchable compression papers,
calibration and recovery data, and a separate set of questions for local
testing. The runtime provides scheduling and uncompressed operations.
The agent chooses its compression algorithm, produces the weights, and
implements the operations required by its chosen representation.

Let a = ( W , I ) a=(W,I) denote a candidate, where W W contains compressed weights
and associated metadata and I I is its inference implementation.
Together they define the executable model q a q_{a} . The search space
includes quantization formats and rounding rules, component-specific
precision, pruning, low-rank representations, and distillation. Changes
to this representation can also require changes to I I . The task does
not prescribe an order for making these decisions.

The storage allowance constrains two quantities. S pkg ​ ( a ) S_{\mathrm{pkg}}(a) counts the saved model package, including code and tokenizer assets. S res ​ ( a ) S_{\mathrm{res}}(a) counts model storage retained on the GPU during
inference, including scales, codebooks, padding, and persistent
dequantized weights. Shared allocations count once. KV caches, recurrent
states, and temporary computation workspace are excluded. These rules
prevent a small saved checkpoint from satisfying the task by retaining
a full-precision model during execution. The allowance constrains resident weights rather than total peak
GPU memory.

2.2 Experiments and Feedback

The agent allocates T T among implementation, calibration, recovery,
local tests, and evaluation of complete candidates. It can use local
measurements such as reconstruction error, KL divergence, or negative
log-likelihood to choose what to build. A supplied evaluator returns
PPL-based reward, package and resident model storage, decode timing,
and execution diagnostics. All such calls consume the same wall-clock
budget as model construction. The agent must judge whether another evaluation is worth its cost.

This interaction follows the budgeted experimentation setting of
MLAgentBench and RE-Bench ( Huang et al., 2024 ; Wijk et al., 2025 ) . Candidate versions and
experiments are recorded so that the final model can be connected to
the revisions that produced it. At time T T , the submitted candidate is
frozen. A separate container performs final verification, adding
held-out generated-answer tests and implementation review to the
likelihood and storage measurements.

We study text generation from two mixture-of-experts (MoE) checkpoints,

3.2 Delivered Models

Twenty-nine of the thirty-six submissions pass final verification
( Table 1 ). All eighteen at the looser limits pass.
At the tighter limits, six fail the answer-accuracy requirement and one
times out during answer generation. Selecting the lowest-PPL agent
artifact for each task gives an average 3.4% PPL increase over BF16.
Those six artifacts average 77.33% downstream accuracy, compared with
79.56% for the remeasured BF16 models.

The storage allowance influences every agent’s result, but does not
fully explain quality. Each agent’s larger-allowance artifact has lower
PPL than its tighter counterpart. Yet Sonnet’s 8 GiB dense model also
has lower PPL than three agents’ 12 GiB models. A better representation
can therefore outweigh additional storage in these comparisons. Uniform
GPTQ passes the answer threshold on the looser MoE tasks and fails on
the remaining settings, indicating that a fixed recipe covers only part of the task suite.

Released quantizations provide a stronger comparison. The best agent
artifact by PPL improves on each of the five measured released-model
references. Answer accuracy distinguishes designs further: the tighter
Qwen3.5 release has higher accuracy than the lowest-PPL agent model,
whereas Sonnet improves both PPL and accuracy over the released dense
references. PPL and answer accuracy thus affect
which artifact would be preferred.

Figure 1 places the results alongside encoded size and
API cost. Sonnet has the best average PPL rank, followed by Opus;
the largest API expenditure does not correspond to the best rank.
The remaining analysis follows the concrete decisions behind these
outcomes, rather than using spending or activity alone to explain them.

4 How Agents Improve Compression

Agents can change compression algorithms, storage allocation across
model components, or candidate evaluation. Recorded trajectories
connect these choices to model measurements and subsequent actions.
Within-task comparisons follow the recorded revisions; a paired
ablation isolates a quantizer decision after search.

4.1 Representation and Storage Tradeoffs

The first question is where an agent finds improvement once a model
fits the storage limit. It can allocate more bytes to a sensitive
component only by saving them elsewhere, or improve the approximation
represented by existing codes. In 24 recorded
revisions whose package sizes differ by at most 0.01 GiB, 21 lower PPL
measured by reward feedback. These pairs span all six agents and all six tasks
( Figure 4 ). These choices improve the
quantizer or redistribute precision within a feasible model.

three agents on five tasks. Bit width fixes the code count; clipping and rounding determine how
those codes approximate weights and activations ( Frantar et al., 2023 ; Shao et al., 2024 ) . The paired dense-model
ablation in Section 11.2 keeps precision allocation,
calibration, and inference implementation fixed while replacing
GLM’s MSE-selected clipping ranges with min–max ranges.
The selected ranges give lower verification PPL and higher answer
accuracy. Both variants occupy the same saved and resident model
storage. All three answer benchmarks favor the selected ranges. This connects the agent’s quantizer choice to the quality of the complete model after search.

Sensitivity guides mixed-precision bit allocation ( Dong et al., 2020 ) , but agents also allocate storage to metadata.
Kimi reduces dense-model group-scale storage to fit additional four-bit
weights. DeepSeek raises
non-expert precision on Nemotron, while Opus gives later Qwen3.5 layers
more expert precision. Weights and metadata share the package budget. Kimi reduces the storage used for scales to make room for higher weight precision; DeepSeek and Opus change where that precision is assigned. These examples show why the allocation includes quantizer overhead as well as the nominal bit width of the weights.

An agent can also remove parameters to afford higher precision for
those that remain. GLM and MiniMax test additional expert or MLP-width
removal; their recorded comparisons favor the less-pruned alternatives.
MiniMax nevertheless retains a large dense-model width reduction after
rejecting an early two-bit implementation. Its subsequent generation
tests expose a substantial loss. MiniMax’s decision to retain pruning
links its precision choice to parameter removal. Subsequent numerical
refinements operate on a model with fewer parameters.

squared norm; the dotted line denotes BF16 PPL.

The second question is how an agent chooses which design to retain.
Local experiments guide which candidate quantizers and precision
allocations an agent builds. We examine what happens when reward
feedback disagrees with that local ranking: whether the agent
reverts the candidate, revises its numerical choices, or changes
the validation used in subsequent experiments. Across 79 matched comparisons from 26 runs, reward feedback reverses
17 prior local rankings across all six tasks
and all agents except MiniMax. Eight reversals lead to explicit rollback: five by Kimi and
three by DeepSeek. Across the eligible comparisons, agents also refine
calibration and quantization or reallocate precision
( Section 11.3 ). Model-level measurements thus
influence both the candidate an agent retains and the numerical choices
it revisits.

A controlled diagnostic on dense Qwen3.8 varies levels, clipping,
rotation, rounding, and attention–MLP bit allocation at similar encoded
size ( Figure 5 ). Forward passes use BF16 reconstructions,
separating numerical representation from packed-kernel execution.
A k-means codebook improves weight reconstruction MSE over clipped
uniform levels but increases PPL. GPTQ rounding has the opposite
pattern: larger weight MSE and lower PPL. Calibration-activation output error follows PPL more closely in this
comparison. Weight MSE treats reconstruction errors equally across input
directions. Linear-output MSE weights those errors by the calibration
activations. A small reconstruction error in a direction with large
activation magnitudes can affect the layer’s output more than a larger
error in a weakly activated direction. Complete-model PPL measures the
resulting behavior after all quantized layers are composed. These criteria can therefore favor different
revisions at similar encoded size.

Figure 6 : Feedback during candidate selection.
(a) Best-so-far PPL for four searches; ticks indicate whether complete-model
feedback confirms or reverses a local ranking. (b) Outcomes of 301 reward
evaluations across 36 runs, grouped by search time. Rewards within 0.002

On looser Qwen3.5, Opus initially favors more precision for early
layers. It revises local validation to score model-generated
continuations, then favors later layers, an allocation supported by
reward feedback. On the tighter task, it spends 1.7 hours exploring
a one-bit expert tier. Local likelihood favors the new candidate, but
feedback favors the previous allocation; Opus restores and refines that
allocation. Conflicting measurements lead it to revise local validation
in one search and revert the candidate in the other.

Later evaluations increasingly match a run’s best PPL
( Figure 6 ). Some confirm that a candidate is worth keeping;
others follow successful numerical revisions. Kimi improves its dense
model after adding a low-rank residual and distillation. MiniMax instead
repeatedly evaluates a pruned candidate after its last improvement.
Reward feedback reports a tested candidate’s performance; the agent
then decides whether to refine its quantizer, change precision
allocation, or reconsider the representation.

4.3 Validating Generation and Execution

A prior pruning study reports mismatches between perplexity and
downstream performance ( Khanal and Capone, 2024 ) . For agents, detecting a generation
regression and finding a feasible repair are distinct challenges. PPL scores fixed source-generated histories, while generation feeds
the candidate’s own choices back into the model. Repetition, early
termination, and changed problem solving therefore require direct
checks. Intermediate verification tracks these changes between
versions; trajectories show whether agents detect the loss and
find a repair they can retain.

Figure 7 : Capability changes across candidate models.
(a) Verification PPL and answer accuracies for Opus on Qwen3.8 / 8 GiB;
shading marks distillation and dashed lines mark BF16. (b) Answers gained
and lost across twelve successive-version pairs from four runs, plotted
against PPL change. (c) HumanEval failure types for selected rejected
artifacts and their BF16 references. Each benchmark has fifty questions.

We verify retained intermediate models after search using the same
held-out inputs as the final artifacts. In Opus’s tighter dense-model
run, allocation and distillation improve PPL while GSM8K accuracy falls
from 88% to 72% across trained versions. HumanEval and TriviaQA improve
over the same versions. Twelve comparisons from four runs show both
newly correct and newly incorrect answers after small PPL changes
( Figure 7 ). A single scalar can conceal changes in
which capabilities survive.

Generation failures also differ in kind. Pruned GLM and MiniMax models
produce repeated or truncated HumanEval completions, while most BF16
errors are executable programs that fail tests. This matters for
acceptance: an artifact may preserve scored-token likelihood yet become
unreliable at completing an answer.

Figure 8 : Testing and acting on failures.
MiniMax’s dense-model run (a) and GLM’s Qwen3.5 run (b) retain pruning;
Opus continues dense-model distillation (c); MiniMax repairs expert
indexing on Nemotron (d). Curves show feedback PPL. Diamonds show the
agents’ generation tests relative to an unpruned three-bit reference (a),
an eight-bit reference (b), or BF16 (c). Final markers show held-out
benchmark accuracy relative to BF16.

MiniMax’s local reasoning tests show a large loss after MLP-width
pruning, relative to its unpruned three-bit reference. GLM’s expert-pruned
Qwen3.5 candidate similarly underperforms an eight-bit reference on
MATH-500. Both agents test alternatives and retain pruning without
finding a feasible design that resolves the loss. Opus tests generation
during distillation but makes later PPL-oriented changes without
repeating the same generation test on its last versions. Those local
MATH-500 measurements and the post-search GSM8K loss are separate tests.
The trajectories expose two distinct requirements: finding a candidate
that fixes a known problem and keeping tests current with the artifact
ultimately submitted.

On Nemotron, MiniMax compares token probabilities under batched and
per-expert inference. The disagreement identifies an expert-indexing
bug. Repair reduces the feedback PPL increase over BF16 from about
11% to 4.5%, and the final model passes verification. Here, the agent repairs
execution while keeping the representation fixed. In the pruning cases,
generation tests reveal regressions, but agents retain the affected
designs. Detecting a failure and finding a feasible change to the
compression design or implementation that resolves it are distinct
challenges.

4.4 Two Complete Compression Strategies

The dense and MoE case studies in Figure 9 bring these
decisions together. Both retain active parameters at the looser limits,
but their numerical methods lead to different allocations and execution
paths.

Figure 9 : From numerical design to execution.
Sonnet compresses dense Qwen3.8 to 12 GiB using rotation, trellis codes,
and sensitivity-based allocation (a). Opus compresses MoE Qwen3.5 to
48 GiB using rotated GPTQ and expert-specific precision (b). Rows connect
the offline pipeline, component precision, inference operations, and
candidate versions. Curves show search-time reward; boxes list explored
alternatives that were discarded.

• Sonnet: trellis codes and bit allocation. Sonnet replaces scalar GPTQ with Hadamard-rotated trellis codes, error
compensation, and Viterbi search ( Frantar et al., 2023 ; Tseng et al., 2024b ) . Matrix experiments
help choose the representation. KL ablations supply a fitted loss model
for bit allocation; token frequency guides embedding and output-head
precision. Representation and allocation changes produce the largest
reward gain, followed by calibration refinements. Sonnet rejects
Fisher-weighted allocation when its measured KL worsens and keeps a
smaller trellis when a larger one offers little reconstruction gain at
greater search cost. Its final artifact has PPL 3.253 and 76.67% mean
answer accuracy, versus BF16’s 3.221 and 74.00%.

• Opus: expert-specific precision. Opus uses rotated GPTQ with different bit widths across experts.
Revising validation shifts the favored allocation toward later layers,
while natural text remains the calibration source. Its search rejects
additional precision tiers and alternative rotations. The final artifact
has PPL 2.818 and 82.67% accuracy, versus BF16’s 2.755 and 84.67%.

Intermediate verification separates likelihood from answer preservation.
Sonnet’s versions v3, v4, and v5 attain PPL 3.2572, 3.2531, and 3.2525,
but answer 111, 104, and 115 of 150 questions correctly. Opus’s Qwen3.5
version v4 has PPL 2.8172 and 120 correct answers; v5–v8 have PPL 2.8178
and 124 correct answers. These tests use final verification inputs;
search-time feedback guides candidate selection. Nearly unchanged
likelihood thus accompanies different generated answers.

Sonnet reconstructs weight tiles from its stored trellis codes as they are needed for matrix computation. Other designs can first reconstruct a whole weight
matrix in temporary workspace and then use dense operations. Both
approaches can satisfy the resident-storage limit because the
reconstructed values are temporary. They expose different amounts
of unpacking work and memory traffic to inference, which contribute
to the measured execution cost. In the dense looser task,
Sonnet improves PPL and accuracy over the released GSQ-RCO artifact,
but decodes at 16.7 tokens/s versus the release’s 74.6 tokens/s
at batch size one
( Table A3 ). This illustrates why the measured
storage–quality improvement does not by itself establish a speedup,
and why representation and kernels must be considered together ( Lin et al., 2024 ; Lin et al., 2025 ) .

5 Related Work

5.1 Agentic Benchmarks

AlphaEvolve optimizes algorithms and LLM-training infrastructure with
coding agents ( Novikov et al., 2025 ) . The Darwin Gödel Machine
modifies agent code and evaluates the resulting coding agents ( Zhang et al., 2026 ) . We study a complementary efficiency objective:
compressed model weights and their execution under a resource budget.
The terminal task connects numerical choices and validation decisions
to the quality of the executable model.

Terminal-Bench evaluates agents on verified command-line tasks ( Merrill et al., 2026 ) ; Harbor provides a container-based
framework for executing tasks and evaluating agents ( Harbor Framework Team, 2026 ) .
SWE-bench studies repository repair ( Jimenez et al., 2024 ) , and
AgentBench evaluates interactive environments ( Liu et al., 2024 ) .
MLAgentBench, MLE-bench, and RE-Bench examine ML experimentation,
competition solutions, and research engineering ( Huang et al., 2024 ; Chan et al., 2025 ; Wijk et al., 2025 ) .
KernelBench tests correctness and runtime for specified tensor computations ( Ouyang et al., 2025 ) ; ServeLearnBench studies learning from
serving feedback ( Zheng et al., 2026 ) . Compression adds the
choice of numerical approximation: the agent must select, implement,
and validate a model whose generated answers remain useful.

5.2 LLM Compression

GPTQ, AWQ, SmoothQuant, and OmniQuant use calibration to choose
rounding, scaling, or clipping ( Frantar et al., 2023 ; Lin et al., 2024 ; Xiao et al., 2023 ; Shao et al., 2024 ) .
QuIP, QuaRot, and SpinQuant improve quantization through incoherence
processing or rotations ( Chee et al., 2023 ; Ashkboos et al., 2024b ; Liu et al., 2025 ) ; QuIP#, AQLM,
and QTIP develop lattice, additive, or trellis representations ( Tseng et al., 2024a ; Egiazarian et al., 2024 ; Tseng et al., 2024b ) .
HAWQ-V2 uses sensitivity for mixed precision ( Dong et al., 2020 ) , while
GSQ and RCO optimize quantization and budget allocation ( Dadgarnia et al., 2026 ; Helcig and Alistarh, 2026 ) .
Pruning removes weights or dimensions; low-rank methods reduce matrix rank ( Frantar and Alistarh, 2023 ; Sun et al., 2024 ; Ashkboos et al., 2024a ; Wang et al., 2025 ) .
Recovery can use quantization-aware fine-tuning ( Malinovskii et al., 2024 ) or distillation ( Hinton et al., 2015 ; Muralidharan et al., 2024 ) .
Serving systems optimize memory management and attention execution ( Kwon et al., 2023 ; Ye et al., 2025 ) ; TinyChat and QServe couple quantized
formats with matching kernels ( Lin et al., 2024 ; Lin et al., 2025 ) .

These methods supply components; we study agents that select, combine,
implement, and validate a complete compressed model.

6 Conclusion

LLM compression provides a concrete task for studying agent-driven model
improvement. Across 36 runs, 29 artifacts pass independent verification.
Recorded searches show quality gains at nearly fixed storage, local
rankings overturned by complete-model feedback, and generation or
implementation failures missed by likelihood alone. Effective compression
requires numerical design, experimental judgment, and validation of the
final executable model. Extending this step toward RSI requires testing
whether a compressed model retains the ability to carry out subsequent
compression tasks.
