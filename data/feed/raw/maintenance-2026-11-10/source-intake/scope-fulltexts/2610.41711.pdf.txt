Hierarchical Residuals: A Minimalist Decoupling of
Residual Width from Compute Width
Ziteng Wang1,2,∗, Jianqiao Lu2, Xinyu Ma2, Jintao Zhang1
Jun Zhu1, Yiyuan Ma2,†, Jianfei Chen1,†
1Tsinghua University, 2ByteDance Seed
†Corresponding authors.
Abstract
Residual connections underpin Transformers, but they implicitly tie the residual width carried
through depth to the compute width used inside each layer. We introduce Hierarchical Residuals
(HiRes), a minimalist architectural change that decouples these dimensions, widening the residual
state while keeping per-layer compute width fixed. HiRes groups layers into blocks: standard
d-dimensional PreNorm layers operate inside each block, while a wider D-dimensional PostNorm
outer residual connects blocks. Learned read/write projections bridge the two spaces at block
boundaries, leaving individual Transformer layers unchanged. Across different model sizes and
depths, HiRes consistently outperforms vanilla residual addition, with fitted scaling laws indicating
a 1.30× improvement in FLOPs efficiency. On OLMoE-1B-7B pretraining for 500B tokens, HiRes
achieves 0.0208 lower training loss and 1.14-point higher downstream accuracy. HiRes is also
competitive with other residual expansion methods such as VWN, mHC and AttnRes with less
activation memory and I/O costs. Built from only dense projections and normalizations, it requires
neither specialized kernels nor infrastructure-level optimizations.
HiRes thus exposes residual
width as a practical scaling variable using only standard operators.

Introduction
Residual connections [14] are the backbone of modern Transformers. A standard PreNorm layer reads from
a normalized copy of the current hidden state, computes an update, and adds that back to the original state
[47, 54]. Repeating this operation yields a simple yet effective transport rule: one d-dimensional state is
carried through depth along an identity path, while every attention and feed-forward module contributes an
additive update. This design makes deep optimization practical, but it also ties the width of the state carried
through depth to the width of the working space of every layer.
Recent residual architectures relax this constraint in different ways. Alternating Updates (AltUp) maintains
multiple residual streams, with each layer computing one stream and predicting the remainder [4]. Hyper-
Connections (HC) likewise uses multiple streams but learns how layers read from, write to, and combine them
with lightweight projectors [59]; Virtual Width Networks (VWN) generalizes this formulation by splitting
each stream into finer granularity [38]; Manifold-Constrained Hyper-Connections (mHC) stabilizes HC by
constraining its residual mixing operators to a doubly stochastic manifold [53]. Attention Residuals instead
retrieves representations from earlier layers using attention over depth [20]. These methods introduce different

residual addition: (i) the effective residual state is expanded, and (ii) residual accumulation becomes explicitly
regulated, keeping the residual scale in check. This suggests that residual-state capacity is an architectural
variable in its own right, rather than a quantity that must always equal model width.
However, their per-layer expanded states and intricate mixing add activation traffic and memory-bound resid-
ual operators, typically requiring fusion, recomputation, overlap, or specialized kernels to recover through-
put [53]. If the benefit stems from the wider state itself rather than particular operators, a natural question
arises: can Transformers benefit from a wider residual state with as little architectural change as possible?
To this end, we introduce Hierarchical Residuals (HiRes). HiRes groups adjacent Transformer layers into
layer blocks and organizes residual computation at two levels. Inside each block, the model runs ordinary
d-dimensional PreNorm Transformer layers. Across blocks, it maintains a D-dimensional outer residual state
with the familiar additive update (D > d). A read projection maps the outer state into a block, and after the
inner residual accumulation, a write projection maps the resulting inner state back. The block write is added
to the outer residual and the sum is then post-normalized, which regulates the residual scale. Thus, the
outer recurrence retains the familiar PostNorm residual, while the inner Transformer layers are unchanged.
In this way, the residual expansion ratio D/d can be selected independently of the compute width d for each
inner layer. Because read/write operations occur only at block boundaries, the additional parameters and
compute costs are amortized over depth. Figure 1 places the two levels side by side: the outer recurrence is
the residual motif of a vanilla PostNorm Transformer, with a whole layer block in place of a sublayer.
Empirically, HiRes consistently outperforms vanilla residual addition across model sizes and depths. Under
fitted loss-compute scaling laws, it is 1.30× more FLOP-efficient. As depth scales up at fixed width, HiRes
continues to improve through 128 layers where the baseline exhibits diminishing returns. Against Hyper-
Connections, mHC, VWN, and Attention Residuals, HiRes remains comparable in quality at lower activation
memory and I/O costs. On OLMoE-1B-7B [30] pretraining for 500B tokens (Section 3.5), HiRes achieves
0.0208 lower training loss and 1.14-point higher downstream accuracy. Overall, HiRes provides a minimalist
way to expand the residual state without widening per-layer compute. It shows that decoupling residual
width from compute width is beneficial, and that this decoupling is available with standard operators.

Method
2.1
Vanilla Residual Addition
Consider a decoder-only Transformer with L layers and hidden width d. Each layer contains an attention
module and an FFN module, giving 2L residual sublayers. Let xi−1 ∈Rd denote the residual state before
sublayer i. A standard PreNorm Transformer can be written as
xi = xi−1 + Fi(RMSNormi(xi−1)) ,
i = 1, . . . , 2L,
(1)
where Fi : Rd →Rd is an attention or FFN transformation. Thus the state carried through depth (resid-
ual width, dimension of xi) and the state processed by every sublayer (compute width, input and output
dimension of Fi) share the same width d.
2.2
Decoupling Residual Width and Compute Width
To decouple residual width and compute width, we introduce a wider residual stream hi ∈RD with D ≥d
and n := D

needs a read map Ri : RD →Rd to project the carried state into the working space, and a write map
Wi : Rd →RD to return the sublayer output to the residual space. So the vanilla residual in Equation (1)
becomes
xi = Rihi−1,
hi = hi−1 + WiFi(RMSNormi(xi)) ,
i = 1, . . . , 2L.
(2)
Setting D = d and Ri = Wi = I recovers the vanilla recurrence.
Residual-expansion methods typically introduce lightweight interfaces by sharing mixing weights across
streams or coordinate groups.
HiRes instead adopts the simplest choice: dense projections Ri ∈Rd×D
and Wi ∈RD×d. At fixed D and d these are the most general linear interfaces, imposing no structural
inductive biases like weight sharing, providing full connectivity between the expanded residual state and
the working space. Empirically, HiRes achieves competitive performance at a smaller expansion ratio than
methods with structured interfaces, while incurring lower activation memory and I/O costs (Section 3.4).
2.3
Hierarchical Residual Recurrence
Applying dense interfaces at every sublayer would add Θ(LDd) parameters and FLOPs, which is comparable
to the Θ(Ld2) cost of the Transformer layers themselves and thus unacceptable. HiRes therefore invokes
them only at block boundaries, yielding a hierarchical structure.
HiRes partitions the L layers into B consecutive blocks B1, . . . , BB.

thus share the same boundary interfaces and d-dimensional coordinate system: the block pulls a subspace of
the outer residual state, transforms it through several layers, and commits the result back.

2.4
Design Choices
Normalization at block boundaries.
Boundary normalization provides residual regulation in HiRes: without
it, the outer residual stream would be unbounded as it accumulates block outputs. Keeping PreNorm within
blocks and applying PostNorm between them combines PreNorm’s optimization stability during the backward
pass [50, 54] with PostNorm’s periodic control of the outer residual scale during the forward pass [19].
Setting D = d and Rb = Wb = I in Equation (4) and removing the outer residual accumulation yields
hierarchical normalization (HiNorm):
xb+1,0 = RMSNormb(Φb(xb,0)),
b = 1, . . . , B,
(6)
which inserts one RMSNorm into the residual stream every L/B layers. HiNorm isolates regulation from
residual expansion and serves as a control in our experiments.
HiNorm alone beats the baseline and reaches minimum loss at an intermediate B = 4 (Appendix Figure 6a).
In Appendix Figure 6b, the residual scale grows monotonically in the vanilla baseline and in HiRes without
boundary normalization. HC, VWN, and AttnRes [20, 38, 59] regulate the scale implicitly through residual
mixing learned at every layer, whereas HiRes regulates it explicitly with boundary normalizations: the scale
grows only within each block and is reset at every boundary.
Interface stabilization.
We empirically observe that randomly initialized interfaces degrade performance
early in training (Appendix D.2.2), which we hypothesize arises from a seesaw dynamic: the interfaces learn
each block’s working coordinate system while the inner layers simultaneously learn to transform representa-
tions within that evolving space. Motivated by prior identity-biased residual gates [3, 46], we stabilize the
interfaces by interpolating between identity and learned mappings using learnable gating scalars:

Experiments
3.1
Setup
We conduct the primary architecture study using the OLMoE codebase [30]. All models use RMSNorm [56],
RoPE [44], grouped-query attention (GQA) [1], and a SwiGLU feed-forward network [39]. We train with
AdamW [24] and a cosine learning-rate schedule with warmup, use a 4096-token context, and initialize weights
with standard deviation 0.02.
The default HiRes configuration uses residual expansion ratio n = D/d = 2 and block count B = 4. We
ablate both choices in Section 4.1.
For architecture comparisons, we average training loss over the final 1000 steps. Validation loss and down-
stream accuracy are averaged over the final 3 evaluations, 1000 steps apart, and across 11 held-out domains
and 12 tasks, respectively. The full experimental setup is detailed in Appendix B.

3.2
Scaling on Model Size
We evaluate model-size scaling over five model sizes, jointly increasing inner width and depth from (d, L) =
(512, 8) to (1536, 24) with the parameter count spanning from 70M to 626M. The detailed scaling ladder can
be found in Table 5. We compare six fixed architecture families: the vanilla residual baseline; HiRes with
n = 2, n = 3, and n = 4; and two reduced forms of HiRes, namely HiNorm, which keeps only the boundary
normalization, and equal-width HiRes with n = 1, which adds the interfaces and the outer residual without
widening. All HiRes variants use B = 4.
Since HiRes introduces modest parameter overhead, we compare models by fitting a loss-compute scaling
law
[16, 18] in analytic training FLOPs: C = T(6P + 12Lsd), where P is the total parameter count, T
is the number of training tokens, L is the number of layers, s is the sequence length, and d is the inner
width. We jointly fit the observations with the scaling law Lf(C) = L∞+ Af(C/C0)−αf , with a shared
irreducible loss and family-specific amplitude and exponent. Here C0 = 1020 FLOPs is the reference compute
and L∞= 2.101 is the fitted irreducible loss.
Figure 2 separates the two sources of the HiRes gain: residual regulation and residual expansion. HiNorm
consistently shifts the vanilla residual scaling curve downward. Widening the residual state (n = 2) brings
a further gain at every scale. Equal-width HiRes (n = 1) remains close to HiNorm, indicating that the
hierarchy interfaces alone add little benefit. A clearer improvement appears when the outer state expands
from D = d to D = 2d, while the n = 3 and n = 4 trajectories remain close to n = 2, indicating diminishing
returns. Regulation and widening thus contribute complementary gains. HiRes with n = 2 combines both,
and the fitted scaling laws estimate that the baseline requires 1.30× the FLOPs of HiRes to reach a validation
loss of 3.00.

3.4
Comparison with Other Residual Expansion Methods
We compare HiRes with other residual expansion methods with the recipe of (d, L) = (768, 12) for 50B-
token training, namely Hyper-Connections (HC) [59], mHC [53], Virtual Width Networks (VWN) [38], and
Attention Residuals [20]. Specifically, we test 2× and 4× wider residual states for HC/mHC/VWN, full and
4-block AttnRes, and n = 2, B = 4 HiRes. We then test mHC-4, VWN-4, Block AttnRes-4, and HiRes
configurations on larger backbones. Appendix C.3 gives the detailed implementations and complete results.
At (d, L) = (768, 12), all residual-expansion methods improve the vanilla residual baseline in loss, and HiRes
achieves comparable performance to mHC, VWN, and AttnRes at a lower residual expansion rate, as shown
in Table 1.
Table 2 compares the vanilla residual baseline, mHC, VWN, Block AttnRes, and HiRes across three backbone
scales: (d, L) = (768, 12), (1024, 16), (1280, 20).
HiRes remains within the leading quality range of these
recent residual-expansion methods. The same table reports the analytic I/O at each scale (Appendix E),
together with throughput and memory from a unified measurement of each method’s highly optimized Triton
implementation (Appendix F). HiRes has the lowest activation I/O among residual-expansion methods and
closest to the baseline’s 3d. Despite additional parameters, HiRes retains 91.7–93.1% of baseline throughput
at 3.3–3.4% memory overhead, which is on par with optimized AttnRes and more efficient than mHC/VWN.
Moreover, HiRes’ standard PyTorch implementation already reaches near-final performance, while other
methods rely on mechanism-specific kernel fusion. Appendix F reports the agentic optimization campaign
and the latency decomposition behind these numbers.

Ablation Studies
4.1
Ablation on Block Count and Expansion Ratio
We ablate the two structural hyperparameters of HiRes: the residual expansion ratio n and the number of
blocks B. All runs use (d, L) = (768, 12) and 50B training tokens. The expansion sweep fixes B = 4 and
varies n = D/d from 0.75 to 4, while the block sweep fixes n = 2 and varies B from 1 to 12. Figure 5 reports
both sweeps.
Expansion ratio.
In Figure 5a, validation loss rapidly decreases as the expansion ratio increases to n = 2,
after which the slope slows. The wider n = 3 and n = 4 settings provide marginal gains, largely following
the shifted scaling law, which accounts for the benefit from extra parameters. Thus n = 2 is the empirical
knee of the quality-overhead curve: it captures most of the benefit of residual expansion while keeping the
interface cost moderate. On the other side, at n = 0.75 the outer state is narrower than the layer compute
width, and it is the only point in the sweep that fails to improve over HiNorm, even with more parameters.
This result identifies residual width, rather than the interfaces themselves, as the main source of the gain.
Number of blocks.
In Figure 5b, increasing B also improves validation loss, with the largest gains occurring
as the hierarchy is refined from one to four blocks. Beyond B = 4, more frequent outer-state updates show
diminishing returns similar to those of the expansion ratio. We therefore retain B = 4 as the empirical knee.

Disabling it raises validation loss by 0.008, a rel-

Nevertheless, its advantage

5
Related Work
Residual-state expansion.
The closest methods expand the residual state, but typically by replacing vanilla
addition with a learned, per-layer operator. AltUp widens the representation into sub-blocks and updates
one sub-block at backbone width while a lightweight predictor updates the rest [4].
Hyper-Connections
(HC) maintains multiple residual streams with learned layer-dependent read, write, and residual mixing
weights [59]; Virtual Width Networks (VWN) generalizes HC by constructing fine-grained fractional streams,
enabling more expressive mixing [38, 60]; mHC constrains the residual stream transition to a doubly stochastic
manifold for stability [53]. Attention Residuals instead learns content-dependent attention over earlier layer
or block representations [20]. Relative to this family, HiRes is simpler in mechanism: one wide outer state,
dense read/write only at block boundaries, and additive residual transport. It maintains more expressive
interfaces between the expanded residual and the fixed-width inner state, and amortizes the cost across depth.
Normalization in Transformers.
The original Transformer normalizes after each residual addition (Post-
Norm), whereas modern language models typically use PreNorm to keep an uninterrupted additive path
through depth
[2, 31, 47, 54, 56]. There exists a well-known trade-off between PreNorm and PostNorm:
PostNorm controls activation scale but can attenuate gradients, while PreNorm eases optimization but lets
the residual state grow unbounded [49]. Hybrid placements pursue both, adding normalization inside the
residual branches [41], around each sublayer [19], mixed within a sublayer [61], across depth [21], or across
coupled PreNorm-like and PostNorm-like streams [22]. HiRes differs in granularity: complete PreNorm lay-
ers run inside a block, and PostNorm is applied only after the block-level outer residual addition, preserving
ordinary inner updates while periodically resetting the outer-state scale.
Cross-layer connectivity and state aggregation.
Prior work enriches information flow across depth through
gated shortcuts, identity paths, or dense connectivity [14, 17, 43]. Transformer variants further aggregate
earlier representations using static weights, element-wise gates, reused values, or low-rank projections [11, 26,
32, 58], while MUDDFormer mixes decoupled streams and Deep Delta Learning maintains a matrix-valued
state [52, 57]. HiRes instead uses hierarchical connectivity, combining a persistent wide outer state across
blocks with narrow inner states within each block.
6
Conclusion
We introduced Hierarchical Residuals (HiRes), a deliberately minimal architecture that decouples residual-
state width from per-layer compute width. HiRes carries a wide persistent state across layer blocks, performs
ordinary Transformer computation in a narrower inner space, and connects the two through learned read/write
projections at block boundaries. This hierarchical design uses only dense linear maps, normalization, and
residual addition, requiring neither specialized kernels nor changes to the inner Transformer layers.
Across model sizes and depths, HiRes consistently outperforms the vanilla residual baseline and is competitive
with other residual expansion methods including HC, VWN, mHC, and AttnRes. These results demonstrate
that residual-state width need not be tied to per-layer compute width and that their conventional equality
can be suboptimal. HiRes therefore establishes residual width as a practical scaling variable that can be
exploited through a simple yet effective hierarchical design.

A
Implementation Pseudocode
HiRes can be implemented as a simple extension of a vanilla Transformer by changing fewer than ten lines
of code in the model’s forward method, as illustrated in Algorithm 1.
Algorithm 1 PyTorch-style pseudocode of the HiRes forward pass.
def forward(self, input_ids):
x = self.embed(input_ids)
x_outer = self.embed_proj(x)
# up-project d -> D
for b in range(self.num_blocks):
# Read at block entry, down-project D -> d
x_inner = self.read_proj[b](x_outer)
# Standard PreNorm inner residual
for i in range(self.num_layers // self.num_blocks):
x_inner = x_inner + self.attn[b][i](self.attn_norm[b][i](x_inner))
x_inner = x_inner + self.ffn[b][i](self.ffn_norm[b][i](x_inner))
# Write at block exit, up-project d -> D
x_outer = self.outer_norm[b](x_outer + self.write_proj[b](x_inner))
x = self.lm_head_proj(x_outer)
# down-project D -> d
logits = self.lm_head(self.final_layernorm(x))
return logits
B
Experimental Setup
All dense experiments use decoder-only Transformers implemented in the OLMoE codebase [30]. Models
use weight-tied input/output embeddings, RMSNorm [56], RoPE [44], SwiGLU [39] with preactivation width
dff = 4d, grouped-query attention [1] with head dimension 64 and 4 KV heads, and per-head QK-norm [9].
Training uses AdamW [24] with β1 = 0.9, β2 = 0.95, ϵ = 10−8, weight decay 0.1, and gradient-norm clipping
at 1.0. The learning rate uses cosine decay to 0.1 of the peak rate after a linear warmup over 2% of training
tokens. Models use a 4,096-token sequence length and initialization standard deviation 0.02. Table 4 lists
the scale-dependent settings.
The training corpus is the OLMo2 stage-1 mixture, tokenized with the Dolma2 tokenizer and its 100,352-
token vocabulary [48]. All compared architectures at a given scale reuse the same data order and global
sample-index array.
Validation loss is averaged over 11 held-out domains from Paloma [25]: C4 [33], Dolma Books, Dolma Common
Crawl, Dolma Pes2o, Dolma Reddit, Dolma Stack, Dolma Wiki [42], ICE, M2D2 S2ORC [23, 34], Pile [13],
and WikiText-103 [27]. Downstream accuracy is averaged over 12 tasks: MMLU [15], ARC-Challenge and
ARC-Easy [7], BoolQ [6], CommonsenseQA [45], COPA [35], HellaSwag [55], OpenBookQA [28], PIQA [5],
SciQ [51], SocialIQA [37], and WinoGrande [36].

D.2.2
Interface Stabilization Dynamics
The scalar gates in Equation (7) bias each read/write map toward the coordinate-aligned identity at initial-
ization. We compare the default initialization, σ(α) = 0.1, with direct dense interfaces. Figure 7 shows that
direct interfaces initially train worse than the baseline and only later cross below it. The identity-biased
parameterization starts closer to the baseline and remains better throughout the early optimization phase.
Stabilization therefore prevents newly initialized interfaces from immediately disrupting residual transport.
The final results in Table 11 further show that stabilization is an optimization aid rather than a requirement
for the architecture.

Agent-Driven Optimization of Residual Mechanisms
To assess the practical efficiency and ease of adoption of each residual expansion mechanism, we measure both
its final training efficiency and the agent-driven optimization required to reach it, comparing framework-level
PyTorch and mechanism-specific Triton implementations.
F.1
Experimental Protocol
We evaluate (dmodel, L) ∈{(768, 12), (1024, 16), (1280, 20)} on eight GPUs using FSDP FULL_SHARD, bfloat16,
sequence length 4096, and per-GPU micro-batch 4. Every measurement includes forward, backward, and
the optimizer update; peak memory is reported per GPU. The attention, MLP, normalization, optimizer,
precision, and measurement harness are shared, and only mechanism-specific code may change.
Starting from functionally equivalent naive implementations, independent Claude Opus 5 agents receive the
same prompt and optimize HiRes, VWN-4, mHC-4, and Block AttnRes-4 in two stages: the PyTorch stage
that may leverage graph transformations, torch.compile, batching, and layout changes; and the Triton stage
that adds mechanism-specific fused kernels. Every candidate must match the reference outputs and gradients
at all three scales. Candidates are measured against the current best and retained only if throughput improves
by at least 0.2% at every scale. We report the best implementation from each stage. The final optimized
Triton implementation is used to measure the efficiency of each residual expansion mechanism in Table 2.

G
A Latent View
Besides expanding the residual state width, HiRes also admits a dual interpretation:
relative to a D-
dimensional persistent hidden state, its attention and FFN computation occurs in a d-dimensional latent
space. Expanding residual width by n = D/d is therefore equivalent to compressing compute width by a
factor of n; the wide state preserves information across blocks, while the narrow state performs the transfor-
mations within each block.
This view connects HiRes to module-specific latent designs. MLA compresses the attention KV representa-
tion [8], while LatentMoE performs routed expert computation in a compressed space [10]. HiRes extends the
same separation between state width and compute width to the residual hierarchy. Its key distinction is in-
teraction granularity: instead of exchanging information between hidden and latent spaces at every sublayer,
HiRes reads once at block entry and writes once at block exit. Layer grouping therefore reduces hidden-latent
transport from per-sublayer to per-block while allowing computation to evolve for multiple layers in the latent
space.
H
Limitations
Our study has the following limitations. First, HiRes decouples residual width from compute width, but we
have not jointly optimized these widths and model depth under a fixed compute budget. The best allocation
of capacity between carrying representations and transforming them therefore remains unclear. Second, we
use equal-sized blocks, so exchanges between the wide state and the inner computation occur at regular
intervals. We have not examined whether different parts of the network benefit from more frequent access to
the wide state. Finally, our results show the benefits of residual expansion, yet how the wider residual state
improves learning remains an open question. In particular, what information is preserved across blocks and
how individual sublayers contribute to its transformation and reuse are not yet well understood.
