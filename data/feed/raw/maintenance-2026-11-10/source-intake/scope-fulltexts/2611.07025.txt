Existing post-training methods exploit redundancy across tokens, layers, and feature dimensions, or lower numerical precision. We identify a complementary axis: within each attention head, values are largely predictable from their corresponding keys. We exploit this with value cache amortisation, which fits a lightweight per-head predictor at test time and stores residuals only for the tokens it reconstructs worst, giving 4 × 4\times near-lossless value compression. The predictor can be initialised by meta-learning for substantially reduced prefill overhead, or fitted from scratch in settings that allow a one-off cost, such as multi-query inference. We pair value amortisation with cross-layer low-rank key compression to produce LowRAM, an asymmetric compression pipeline that stays close to lossless across three model families. By reconstructing only a selected subset of KV pairs at each decoding step, LowRAM can keep decoding overhead minimal and achieve up to 5 × 5\times higher peak decode throughput at 4 × 4\times compression. LowRAM further composes with quantisation and eviction, reaching 26.9 × 26.9\times compression at 94.5 % 94.5\% of baseline performance on long contexts. These results show that treating keys and values as structurally distinct enables efficient, aggressive, and composable KV cache compression. † † footnotetext: ∗ Equal contribution. 1 Introduction Transformers ( Vaswani et al., 2017 ) have become the dominant architecture for language modelling, but their deployment at long context lengths is fundamentally constrained by the compute cost of autoregressive decoding. Modern inference stacks address this via a KV cache: the key and value projections of each preceding token are computed once and reused at every subsequent decoding step. This turns decoding from a quadratic to a linear operation in sequence length, but shifts the bottleneck from compute to memory: the cache grows linearly with context length and batch size, and at long contexts comes to dominate the model’s activation footprint. A wide range of architectural responses to this bottleneck have been proposed, including linear attention and state-space alternatives that replace the cache with a fixed-size recurrent hidden state ( Katharopoulos et al., 2020 ; Gu and Dao, 2023 ; Dao and Gu, 2024 ) , and sparse, sliding-window, grouped-query, and multi-head latent attention variants that reduce per-token cache size architecturally ( Ainslie et al., 2023 ; DeepSeek-AI et al., 2024 ) . However, these approaches require pretraining or substantial finetuning, and most open-weight models still rely on grouped-query attention with a full KV cache ( Grattafiori et al., 2024 ; Jiang et al., 2023 ; Team et al., 2024 ; Yang et al., 2025a ) . This has motivated a parallel line of post-training KV cache compression methods operating on frozen pretrained models. Existing methods fall into three families: eviction, which discards unimportant entries ( Xiao et al., 2024 ; Zhang et al., 2023 ; Li et al., 2024 ; Cai et al., 2025 ) ; quantisation, which lowers the precision of stored entries ( Liu et al., 2024 ; Hooper et al., 2024 ; Dong et al., 2024 ) ; and low-rank decomposition, which approximates KV matrices with smaller, factorised representations ( Yu et al., 2024 ; Chang et al., 2025 ; Saxena et al., 2024 ) . These families are largely orthogonal, exploiting redundancies along different axes of the cache. This leaves the redundancy between keys and values largely unexplored. Keys and values are computed from the same representation, and although they serve different functions, their shared origin induces a predictable relationship between them. We exploit this redundancy by using the keys as a source from which the value cache can be recovered. We first compare several predictive relationships within and across layers under a matched memory budget and find that reconstructing current-layer values from current-layer keys best preserves downstream performance. Based on this finding, we introduce value cache amortisation: during prefill, we fit a lightweight per-head network to map cached keys to their associated values. We then rank tokens by reconstruction error and store residual corrections only for the least accurately predicted values. The resulting value cache consists of the network parameters and a sparse set of residuals. During decoding, values are recovered by applying the network to the keys and adding the stored corrections, as illustrated in Figure 2 . Amortising the values still requires keys to be retained, both for attention and as inputs to the learned map. A complete compression scheme must therefore reduce the key cache as well. Our source-target analysis suggests that applying the same predictive strategy to the keys leads to less downstream performance than for values. Instead, for keys, prior work points to low-rank decomposition: their energy is concentrated in a relatively small number of feature directions, producing a short spectral tail and correspondingly small approximation error at reduced rank ( Saxena et al., 2024 ) . These findings motivate an asymmetric design: values are reconstructed from keys, while the keys themselves are compressed according to their low-rank structure. LowRAM realises this design by pairing value cache amortisation with xKV ( Chang et al., 2026 ) , which shares a low-rank basis across layers within each group to exploit alignment between their dominant key-cache subspaces. The former dramatically reduces prefill overhead introduced by amortisation, while the latter achieves up to 5 × 5\times higher peak decode throughput. 2 Related Works Low-Rank Decomposition of KVs. Training-free SVD-based KV compression largely targets per-layer redundancy, via activation-aware or grouped SVD on the KV projection weights ( Yuan et al., 2025 ; Yu et al., 2024 ; Zhang et al., 2024 ; Chang et al., 2025 ; Yan et al., 2025 ) , projecting attention into an offline-fitted eigen-subspace ( Saxena et al., 2024 ) , or direct channel pruning ( Xu et al., 2025 ) . Complementary learned-projection methods ( Lin et al., 2025 ; Shi et al., 2025 ; Benfenati et al., 2026 ; Hao et al., 2026 ; Wang et al., 2026 ; Lesens et al., 2025 ; Zhu et al., 2025 ; Shaikh et al., 2026 ) reach similar ratios with trained or online-adapted projectors. xKV ( Chang et al., 2026 ) instead exploits cross-layer redundancy, sharing a single SVD basis across contiguous layer groups since adjacent layers share dominant singular vectors. Eviction. Eviction reduces KV cache memory by discarding unimportant tokens. Early methods keep attention sinks and a recent window ( Xiao et al., 2024 ) , or a mix of recent and high-attention tokens ( Zhang et al., 2023 ) . Later work selects tokens using an observation window ( Li et al., 2024 ) , or allocates budgets per layer ( Cai et al., 2025 ) or per head ( Ge et al., 2024 ; Feng et al., 2025 ; Tang et al., 2025 ) . Query-agnostic methods instead score tokens by how well they support reconstructing the context ( Kim et al., 2025 ; Jegou and Jeblick, 2026 ) . Quantisation. Quantisation compresses the KV cache by lowering the precision of stored keys and values. However, these exhibit channel-wise outliers ( Dettmers et al., 2022 ; Xiao et al., 2023 ) that dominate a uniform quantisation grid, so naive quantisation degrades sharply below 4 4 bits ( Liu et al., 2024 ; Hooper et al., 2024 ) . Sub- 4 4 -bit methods therefore target these outliers by quantising keys channel-wise and values token-wise ( Liu et al., 2024 ) , allocating bit-widths per token ( Yang et al., 2024a ; He et al., 2024 ; Dong et al., 2024 ) or per layer ( Li et al., 2025 ) , inverting positional embeddings before quantisation ( Hooper et al., 2024 ) , or removing outliers with random rotations ( Ashkboos et al., 2024 ; Han et al., 2026 ; Zandieh et al., 2026 ) . AQUA-KV ( Shutova et al., 2025 ) instead quantises a prediction residual, using linear adapters that exploit both inter-layer and intra-layer dependencies: keys are predicted from previous-layer keys, while values are predicted jointly from previous-layer values and current-layer keys. Our amortised value cache uses context-adapted prediction of values from keys within each attention head, storing residuals only for tokens that are hard to reconstruct. 3 Methods We propose LowRAM, an asymmetric compression pipeline that treats the key and value caches as structurally distinct objects. For keys, we adopt xKV ( Chang et al., 2026 ) , which exploits the low-rank cross-layer redundancy of key states. For values, we introduce amortisation, a learned associative memory that predicts each token’s value vector directly from its key, fit once per context, and retains residuals only for the values the predictor reconstructs poorly. Prior to both decomposition and prediction, we invert RoPE, following evidence that pre-RoPE representations are more amenable to compression ( Hooper et al., 2024 ; Su et al., 2025 ; Sun et al., 2025a ) , with the rotation reapplied at attention time. Both predictor fitting and value reconstruction use the pre-RoPE keys reconstructed by xKV. During decoding, generated key-values are stored exactly in the cache. 3.1 Identifying the Predictive Structure of the KV Cache Prior work has explored predictive compression of the KV cache using inter-layer and intra-layer dependencies ( Shutova et al., 2025 ) or across tokens ( Hao et al., 2026 ) .Here, we focus on learning a mapping from keys to values within individual attention heads. To determine which representation is best suited to predictive compression within our framework, we perform a source-target analysis over the KV cache. For each layer, we train the same predictor to reconstruct either the current-layer keys or values while varying the available source representation. Specifically, we consider previous-layer keys ( K L − 1 K_{L-1} ), previous-layer values ( V L − 1 V_{L-1} ), their concatenation ( K ​ V L − 1 KV_{L-1} ), current-layer values ( V L V_{L} ), and current-layer keys ( K L K_{L} ). To match our proposed compression scheme, each predictor is paired with a residual store, with the residual budget fixed across all configurations. All configurations are evaluated under the same 3 × 3\times compression budget using both reconstruction error and recovered LongBench performance. Under this setting, lower reconstruction error does not necessarily imply better preserved downstream performance. Two further observations are worth noting. First, value reconstruction generally recovers more downstream performance than key reconstruction. Second, reconstruction error correlates only weakly with downstream performance: source–target pairs with similar reconstruction errors can exhibit significantly different recovered performance, and the differing scales of keys and values make their absolute error difficult to compare directly. We therefore base our design decisions primarily on recovered downstream performance rather than reconstruction error. 3.2 Value Cache Amortisation Having established K L → V L K_{L}\rightarrow V_{L} as the preferred prediction direction, we model this relationship with a lightweight parametric function. Warm-starting the Amortised Value Cache MLP. Adapting f θ f_{\theta} from scratch on each context wastes gradient steps relearning shared structure. We instead split the work in two: a one-off offline stage that learns the general key-to-value mapping (one pass over 32 batches of 4096-token FineWeb-Edu sequences, 25 gradient steps, under five minutes on one GPU, run once per model), and an online stage that overfits this mapping to the current context. At inference, these weights initialise each layer’s MLP before per-context adaptation, reducing the steps needed to reach a useful approximation. 3.3 Efficient Adaptation and Selective Reconstruction Meta-learned initialisation. Even with warm-starting, fitting the value predictor requires many per-context gradient updates, making it costly when a context is queried only once. We therefore meta-learn an initialisation ϕ \phi using First-Order MAML Nichol et al., 2018 . Each sequence defines a meta-learning task consisting of its observed KV pairs, and the inner loop adapts the per-head predictor for K K gradient updates. At inference, the predictor is initialised from the learned parameters ϕ ⋆ \phi^{\star} and adapted to the new context using the same K K -update budget. Appendix E gives the complete training procedure. Selective reconstruction. Reconstructing the complete cache at every decoding step can offset the computational benefit of compression. Following landmark-guided retrieval ( Sun et al., 2025a ) , we partition the prefix into chunks represented by mean-key landmarks, retain outlier chunks and a local window exactly, and reconstruct only the top- k k chunks selected by the current query. A persistent buffer reuses chunks selected across consecutive decoding steps. We additionally replace the exact key cache SVD with a randomised Cholesky-QR decomposition, giving a 4 × 4\times speedup with no loss in downstream quality ( Chang et al., 2026 ) . We evaluate on RULER ( Hsieh et al., 2024 ) and LongBench ( Bai et al., 2024 ) , and additionally report LongBench filtered to sequences of at least 10K tokens. For this subset we exclude tasks with fewer than 20 samples meeting the length requirement. Appendix G gives per-task statistics. All results are reported as recovered performance relative to the uncompressed baseline. We evaluate across three model families: Mistral-7B-Instruct-v0.3 ( Jiang et al., 2023 ) , Llama-3.1-8B-Instruct ( Grattafiori et al., 2024 ) , and Qwen3.5-4B ( Qwen Team, 2026 ) . Qwen3.5-4B is a hybrid architecture that interleaves full attention with linear attention layers; only the full attention layers maintain a conventional KV cache, so LowRAM is applied to that subset of layers alone, and the compression ratios we report for Qwen3.5-4B are relative to that subset’s cache rather than the whole model’s. Eviction. When combined with LowRAM, we apply eviction before fitting the map, discarding tokens unlikely to be attended to so the MLP need only reconstruct and store residuals for the tokens it retains. Importance is estimated with a small CNN predictor adapted from Yang et al. (2025b) : during prefill, a pre-hook on each attention layer scores every token by predicted future attention (averaged across heads), and we retain the top- ρ ​ T \rho T positions by this score, with attention sinks (first 8 tokens) and a local window (last 64 tokens) kept unconditionally. Quantisation. We quantise with TurboQuant ( Zandieh et al., 2026 ) , omitting the 1-bit QJL ( Zandieh et al., 2025 ) error-correction step. Section 3.3 introduced one mechanism targeting each; here we measure their effect on latency, throughput and accuracy. Meta-learning the MLP initialisation reduces per-context adaptation to 2 gradient updates, lowering the time-to-first-token (TTFT) overhead of the amortised value cache to 1.3 × \times that of the uncompressed baseline, down from 26.3 × \times with 150 updates and 55.5 × \times with 300 (Figure 6 ). Figure 4 compares the decode throughput of the baseline with that of LowRAM with selective reconstruction (LowRAM-SR) at 4 × \times compression. The baseline is faster at small batch sizes, but it quickly becomes memory-bound and plateaus, while LowRAM-SR continues to scale. The crossover occurs earlier at longer contexts, and beyond it the gap widens until the baseline runs out of memory. LowRAM-SR supports a batch size of 28 at all three context lengths and, at 262K tokens, reaches roughly 5 × \times the peak throughput of the baseline. Quantisation combines particularly well with our method, increasing both the overall compression ratio and recovered performance. For Mistral on LongBench, for example, adding quantisation to the 4 × \times LowRAM cache raises compression to 6.4 × \times and recovery from 97.9% to 99.4%. The benefit is largest where LowRAM alone degrades most, e.g. raising recovery for Llama on RULER at 4 × \times from 93.9% to 99.4%. We attribute this to two factors. First, storing residuals at lower precision reduces the memory each one requires, so LowRAM can retain more residuals within the same budget. Second, in most configurations quantisation alone introduces very little error, so the gain from additional residuals outweighs the error it adds. The exception is Llama on LongBench, where quantisation alone recovers only 96.3%. In this case the additional error is not fully offset, and adding quantisation lowers recovery at every compression ratio. Within each attention head, values are largely predictable from their keys. A small per-head predictor fitted to the context, with exact residuals kept for the tokens it reconstructs worst, stays close to lossless at 4 × 4\times value compression and holds up better on LongBench than low-rank compression of the same cache (Table 5 ). Pairing it with low-rank keys gives LowRAM, which remains close to baseline at moderate compression and combines with quantisation and eviction to reach 26.9 × 26.9\times on long contexts. The ablations suggest why prediction suits values. The key-to-value map appears strongly head-specific (sharing one predictor across a layer’s heads costs almost 20 points, Table 7 ). Keys are harder to predict, and their errors are likely more harmful: a key error perturbs the attention logits and can shift attention onto the wrong tokens, whereas a value error enters only after the attention weights are fixed. This matches findings on asymmetric KV quantisation ( Tao et al., 2025 ) and may explain why reconstruction error tracks downstream performance so poorly (Figure 3 ). Residual placement also matters: at a fixed budget, error-ranked selection recovers almost all accuracy, whereas random selection loses most of it (Figure 5 ). LowRAM is best suited to long contexts. The predictor’s parameters are a fixed cost that is only amortised after a few thousand tokens (Figure 8 ). This is why LowRAM degrades more on 4K RULER than on LongBench, and why it combines less cleanly with eviction, which shortens the sequence but leaves this cost unchanged. The choice of initialisation adds a second trade-off. Meta-learning brings prefill close to baseline speed at a small cost in accuracy, while full per-context fitting is slower but more accurate. Since both components of LowRAM depend only on the context, the slower option becomes attractive whenever a context is reused, as in document QA or shared-prefix serving, because the fitting cost is paid only once. 6 Limitations and Future Work We have not evaluated long generations, which would require periodically compressing the suffix of newly generated tokens (e.g. every N N tokens) rather than relying on a single prefill-time fit. It is also unclear how much of the learned parametrisation persists across contexts: gains from warm-starting and Slim Attention initialisation suggest part of the key-to-value relationship is shared, while gains from test-time adaptation indicate a remaining context-specific component. Understanding this split, and whether hard-to-predict tokens are stable across contexts, could enable more efficient allocation of memory and computation. AI Use Statement. Appendix A Extended Related Works A.1 Test-time Adaptation and Learned Associative Memory A separate line of work reframes sequence modelling itself as online learning at inference. The motivating observation is that the distribution of sequences encountered at test time differs substantially from the training distribution, and that a model which can fit itself to the stream it is currently processing should enjoy better in-context performance. Test-time training ( Sun et al., 2020 ) gives this idea a concrete architectural form. Rather than maintaining a fixed memory state, Sun et al. (2025b) treat the state itself as the parameters of a small predictive model, updated during inference by a self-supervised reconstruction loss over the incoming tokens. This makes the memory a sequence-specific map learned online, rather than a hand-specified accumulation rule or a static summary of the past. Titans ( Behrouz et al., 2025 ) similarly add a neural long-term memory trained at test time, using a surprise-based gradient update and adaptive forgetting mechanism, and combine it with short-window attention for longer-range storage. This view has roots in Fast Weight Programmers ( Schmidhuber, 1992 ; Schmidhuber, 1993 ) , where a slow controller network writes key-value associations into fast weights. Schlag et al. (2021) later showed that linear attention ( Katharopoulos et al., 2020 ) can be interpreted as such a fast-weight memory, with later variants improving the write rule using delta-style corrections and gates ( Yang et al., 2024b ; Yang et al., 2024c ; Yang et al., 2025c ) . We inherit the core abstraction of this line (a map from keys to values trained by a reconstruction loss) but not its deployment regime: the map is fit once, after prefill, to the completed KV cache of a pretrained Transformer, and neither the base model nor the attention computation is modified at inference. To test whether the choice of which tokens receive residuals matters beyond the residual budget itself, we compare four selection strategies at equal budgets on RULER NIAH-Multikey-1 (4K tokens) with Llama-3.1-8B-Instruct. Appendix F Selective Reconstruction To reduce decode-time compute, we adopt landmark-guided selective reconstruction, following ShadowKV ( Sun et al., 2025a ) : rather than reconstructing the full key/value cache at every decode step, we retrieve and reconstruct only a query-dependent subset of tokens, using inexpensive per-chunk landmarks as a cheap proxy for full attention when deciding which tokens to retrieve. Prefill: landmark construction and exact retention. During prefill, keys are partitioned into fixed-size chunks of c c tokens, and a landmark is computed for each chunk as the mean of its keys. Two subsets of chunks are then set aside and kept exact (both keys and values, uncompressed) rather than represented by their landmark: the o o chunks whose keys are least similar to their own landmark (outlier chunks, as in ShadowKV), and the chunks overlapping the most recent w w tokens (a local window; unlike the landmark and outlier mechanism, this is not part of ShadowKV’s original design). The remaining chunks form the landmark pool used for query-time retrieval at decode time. This exact retention is not free: the landmarks, their chunk indices, and the outlier/local exact keys and values are all additional persistent state on top of the compressed key cache itself. Rather than reporting a compression ratio that ignores this, we account for it directly in rank selection. Because xKV shares one low-rank factor across every layer in a group rather than factorising each layer independently, this overhead is measured per layer but spent per group: at the point a group’s decomposition is triggered, we sum the selective-reconstruction overhead of every layer in the group and subtract it from the byte budget implied by the group’s target compression ratio before choosing the shared rank, so the group’s realised ratio (low-rank factors plus the combined overhead of its member layers) matches the configured target. We additionally accelerate the low-rank key decomposition using a custom randomised SVD kernel adapted from xKV ( Chang et al., 2026 , Appendix C.2) , which executes power iterations in 16-bit precision and replaces Householder QR with a parallelisable shifted Cholesky-QR factorisation, in place of exact SVD when factorising the key matrices. This modification leads to a 4 × \times speedup over exact SVD without harming performance. Decoding: landmark-guided retrieval. Landmarks are computed per key/value head, so under grouped-query attention we pool scores across each group of query heads sharing a head by taking the max, before selecting chunks. At each decode step, the incoming query is scored against every landmark in the pool, and the top- k k chunks (a chunk budget k k , equal to the token budget in Table 14 divided by chunk size c c ) are retrieved and expanded back into token positions. The retrieved positions are combined with the exact outlier and local positions; keys and values, though compressed independently, are reconstructed at this shared set of positions. Persistent reconstruction cache. Following ShadowKV, we avoid redundant reconstruction work across decode steps by keeping a persistent buffer of the k k most recently reconstructed chunks (capacity k × c k\times c tokens). At each step, the newly selected chunk set is diffed against what the buffer already holds: chunks selected again are reused as-is, and only chunks newly entering the selection are reconstructed and written into the buffer. This is implemented via fused CUDA kernels adapted from ShadowKV/xKV.
