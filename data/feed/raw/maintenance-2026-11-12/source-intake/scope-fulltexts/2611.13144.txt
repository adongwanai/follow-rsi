We ask whether a stronger LLM teaches a fixed student better when it applies this principle. The student is an LLM agent acting through a harness that fixes its tools, context, and action budget, so a procedure that helps one model can exhaust the budget of another. We introduce Student-Aware Teaching ( SAT ). The teacher builds a learner model that pairs an empirical profile with hypotheses about the student’s limitations, tests these hypotheses with diagnostic probes, and writes reusable skills for the diagnosed failures. A skill enters the library only after it raises success on matched development tasks. With Claude-Sonnet-5 teaching DeepSeek-V4-Flash, SAT reaches 86.46% task success across four primary runs, leading both a profile-free teacher with the same framework (81.04%) and the untaught student (75.00%) in each run. Removing the analytical learner model lowers both prediction and success, and under misleading learner profiles none of the 48 candidate skills passes admission. When DeepSeek-V4-Flash and Gemini-3.8-Flash exchange libraries, each performs better with its own. Saved libraries keep average gains of up to 11.1 points after the teacher leaves. The benefit depends on a student that can follow instructions and a deployment route that delivers them. K eywords LLM agents ⋅ \cdot Agent skills ⋅ \cdot Machine teaching ⋅ \cdot Theory of mind ⋅ \cdot Agent harnesses 1 Introduction Many large language model (LLM) agents now pair a model with a harness ( Yao et al., 2022 ; Yang et al., 2024 ; Wang et al., 2025a ; Anthropic, ; OpenAI, ) . A harness is the software layer around the model. It supplies tools, runs a multi-step action loop, manages the context, and caps how many actions the model may take. These components make execution far more complicated than answering a single prompt. A model may know how to restock an inventory and still fail because it spends its allowed actions querying items one at a time. A model may know how to rename files and still leave a nested directory untouched. Many agent failures are failures of execution through a specific harness. This shift also complicates how competence is transferred. Knowledge distillation and machine teaching mostly target the model itself, by updating its weights or choosing its training examples ( Hinton et al., 2015 ; Hsieh et al., 2023 ; Zhu, 2015 ) . Yet smaller models are increasingly deployed inside harnesses while stronger models remain available at higher cost ( Belcak et al., 2025 ) , and many deployed models cannot be retrained by their users. The model is also not the only component that can learn. The harness can receive knowledge from an external source as reusable procedures, often called skills, which it loads at run time to guide a fixed model’s actions. Skills are readable, cheap to store, and easy to replace. Recent work already learns such skills from execution ( Zheng et al., 2025 ; Yang et al., 2026 ; Alzubi et al., 2026 ; Ni et al., 2026 ) . These methods mostly learn from the agent’s own failures or optimize skills against a task metric, and less attention has gone to what a teacher should know about the particular model and harness it teaches. We study this question with skills that the harness supplies as advisory context, keeping the model weights and harness code fixed. The hard part is deciding what a skill should say. Advice to verify every intermediate result helps a student that loses track of its state. The same advice exhausts the action budget of a student that already verifies too often. A useful lesson therefore depends on the learner. Theory of Mind describes the capacity to infer the latent state of another agent from its behavior and to use that inference to anticipate what it will do ( Premack and Woodruff, 1978 ) . Developmental research links this capacity to teaching, since a teacher must reason about what the learner knows and where it will go wrong ( Strauss et al., 2002 ; Wellman and Lagattuta, 2004 ) . In practice this reasoning forms a teaching loop. The teacher keeps a working estimate of the student’s state, updates it from the student’s responses, and uses it to choose the next lesson, so the quality of teaching depends on the quality of that estimate. This view fits harness teaching especially well. The limits that matter live in the execution procedure, such as how many updates fit in the action budget, and a teacher can see them only by modeling how this student acts through this harness. We therefore ask: does a teacher model write better skills when it first models the student it teaches? Student-Aware Teaching ( SAT ) takes this teaching loop as its design basis. The learner is a student model paired with its harness. The teacher maintains a learner model with two parts: an empirical profile records what the student does, and an analytical learner model holds hypotheses about why it fails. The teacher tests these hypotheses with controlled probes, such as inventories of increasing size, and writes skills for the diagnosed failures. A candidate enters the library only if it raises the student’s success on matched development tasks. After teaching, the teacher leaves and the student works with the saved library alone. Our study focuses on three research questions. • RQ1 (teaching quality). Does an explicit model of the learner produce better skills than teaching from the same types of execution feedback alone? • RQ2 (teaching content). What does a student-aware teacher teach differently, and are its lessons specific to their student? • RQ3 (realizing the benefit). Does the curriculum keep helping after the teacher leaves, and which delivery routes, students, and harnesses turn it into a gain? We compare SAT with an agnostic teacher that uses the same skill generation and admission framework and learns from its own failed trajectories, but has no learner model or probes. SAT leads it in all four primary runs ( RQ1 ). False-profile and library-swap controls provide additional evidence that teaching benefits from learner-specific information ( RQ1 , RQ2 ). Saved libraries keep average gains of 5.6 to 11.1 points with the teacher absent. The gain is realized when the delivery route suits the student and the student can execute procedures. Mid-sized open students benefit most, while the smallest cannot ( RQ3 ). Our contributions are as follows. • We formulate agent teaching as building a validated skill library for a fixed model and harness, separating teaching quality from how skills are delivered after the teacher leaves. • We propose SAT , which puts a Theory-of-Mind view of teaching into practice. Its learner model pairs an empirical profile with analytical hypotheses, probes test those hypotheses, and matched admission tests validate each lesson. • We show that learner-conditioned teaching improves a fixed student over profile-free teaching, particularly when failures arise from execution constraints. Controls with misleading profiles and exchanged libraries support the role of learner-specific information, and student capability and skill delivery determine whether the gain is realized. 2 Related Work Learner modeling in teaching. Theory of Mind research argues that a teacher must reason about a learner’s knowledge, ignorance, and misconceptions ( Strauss et al., 2002 ; Wellman and Lagattuta, 2004 ) . Knowledge tracing and machine teaching formalize instruction for a modeled learner ( Corbett and Anderson, 1994 ; Zhu, 2015 ) , and Iterative Machine Teaching and its black-box extension choose examples from the learner’s estimated state ( Liu et al., 2017 ; Liu et al., 2018 ) . Machine Theory of Mind and false-belief tests for LLMs study whether models can predict other agents ( Rabinowitz et al., 2018 ; Kosinski, 2024 ) . SAT uses the idea in a functional sense. Its learner is an LLM paired with its harness, so the state to estimate includes execution limits such as how many updates fit in the budget. Transferring competence to a fixed model. Knowledge distillation and its variants train a student on teacher predictions, rationales, or feedback on the student’s own samples ( Hinton et al., 2015 ; Hsieh et al., 2023 ; Agarwal et al., 2024 ) . These methods update weights, while SAT writes an external library that can be inspected and edited and that reaches students with inaccessible weights. Prompt optimization refines instructions or pipelines from textual critiques, task metrics, or execution traces ( Pryzant et al., 2023 ; Yuksekgonul et al., 2024 ; Khattab et al., 2023 ; Agrawal et al., 2026 ) . Our agnostic baseline generates skills from traces, verifier outcomes, and development feedback. SAT adds an explicit learner model that guides diagnostic probes and skill generation. Agent memory, skills, and harnesses. Experience-based methods store lessons from an agent’s own runs as verbal feedback, insights, workflows, or playbooks ( Shinn et al., 2023 ; Zhao et al., 2024 ; Wang et al., 2024 ; Ouyang et al., 2026 ; Zhang et al., 2026 ) . Skill libraries range from executable code ( Wang et al., 2023 ; Wang et al., 2025b ) to skills that stronger agents pass to weaker ones ( Zheng et al., 2025 ) . SkillOpt and EvoSkill revise natural-language skills for a frozen agent from execution failures and keep an edit only when held-out validation improves ( Yang et al., 2026 ; Alzubi et al., 2026 ) . Trace2Skill consolidates lessons from many trajectories into declarative skills that transfer across models ( Ni et al., 2026 ) . Other work shows that the agent-computer interface shapes performance ( Yao et al., 2022 ; Yang et al., 2024 ) and searches agent, workflow, or harness code ( Hu et al., 2025 ; Zhang et al., 2025 ; Lee et al., 2026 ) , including harnesses built by strong models for weaker targets ( Qian et al., 2026 ) . SAT asks what an explicit student model and diagnostic probes add to learning skills from failures. Our library exchange tests how much of a learned library is specific to its student. In each round the student attempts teaching tasks, and the teacher updates its model of the student, tests it with diagnostic probes, and writes candidate skills that must pass an admission test. After preparation the teacher leaves, and a selector delivers the saved skills to new tasks. Figure 1: Student-Aware Teaching. The learner is a student model operating through its existing harness. At deployment the teacher is absent and a selector delivers the saved skills. The aware teacher maintains a learner model σ \sigma with two parts. The empirical profile records what the student does. At each round the student attempts a batch of teaching tasks with its current library, and the teacher updates category-level success statistics, failure labels, and notes (Appendix A ). The analytical learner model records why the student fails. Observed failures rarely identify their own cause, so the teacher keeps hypotheses about latent execution constraints. Each hypothesis stores a proposed mechanism, a confidence, supporting evidence, and a status. For example, the teacher may hypothesize that repeated stock queries consume the action budget before all updates finish. The learner model also yields a prediction p ^ σ ​ ( x ) \hat{p}_{\sigma}(x) of whether the bare student will solve task x x . We score these predictions with Brier and AUROC on a fixed calibration panel. Controlled probes as hypothesis tests. Passive observation can support several explanations for one failure. An inventory failure may come from misreading the task, missing a deficient item, or running out of actions. SAT therefore makes learner modeling active. The teacher requests probes that vary one supported property within a task family, such as inventory size or file count. The bare student attempts each variant, which is rebuilt with its own verifier. If success falls as size grows, the evidence points to an execution-budget limit and the transition records a sampled boundary. The outcome updates the learner model and steers the teacher toward simpler procedures. Skill generation. The teacher proposes up to three candidate skills per round, each a short natural-language procedure with a target category and applicability metadata (Appendix A ). The aware prompt receives the learner model, weak-category priorities, and probe evidence, while the agnostic prompt receives tasks and failed traces from its own condition. Both forbid copying task-specific answers. Skills are delivered as advice, and the student chooses its own actions. 3.3 Admission and deployment A candidate s s is tested on one to four development tasks P s P_{s} from its category. No selector sees test outcomes. 4 Experimental Setup Base harness. Our base harness is a compact planning harness. It first asks the student for a plan and then runs a tool-calling loop of at most ten iterations. It truncates long tool observations and keeps a limited window of recent messages, so action budget and context loss are real constraints. Skills enter as advisory text ahead of the task instruction. Unless a result states another selector, skills reach the student through category routing, both during teaching and in the reported evaluations. Tasks. We use five task suites. A generator builds each task together with its working environment and a programmatic verifier. The suites target different ways an agent can fail inside a tight harness. • Terminal. Shell tasks such as recursive renaming, sorted numeric merges, and staged file pipelines, which test coverage of the environment. • Inventory API. Restocking every item below a threshold through list, query, and restock tools, which tests action economy. • Arithmetic. Word problems on discounts, mixtures, and rates, which test task semantics. • Python code. Function implementation and bug repair, which test program correctness. • Dependent workflows. Chains of file stages that each consume the previous output, which test state tracking. Main setting and experiments. Runs S1 through S4 use Claude-Sonnet-5 ( Anthropic, 2026 ) as teacher and DeepSeek-V4-Flash ( DeepSeek-AI et al., 2026 ) as student. Each run uses 60 teaching tasks, 30 development tasks, and four teaching rounds. The final evaluation executes 60 held-out tasks, twelve per suite, twice each. Every experiment compares no skill, agnostic teaching, and aware teaching ( SAT ) under the same student and harness. RQ1 adds two component ablations and a false-profile control, which replaces the learner model with a frozen and deliberately wrong profile. RQ2 analyzes skill bodies, an eight-round extended run, and a library swap between DeepSeek-V4-Flash and Gemini-3.8-Flash ( Doshi and Popa, 2026 ) . RQ3 evaluates frozen libraries under three selectors with the teacher absent and varies the student across Qwen3 ( Yang et al., 2025a ) , Qwen2.5-Instruct ( Yang et al., 2025b ) , GPT-5.4-Mini ( OpenAI, 2026 ) , and Gemini-3.8-Flash. Further experiments cover production harnesses, MATH and GSM8K subsets ( Hendrycks et al., 2021 ; Cobbe et al., 2021 ) , and self-teaching. Only S1 through S4 enter the primary mean. We report acceptance , the percentage of held-out executions whose final result passes the task’s verifier (Appendix J ). 5 Results We present results in the order of the three research questions. Both teachers see the student fail, and both can write useful procedures. The learner model changes which procedure the teacher chooses. A failed inventory task is consistent with misreading the task, missing an item, or running out of actions, and each reading suggests a different lesson. When the teacher’s model and probes point to the action budget, it writes a bulk query. When they point to incomplete coverage, it writes recursive discovery. The results line up with this account. Gains concentrate in suites where execution constraints bind, ablating the analytical model or the probes lowers acceptance, misleading profiles yield no admissible skill, and each student does better with its own library. In the language of Theory of Mind, the teacher benefits from anticipating how this particular student will act. None of these controls alone isolates learner modeling as the only source of the gain, but they point in the same direction as the main comparison. Scope. Most evidence comes from one teacher and student pair in one base harness, with few seeds for the controls and deliberately extreme false profiles. Deployment results depend on the selector, and the production and exploratory experiments carry the caveats stated beside them. The learner model also has natural limits: it cannot help a student too small to execute procedures, and it adds little for a student near ceiling. Matched replays of teaching evidence, milder profile errors, more seeds, and dedicated studies in production harnesses are the natural next steps. 7 Conclusion We asked whether a teacher model teaches better when it first models its student. Across four primary runs, Student-Aware Teaching improves over profile-free teaching, with the largest gains on tasks that involve constrained execution. Its saved libraries keep helping after the teacher leaves. Ablations, misleading profiles, and exchanged libraries all support the role of learner-specific information, which Theory of Mind research places at the center of human teaching. Modeling whom it is teaching can help a teacher decide which procedures to teach. Cited by: §1 , §2 . Appendix A Additional Method Details A.1 Learner model For each teaching round, the student attempts a batch using its current library. The aware profile tracks successes and failures per category. For category c c , its Beta-Bernoulli summary begins with α c = β c = 1 \alpha_{c}=\beta_{c}=1 . Observed successes increase α c \alpha_{c} and failures increase β c \beta_{c} . The profile also stores failure counts and short teacher notes. Because the library changes across rounds, these statistics describe the student under an evolving curriculum. They should be read as estimates of the taught student, which differs from the bare model. The analytical learner model stores a textual mechanism summary and a bounded set of hypotheses. Each hypothesis includes a claim, a confidence, supporting evidence, and a status. Additional fields hold inferred or measured task boundaries. The teacher uses this state to target a recurring execution problem. For example, it may suspect that repeated stock queries exhaust the action budget before all updates are issued. Analytical updates are stored separately from the empirical profile, which lets us examine observed behavior and its proposed explanation separately. How the learner model changes a teaching decision. The empirical profile includes category performance, observed failure modes, teacher notes, and probe outcomes. These components can guide teaching before a detailed explanation is available. A low inventory success rate can motivate a lesson on completing stock updates within the action budget. Repeated intermediate reads can motivate consolidated execution. Missing nested files can motivate recursive discovery. The same task can support several plausible lessons. A student that omits necessary checks may need an explicit completion test, while a student that repeatedly checks finished work may need fewer checks. The learner model tells the teacher which of these lessons fits. A.2 Controlled probes Probes vary a supported task property while preserving the task family. Implemented axes include inventory size and file count for search tasks. The generator rebuilds each variant and recomputes its verifier. The bare student attempts a small ordered set of property values. Analytical hypotheses can guide these diagnostics, and empirical failures can trigger probes before any explanation exists. A transition from observed success to observed failure is recorded as a sampled boundary. For example, passing at 12 items and failing at 16 brackets a transition over those tested instances. All-pass, all-fail, and nonmonotonic sweeps are recorded as inconclusive. A.3 Skill generation and representation The teacher proposes up to three skills per round. The prompt requests concise reusable procedures and prohibits copying task-specific answers. Each body is limited to 900 characters. Skills have four native types: content, process, affordance, and plan. A record stores its body and target category together with harness scope, provenance, and a validation summary. Applicability metadata can name task families and failure modes, and an optional field holds a student-specific rationale. The aware teacher receives the statistical profile, the available analytical learner model, and a focus list of weak categories. The agnostic teacher receives tasks, verifier information, eligible execution traces, and prior skills from its own condition. A generation request includes up to six task descriptions and four failed traces. Plan records can contain structured directives. In all complete packages reported here the delivery mode is advice, so the harness injects skill text and the student chooses its actions. The implementation also supports controller-enforced plans, which we leave for future evaluation. A.4 Empirical skill admission A candidate skill s s is evaluated on up to four development tasks matching its category. Each task is executed with the candidate and with an empty library, giving the standalone utility in Equation 2 . Candidate validation uses temperature zero. A candidate with no matched task is rejected, and a positive estimate admits the skill. Admission can deactivate a generic seed in the same category, and the library keeps at most two active skills per category. Up to two off-category tasks estimate interference with the same paired comparison. This quantity is logged for analysis only. Because the gate measures each candidate against an empty library, we evaluate complete libraries separately at test time. A.5 Selection after teaching The saved artifact contains the library and the learner model. The deployment experiment removes the teacher and evaluates three routes. • Student selection. The student reads a metadata menu and returns at most two valid skill identifiers. It sees the task’s category label, the first 400 characters of the instruction, and a short preview of each body. Selected bodies are injected before execution. • Category routing. A deterministic rule matches the task’s category or suite tag and selects up to two skills by validation utility. Logs call this route oracle . • Flat injection. Every active skill is supplied to the student. Category routing uses task metadata and has no access to test outcomes. Deployment on untagged tasks is a natural extension. A.6 Evaluating the student model The teacher can predict bare-student success on calibration tasks. Brier score measures squared probability error. Predictions are scored on a panel of ten calibration tasks. Task success remains the primary measure of whether a curriculum helps the student. Appendix B Base Harness and Task Suites Base harness. The compact planning harness runs one episode per task. It first asks the student for a short plan, then enters a tool-calling loop of at most ten iterations. Each iteration lets the student call one tool or finish. Tool observations are truncated to 400 characters. The context keeps the system message and the six most recent conversational messages, so earlier observations drop out of view in long episodes. Supplied skills are injected as advisory text before the task instruction, and the student decides whether and how to follow them. The harness itself never changes during teaching. The same harness executes teaching, development, probe, and test tasks for every condition. Task generation. Each suite has a seeded generator that builds a task instruction, its working environment, and a programmatic verifier. A frozen collection fixes the teaching, development, and test splits before any teaching begins, and all conditions within an experiment share one collection. Probes call the same generators with one property changed, such as the number of inventory items or the number of files to search, and rebuild the verifier for each variant. C.5 Verification as a conditional teaching decision Several chain skills in S2 through S4 combine reading, computation, and writing in one shell action. They discourage a separate read for every intermediate value and defer verification. The Qwen3 aware chain skill asks the student to check each output file before proceeding, and its inventory skills add explicit checks after updates. Within one main-setting aware library, the chain skill suppresses intermediate checks while the pipeline skill asks for one check per stage. These bodies expose a concrete teaching choice about which checks a student should perform under a constrained budget. A label such as verification is therefore most informative when paired with its timing and target. C.6 Admission support The aware rename procedures repeatedly address recursive discovery and exact extension replacement. Eight of twelve complete main-setting aware skills were admitted using one matched task, and the other four used four tasks. For agnostic teaching, three skills used one task, one used two, and six used four. Development splits contain one rename task each, which is reused across rename candidates. Larger development pools would sharpen utility estimates for narrow categories. Self-teaching. This experiment asks whether a strong external teacher adds value beyond cheaper alternatives that reuse the student’s own backbone. We compare three teaching conditions against a no-skill baseline, all given identical task inputs and differing only in who produces the skills. In self-improvement , the student reflects on its own failures and writes its own skills, with no separate teacher. In self-aware teaching, a teacher reasons about the student but runs on the student’s own backbone, a low-cost stand-in for a strong teacher. In aware teaching, a strong external teacher model builds an explicit model of the student and generates skills from it. The setup has 36 task identities with two executions each, for 72 executions per condition. No-skill reaches 72.22%. Self-improvement reaches 81.94% (a gain of +9.7 points over no-skill, 95% CI [+1.4, +19.4]). Self-aware teaching reaches 79.17% (+6.9 points, 95% CI [ − 1.4 , + 18.1 ] [-1.4,+18.1] ). The external aware teacher reaches 83.33% (+11.1 points, 95% CI [+1.4, +23.6]). Self-improvement and aware teaching each clear zero over the baseline; self-aware does not. Same-backbone self-improvement is therefore a strong baseline. The external teacher’s margin over it is 1.39 points, which corresponds to one accepted execution out of 72, so on this single seed the advantage of the external teacher over self-improvement is small and should be read as exploratory. We also note that self-improvement incurred six skill-generation failures, whereas both teacher-driven conditions generated skills without errors. Each main run executes 60 distinct teaching records. Generation prompts expose subsets of task descriptions and trace summaries, and profiles and development feedback add further evidence. The 30 development records cover categories unevenly. Each run has one development task per terminal category and six inventory tasks, while code and arithmetic counts vary. Evaluation protocol. Every teaching round evaluates the same frozen test split, and unless otherwise stated, results report the final round. This fixes the reporting point in advance and avoids selecting the best intermediate score. A task’s score is the fraction of its two executions that the verifier accepts, so it is 0, 0.5, or 1. Acceptance is the mean task score over the held-out tasks, reported as a percentage, and run-level standard deviations are computed across runs.
