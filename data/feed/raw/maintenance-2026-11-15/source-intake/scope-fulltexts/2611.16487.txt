Affiliation: Department of Computer Science and Engineering, Sungkyunkwan University Affiliation: Department of Artificial Intelligence, Sungkyunkwan University Email: hwoo@skku.edu Abstract Embodied agents make decisions by combining information from heterogeneous memory modules, including declarative memory for explicit knowledge, procedural memory for learned routines, and working memory for current observations.
During interaction, the memory contents required for decision making change with the agent’s state, goal, and task progress, while many contents remain shared across consecutive decisions.
However, existing memory modules are typically accessed through separate interfaces, so each updated memory context is often processed as a new input to the foundation model.
This prevents selective key-value (KV) cache reuse for unchanged memory contents and forces full KV cache recomputation even when much of the memory context remains valid.
We introduce HeMeR , an inference framework that performs KV reconciliation between dynamically updated memory contexts and reusable KV states. HeMeR tracks declarative, procedural, and working memory contents across action decisions, preserves KV states for unchanged contents, and reconciles only the KV states affected by memory-content updates.
This enables efficient and stable inference as memory contents evolve during interaction.
We evaluate HeMeR on ALFWorld, Habitat, and real-world robotic deployments requiring coordinated use of heterogeneous memory contents.
In the real-world setting, HeMeR achieves 83.20 % 83.20\% task success and reduces per-step inference time from 2.94 2.94 to 1.87 1.87 seconds compared with MemRL, while preserving compatible KV states as task progress updates the memory context. 1 Introduction Embodied agents increasingly build on foundation models, using language or vision-language models to interpret observations, reason about goals, and select actions [ 1 , base:react , embodied:llmplanner , 13 , embodied:progprompt , embodied:voyager ] .
However, embodied tasks often require information beyond immediate observations, including explicit environmental knowledge, learned behavioral routines, and ongoing task progress [ 13 , embodied:progprompt , embodied:voyager , embodied:reflexion ] .
Accordingly, recent studies augment foundation models with memory modules that store, retrieve, and update task-relevant memory contents across interactions [ embodied:voyager , embodied:reflexion , method:genagent , serve:memgpt , mem:memorybank ] .
These modules help agents preserve continuity over long-horizon tasks, but also make each action decision depend on memory contents that change with accumulated experience, current observations, and task progress. Recent memory-augmented agents use heterogeneous memory modules that maintain distinct forms of memory content for embodied decision making [ base:react , embodied:voyager , method:genagent , embodied:coala ] .
A declarative memory module maintains explicit content about environmental objects, relations, and task conditions, often as structured representations such as symbolic facts [ method:genagent , serve:memgpt , mem:amem , 7 ] .
A procedural memory module maintains learned behavioral routines that guide future actions [ embodied:progprompt , embodied:voyager , mem:procedural , 6 ] , including parametric representations such as neural adapters [ 11 ] .
A working memory module maintains content about the current task state, including recent observations, intermediate decisions, and goal progress [ base:react , 13 , mem:working ] .
Although these modules are often studied through separate storage, retrieval, and update mechanisms, action selection requires their contents to be composed into a memory context.
The resulting memory context is processed by the foundation model to form transformer KV states during inference [ mem:kv , serve:vllm ] .
As the agent receives new observations and progresses through the task, the memory context must be updated while many memory contents remain unchanged across consecutive decisions. Figure 1: Motivation of HeMeR . Environment changes can trigger memory-content updates, including procedural changes that switch the active adapter.
A naive implementation recomputes the full KV cache, whereas HeMeR updates affected KV ranges and reuses compatible KV states. This modular separation is well motivated, since each memory module serves a distinct role in embodied decision making [ embodied:coala , mem:procedural , mem:working , mem:episodic ] .
However, after memory contents from multiple memory modules are composed into a single memory context, the foundation model must process this memory context to form the hidden representations and KV states used for action selection [ mem:kv , serve:vllm ] .
As illustrated in Figure 1 , changes in the environment can trigger updates to declarative and working memory contents and procedural adapter switches, thereby changing the memory context across decision steps.
Such changes can make some previously cached KV states incompatible with the updated memory context, while others may remain reusable [ serve:cacheblend , serve:kvlink , serve:cacheslide , pos:rope , 14 , 15 ] .
Existing memory-augmented agents mainly focus on what to store, retrieve, and update, but do not explicitly address how to reconcile updated memory contexts with reusable KV states during foundation model inference [ serve:memgpt , mem:memorybank , mem:amem , 16 , mem:titans ] .
Without such reconciliation, a naive implementation processes each updated memory context as a new input and recomputes the full KV cache, causing redundant computation during long-horizon embodied interaction [ serve:kvlink , 12 , 17 , 5 ] . To address this problem, we introduce HeMeR , a memory-serving framework for embodied agents that reconciles dynamically updated memory contexts with reusable KV states during foundation model inference.
Although declarative, procedural, and working memory serve different roles, their effects on foundation model inference are ultimately reflected in the KV states used for action selection.
Rather than treating each memory context as a flat token sequence, HeMeR represents it as a sequence of structured memory chunks associated with corresponding KV ranges, providing a common basis for reconciling heterogeneous memory updates with cached KV states. HeMeR realizes this reconciliation through two complementary mechanisms, Chunk-Level KV Reconciliation for content-level changes and rearrangements within the memory context, and Adapter-Stable KV Reconciliation for procedural changes that alter the active adapter. Specifically, Chunk-Level KV Reconciliation handles updates to declarative and working memory contents by mapping content-level changes and rearrangements to their corresponding KV ranges. HeMeR identifies reusable KV ranges by tracking changes in memory contents and their dependencies, selectively recomputing only the affected ranges.
When an unchanged memory chunk shifts position, RoPE-based remapping preserves positional consistency, allowing its KV states to be reused [ pos:rope ] . Adapter-Stable KV Reconciliation handles procedural memory updates that alter the active adapter.
Because KV states computed under a previous adapter may become incompatible even when other memory contents remain unchanged, HeMeR treats the adapter configuration as part of the KV compatibility condition, selectively recomputing affected KV ranges while preserving compatible KV states across adapter switches.
By jointly reconciling memory content updates and procedural adapter changes without rebuilding the full KV cache, HeMeR supports efficient and stable inference over long-horizon embodied tasks. We evaluate HeMeR on unseen simulated tasks from ALFWorld [ 19 ] and EmbodiedBench Habitat [ ben:embodiedbench , 20 ] , where evaluation episodes require the agent to combine memory contents across different situations rather than rely on a directly applicable memory content.
We further evaluate HeMeR on real-world embodied tasks in a UR7e manipulation setup, requiring the agent to coordinate heterogeneous memory contents as procedures and task states change.
We highlight task success rate and inference time per decision step, with each step corresponding to one action selection.
On ALFWorld, HeMeR achieves a 71.43 % 71.43\% task success rate with 0.18 0.18 seconds per decision step, compared with a 52.86 % 52.86\% task success rate and 0.90 0.90 seconds per decision step for MemRL [ 26 ] , the strongest baseline in task success (Table 1 ).
On EmbodiedBench Habitat, HeMeR achieves a 76.27 % 76.27\% task success rate with 1.82 1.82 seconds per decision step, compared with a 61.80 % 61.80\% task success rate and 2.68 2.68 seconds per decision step for MemRL (Table 1 ).
In the real-world setting, HeMeR achieves an 83.20% goal-conditioned success rate with 1.87 seconds per decision step, compared with a 64.28% goal-conditioned success rate and 2.94 seconds per decision step for MemRL (Table 2 ).
These results show that KV reconciliation improves task robustness and inference efficiency as memory contexts change across embodied decision steps. We make the following contributions. • We formulate heterogeneous memory use as a KV reconciliation problem for foundation model-based embodied agents, where memory contents from declarative, procedural, and working memory modules change across action decisions while many contents remain reusable. • We introduce HeMeR , a heterogeneous memory reconciliation framework that anchors memory contents as typed chunks with KV ranges and selectively reuses compatible KV states. • We develop chunk-level and adapter-stable KV reconciliation mechanisms that update only affected KV ranges, preserve positional consistency under memory-content updates, and maintain compatible KV states across procedural adapter switches. • We evaluate HeMeR on ALFWorld, Habitat, and real-world robotic deployments, showing that it improves task success and reduces per-step inference time over strong baselines. 2 Related work Foundation Model-based Embodied Control. Recent studies use language and vision-language foundation models as general-purpose decision modules for embodied agents, enabling them to interpret observations, reason about goals, and select actions in interactive environments [ 1 , embodied:llmplanner , 13 , embodied:progprompt , embodied:voyager , embodied:ecot ] .
These agents are further augmented with memory modules to store and retrieve task-relevant memory contents across decision steps and adapt action selection over long-horizon interactions [ embodied:reflexion , mem:memorybank , 28 , 26 , 21 ] . HeMeR follows this line of work, but focuses on the inference problem that arises when memory contents from multiple memory modules are composed into a dynamically updated memory context that must be reconciled with reusable KV states across action decisions. Memory-Augmented Embodied Agents. Recent memory-augmented embodied agents introduce specialized memory modules for different roles in decision making.
Declarative memory modules maintain explicit content about environmental objects, relations, and task conditions [ method:genagent , mem:memorybank , mem:amem , 7 ] .
Procedural memory modules maintain learned behavioral routines, including reusable procedures and skills [ embodied:progprompt , embodied:voyager , mem:procedural , 6 , 10 , mem:automanual , 24 , 14 ] .
Working memory modules maintain memory content about recent observations, intermediate decisions, and goal progress during the current interaction [ base:react , 13 , embodied:coala , mem:working ] .
These memory modules help embodied agents preserve task-relevant memory content beyond immediate observations and adapt action selection over time.
However, existing studies mainly focus on how each memory module stores, retrieves, or updates its own memory content for a role-specific objective.
In contrast, HeMeR jointly handles memory contents from declarative, procedural, and working memory modules once they are composed into a single memory context, reconciling their updates with reusable KV states across action decisions. Efficient KV Reuse. KV caching is a standard mechanism for efficient autoregressive inference, in which previously computed KV states are stored and reused across decoding steps [ mem:kv , serve:vllm , serve:orca ] .
Prior work on KV reuse reduces inference cost by reusing cached KV states for repeated prefixes, shared prompts, or recurring context segments [ 12 , kv:promptcache , 8 ] .
Recent systems further exploit structured generation programs, retrieved context chunks, position-independent context segments, or embodied reasoning traces to reuse computation across related inference requests or decision steps [ serve:cacheblend , serve:kvlink , serve:cacheslide , serve:sglang , 9 , 23 ] .
Complementary work reduces KV cache storage requirements, transfer costs, or loading overhead through eviction, compression, streaming, or cache-layer management [ 17 , 5 , 27 , 22 ] .
In parallel, multi-adapter serving systems improve the efficiency of models augmented with LoRA adapters by batching requests, switching adapters, or reusing KV states across adapters during inference [ 11 , 14 , 15 , serve:slora , serve:punica , serve:dlora , 25 ] .
Building on these advances, HeMeR integrates KV reuse and multi-adapter serving techniques within a memory-serving framework to efficiently reuse KV states as memory contexts change across action decisions. 3 Problem formulation We consider a foundation model-based embodied agent that acts over a sequence of decision steps.

HeMeR indexes memory chunks, updates affected KV ranges, and preserves compatible cache states across decision steps. 4.1 Overall Architecture We present HeMeR , a heterogeneous memory reconciliation framework that enables foundation model-based embodied agents to process changing memory contexts without rebuilding the full KV cache, as illustrated in Figure 2 .
At each decision step, the agent obtains memory contents from multiple memory modules and composes them into a single memory context, which the foundation model uses together with the current observation and task goal to generate the next action.
During interaction, new observations may introduce memory contents, outdated contents may be removed, existing contents may be reordered, and the active procedural adapter may switch.
To handle these changes, HeMeR uses a memory schema to anchor each memory content as a typed memory chunk with an associated KV range.
It then reconciles memory-content updates through localized cache operations while preserving compatible KV states across procedural adapter switches. We distinguish three levels of memory representation: memory modules, memory contents, and memory contexts.
A memory module stores and retrieves a specific type of information, and each item retrieved at a decision step is a memory content.
A memory context is formed by composing multiple memory contents to support action selection.
In our setting, the agent uses declarative, procedural, and working memory modules.
Declarative memory stores explicit task and environment knowledge, such as object locations, receptacle relations, and task conditions.
Procedural memory stores reusable behavioral procedures, instantiated as LoRA adapters in our LRAgent-based implementation [ 14 ] .
Working memory stores the current interaction state, including recent observations, intermediate decisions, subgoals, and action history. Rather than treating the composed memory context X t X_{t} defined in Sec. 3 solely as a flat token sequence, HeMeR organizes it as a sequence of memory chunks.
Each memory chunk represents a single memory content, with schema-defined metadata linking it to a contiguous KV range after tokenization and encoding.
The memory schema records each chunk’s persistent ID, memory module type, semantic role, normalized content, dependency annotation, position, token span, and KV range, as well as its adapter identifier when applicable.
This index maps memory-content updates to their corresponding KV ranges, enabling HeMeR to reconcile the KV cache through localized operations on affected ranges.
The initial memory context is prefilled as a single causal sequence.
At subsequent decision steps, HeMeR prefills newly inserted memory chunks and selectively recomputes affected KV ranges at their positions in the current memory context, recording the resulting KV ranges in the memory schema. 4.2 Chunk-Level KV Reconciliation Chunk-level KV reconciliation aligns the previous KV cache with the memory contents in X t X_{t} .
As the agent progresses, memory contents may be inserted, evicted, or reordered, potentially altering token positions and dependencies in X t X_{t} .
Naive KV reuse is therefore unreliable, while rebuilding the full KV cache can introduce redundant computation when many memory contents remain unchanged. Schema-Guided Reconciliation. To address this trade-off, HeMeR uses the chunk-level index to compare memory chunks across consecutive decision steps.
Chunks in X t − 1 X_{t-1} and X t X_{t} are first matched by persistent chunk IDs, regardless of their positions or token spans.
Matched chunks are eligible for KV reuse only when their memory module type, semantic role, dependency annotation, normalized content, and adapter identifier (when applicable) agree.
Otherwise, their KV ranges are locally recomputed.
Given two consecutive memory contexts, HeMeR computes a schema-guided reconciliation plan Δ t = Diff 𝒮 ​ ( X t − 1 , X t ) , \Delta_{t}=\mathrm{Diff}_{\mathcal{S}}(X_{t-1},X_{t}), (6) where Diff 𝒮 \mathrm{Diff}_{\mathcal{S}} matches chunks by persistent IDs and checks schema compatibility.
Matched chunks with changed positions are reordered, chunks only in X t X_{t} are inserted, and chunks only in X t − 1 X_{t-1} are evicted.
The index maps these operations to KV ranges, so HeMeR updates only affected ranges. KV Operations and RoPE Remapping. Based on the reconciliation plan Δ t \Delta_{t} , HeMeR performs the corresponding KV operations.
New memory chunks are prefilled, while the KV ranges of evicted chunks are removed.
When chunks are reordered, HeMeR relocates their KV ranges according to the current X t X_{t} , reusing compatible KV states when possible.
These operations allow the KV cache to be updated without full recomputation. RoPE remapping is used only for matched chunks whose update is a position shift.
If a reusable token shifts from position p j p_{j} to p j ′ p^{\prime}_{j} , its cached key is updated as k ~ j = R θ ⁡ ( p j ′ ) ​ R θ ⁡ ( p j ) − 1 ​ k j , \tilde{k}_{j}=R_{\theta(p^{\prime}_{j})}R_{\theta(p_{j})}^{-1}k_{j}, (7) where k j k_{j} denotes the cached key at position p j p_{j} , R θ ⁡ ( p ) R_{\theta(p)} denotes the RoPE rotation at position p p , and k ~ j \tilde{k}_{j} denotes the remapped key at position p j ′ p^{\prime}_{j} .
This corrects the cached key’s positional phase under a pure position shift.
RoPE remapping updates only the cached keys.
For multimodal backbones, we restrict RoPE-based remapping to text-side memory chunks whose schema fields remain unchanged [ pos:rope ] .
Visual tokens from current observations are not position-remapped and are encoded normally at each decision step.
When content, dependencies, or adapters change, HeMeR recomputes the affected KV range to avoid stale reuse. Chunk-level KV reconciliation differs from prompt-level or segment-level cache reuse.
Prefix caching reuses only stable prefixes, Prompt Cache reuses segments computed without their preceding context, and CacheBlend-style reuse still relies on reusable segment boundaries and selective recomputation around them [ serve:cacheblend , serve:kvlink , kv:promptcache ] . HeMeR makes the same class of non-prefix reuse approximation, but grounds it in schema-indexed memory chunks and reuses a KV range only when the corresponding memory content remains schema-compatible.
Thus, HeMeR avoids both naive KV reuse and full KV cache recomputation by selectively reconciling KV ranges affected by memory-content updates across decision steps. 4.3 Adapter-Stable KV Reconciliation Procedural memory introduces a second source of cache incompatibility.
In our LRAgent-based implementation, procedural memory contents correspond to reusable behavioral procedures implemented as LoRA adapters.
When the procedural memory content changes across decision steps, the active adapter may also change.
Even if declarative and working-memory contents remain unchanged, KV states computed under the previous adapter may no longer be compatible with the new adapter configuration.
This issue is particularly important in embodied tasks, where agents switch among procedures such as searching, manipulating, cleaning, heating, cooling, and placing objects. Adapter-Aware Reconciliation. HeMeR maintains adapter identifiers as part of the chunk-level index.
For each procedural memory chunk, the index records the adapter under which its KV states were computed, and the reconciliation plan marks adapter switches as procedural updates.
When the active adapter changes, HeMeR recomputes the procedural memory chunk’s KV range and those of its direct and transitive dependents under the declared dependency annotations.
Other unchanged ranges are approximately reused under the shared-attention LoRA design.
This allows adapter switches to be handled within the same indexed reconciliation process without rebuilding the full KV cache. Cross-Adapter KV Compatibility. To stabilize cross-adapter reuse, HeMeR adopts the shared-attention LoRA design used by LRAgent.
The rank-8 adapters are applied to the query and value projections, with a low-rank down-projection shared across adapters and adapter-specific up-projections.
The key, output, and MLP paths remain shared, and the active adapter is applied to the entire forward sequence rather than only to procedural-memory tokens.
This design limits, but does not eliminate, cross-adapter drift.
Therefore, HeMeR includes the adapter identifier in its KV compatibility condition and recomputes the procedural memory chunk’s KV range while preserving ranges that remain compatible across the switch. While LRAgent primarily addresses KV cache reuse across adapter switches, HeMeR incorporates adapter compatibility into the same reconciliation process used for updates to declarative and working memory contents.
Such methods reduce overhead for procedural changes, but they do not explicitly address updates to declarative and working memory contents that arise during embodied interaction. HeMeR jointly handles both sources of change: adapter switches from procedural memory and chunk-level reconciliation of updates to declarative and working-memory contents.
Consequently, HeMeR preserves compatible KV states across heterogeneous memory-content updates while avoiding the need to rebuild the full KV cache at every decision step. 5 Evaluation 5.1 Experimental setting Environment. We evaluate on ALFWorld [ 19 ] , EmbodiedBench Habitat [ ben:embodiedbench , 20 ] , and Real-world, a UR7e manipulation setup.
Each evaluation episode is unseen in the sense that no single memory fragment covers the required procedure-room combination.
Solving these tasks therefore requires composing fragmented memories across different situations rather than retrieving a directly applicable past experience.
Real-world evaluation comprises two long-horizon tasks in two tabletop environments, with five independent physical repetitions per task, yielding 10 trials per method.
Initial object positions and instruction phrasings vary across repetitions.
Benchmark configurations, task details, and evaluation procedures are provided in Appendix A . Model. We use two backbone models matched to the observation modality of each environment.
For ALFWorld, a text-based environment, we use Llama-3.2-3B-Instruct [ 2 ] .
For EmbodiedBench Habitat, a vision-based 3D environment, we use Qwen3-VL-4B-Instruct [ 3 ] , which natively processes RGB observations.
Both are served with greedy decoding (temperature = 0 \,{=}\,0 ).
For procedural memory, we use rank-8 LoRA adapters [ 11 ] fine-tuned on task-type-specific trajectories for each backbone.
Each procedural memory content is linked to an adapter identifier used for adapter selection and KV compatibility checking, as described in Sec. 4.3 . Baselines. We compare HeMeR with six baselines covering agent-level reasoning, memory use, KV reuse, and procedural adapter switching.
ReAct [ base:react ] tests prompting without explicit external memory, and Reflexion [ embodied:reflexion ] tests self-reflective feedback from prior failures.
MemRL [ 26 ] retrieves episodic memory from previous trajectories to guide action selection, but treats the retrieved context as a conventional input across decision steps.
CacheBlend [ serve:cacheblend ] and KEEP [ 23 ] evaluate segment-level and invalidation-based KV reuse, respectively.
LRAgent [ 14 ] tests LoRA-based procedural skill switching, but does not explicitly track updates in declarative or working-memory contents.
Together, these baselines separate the effects of prompting, episodic memory retrieval, cache reuse, procedural adapter switching, and the proposed heterogeneous-memory KV reconciliation. Metrics. We evaluate task performance, action behavior, and inference efficiency with six metrics.
SR measures binary end-to-end task success in ALFWorld and Habitat [ 19 , 20 ] , and goal-conditioned success rate in real-world tasks.
Latency measures average wall-clock time per decision step, while TTFT isolates prefill and cache-processing latency before the first generated token, a common serving-level efficiency metric [ serve:vllm , serve:cacheblend ] .
Reuse ratio measures the fraction of KV states preserved after memory-content updates, following prior cache reuse studies [ serve:cacheblend , 12 ] .
Active action ratio measures the fraction of generated actions belonging to predefined task-progressing action categories [ 18 ] .
Action diversity measures the average per-episode ratio of unique actions among all generated actions [ 4 ] .

Overall, the ablation results show that the memory schema identifies reusable contents, chunk-level reconciliation localizes memory-content updates, and adapter-stable reconciliation ensures reused states remain compatible under procedural changes. 6 Conclusion We presented HeMeR , a heterogeneous memory reconciliation framework for foundation model-based embodied agents. HeMeR anchors memory contents as typed memory chunks with associated KV ranges and reconciles memory-content updates through localized KV operations.
By combining chunk-level and adapter-stable KV reconciliation, it preserves compatible KV states across changes to declarative, procedural, and working memory contents without rebuilding the full KV cache.
Experiments on ALFWorld, Habitat, and real-world tabletop manipulation tasks show that HeMeR improves task success and reduces per-step inference time over strong baselines.
These results demonstrate that reconciling dynamically updated memory contexts with reusable KV states supports efficient and stable inference in long-horizon embodied tasks. Limitation and future work. Our evaluation focuses on single-agent embodied tasks, where memory contexts are updated across successive decision steps.
In multi-agent embodied systems, concurrent updates to shared memory contents may introduce consistency issues between memory contexts and cached KV states, which are not addressed by the current framework.
As future work, we plan to extend HeMeR to multi-agent embodied systems by incorporating concurrency control for shared memory updates and KV reuse.

Environment. Our real-world setup employed a UR7e robotic arm mounted on a tabletop workspace. For perception, we used two Intel RealSense D435 RGB-D cameras: one attached to the gripper for close-range, viewpoint-aligned observation during manipulation, and another mounted overhead in a bird’s-eye configuration to capture the global scene layout. The two depth streams were fused into a unified point cloud, yielding a high-resolution 3D reconstruction of the workspace that served as the basis for object localization and visual grounding. Perception and control were integrated in a single real-time loop, ensuring consistent behavior throughout manipulation. Task. Real-world tasks are executed using a compact set of predefined task-level skill APIs. As summarized in Table 7 , these APIs cover common tabletop manipulation operations, including pose-conditioned motion, object picking, object placement, pick-and-place transfer, directional pushing, tool grasping, and object flipping. Each skill exposes only the task-relevant arguments needed for planning, such as the target object, source and target locations, end-effector pose, or push direction. This abstraction hides low-level control details while preserving sufficient flexibility for the LLM-based agent to compose actions across cooking and beverage-preparation tasks. Real-world experiments were conducted in two tabletop environments: a Dual-Section Kitchen-Café environment and a Single-Section Beverage Station environment.
Each of the two evaluated long-horizon tasks is repeated with varying object configurations.
At the beginning of each trial, objects were sampled from the corresponding object pool and placed at randomized positions within the workspace.

A.5 Baseline To provide a comprehensive comparison, we group the baselines by their assumptions about memory-content updates and reusable KV states during embodied inference. • General embodied reasoning baselines generate actions from observations, goals, and interaction history without explicit memory reconciliation. – ReAct [ base:react ] interleaves reasoning traces and actions for step-by-step embodied decision making. – Reflexion [ embodied:reflexion ] uses verbal self-reflection from previous failures to guide future action decisions. • Memory-augmented embodied baselines retrieve past experience or task-relevant memory to support long-horizon action selection. – MemRL [ 26 ] retrieves episodic memory from trajectories to improve embodied decision making. • KV cache reuse baselines reduce inference cost by reusing cached states under repeated or partially shared contexts. – CacheBlend [ serve:cacheblend ] reuses non-prefix segments and selectively recomputes boundary regions. – KEEP [ 23 ] reuses KV states across embodied reasoning by invalidating affected cache portions. • Adapter-based baselines improve efficiency under procedural skill switching. – LRAgent [ 14 ] represents procedural skills with LoRA adapters and supports adapter switching during embodied inference. We compare HeMeR against six baselines that span both agent-level memory mechanisms and cache-level reuse strategies. All baselines share the same backbone model and decoding configuration as HeMeR (Llama-3.2-3B-Instruct on ALFWorld; Qwen3-VL-4B-Instruct on Habitat; greedy decoding) so that any difference reflects memory or cache handling rather than model capacity. ReAct [ base:react ] . Reasoning-and-acting prompting baseline. The agent emits a Thought followed by an Action at every step, with the conversation history accumulated as a chat trace. ReAct has no explicit memory module beyond the natural in-context history, so the cache contains only the running conversation and is rebuilt as the prompt grows. Reflexion [ embodied:reflexion ] . ReAct extended with verbal self-reflection on episode failure. After a failed episode, the agent generates a free-form reflection that is stored and retrieved in subsequent episodes. Reflexion tests whether self-reflective episodic feedback suffices in the absence of structured memory composition. MemRL [ 26 ] . Memory-augmented decision making with episodic memory and Q-learned utility, but no structured KV reuse. We use the published MemRL retrieval policy (top- k k word-overlap retrieval with ϵ \epsilon -greedy exploitation) and inject retrieved trajectories as in-context successful and failed memory snippets. MemRL serves as the strongest agent-level memory baseline. CacheBlend [ serve:cacheblend ] . Segment-level KV reuse that fuses precomputed chunks at chunk-boundary positions with selective recompute of the boundary tokens. We adapt CacheBlend to embodied trajectories by treating each per-step memory composition as a chunked input; off-boundary updates are ignored, and at chunk-boundary steps the trailing chunks are re-prefilled with selective calibration. We use the boundary period K = 5 K=5 throughout, matching the recompute budget of the original system. KEEP [ 23 ] . Embodied-memory cache management with internal-trigger invalidation. KEEP evicts memory regions that conflict with the agent’s most recent action and keeps unaffected regions. We implement KEEP-style invalidation as the eviction-only subset of HeMeR ’s policy: the dispatcher honors only evict and adapter_switch edits, which mirrors KEEP’s self-induced invalidation scope without re-injecting the inserted or reordered content. LRAgent [ 14 ] . Procedural memory through LoRA adapter switching with shared-attention cross-adapter cache. LRAgent reuses the prefill cache across adapter switches but does not edit the cache for declarative or working-memory updates.
We use the same adapter pool as HeMeR while retaining LRAgent’s adapter-level cache-reuse policy. Faithfulness statement. CacheBlend, KEEP, and LRAgent are implemented according to their public descriptions and adapted to the embodied-agent evaluation setting.
Because the original systems target different serving stacks or task interfaces, we keep their core reuse assumptions unchanged while integrating them into our shared observation, action, and memory-context pipeline.
Within this harness, all baselines and HeMeR use the same observation pipeline, action filter, prompt template, backbone model, decoding setting, and admissible-command set when applicable.
Thus, performance differences primarily reflect how each method handles memory use and KV reuse under dynamically changing embodied contexts. A.6 Metrics We report six metrics that characterize task performance, action behavior, KV reuse, and inference efficiency. Success Rate (SR). For ALFWorld and Habitat, SR measures binary end-to-end task completion: SR = 1 N ​ ∑ i = 1 N 𝟏 ​ [ goal ​ _ ​ satisfied i ] , \mathrm{SR}=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}[\mathrm{goal\_satisfied}_{i}], where N N is the number of evaluation episodes and goal ​ _ ​ satisfied i \mathrm{goal\_satisfied}_{i} is the binary task-completion indicator returned by the environment.
For real-world tasks, we use goal-conditioned success rate, which measures the proportion of satisfied goal conditions within each trial, averaged across physical trials. Latency. Latency is the average wall-clock inference time per decision step.
It is measured after the step input is finalized and includes KV reconciliation, prefill, local recomputation, and decoding.
Latency is reported in seconds per step. Time-to-first-token (TTFT). We report TTFT as the sum of measured KV-cache update execution and fresh-tail prefill times through the first generated token.
It includes required prefill, local recomputation, and cache assembly.
For cache-reuse methods, KV ranges cached at previous steps are available before timing begins.
It excludes environment execution, memory retrieval, prompt construction, and schema-diff planning. Reuse ratio. Reuse ratio measures the fraction of previous-step cached tokens whose KV states are preserved at the current step.
Let S t S_{t} be the number of tokens in the previous cache and C t C_{t} the number of those tokens whose KV states are not preserved, including evicted and locally recomputed tokens.
We average over T T steps with an available previous cache: Reuse = 1 − 1 T ​ ∑ t = 1 T C t S t . \mathrm{Reuse}=1-\frac{1}{T}\sum_{t=1}^{T}\frac{C_{t}}{S_{t}}. Inserted tokens are excluded, while RoPE-remapped KV states count as preserved.
A value of 1 indicates that all previous-step cached KV states are preserved, while 0 indicates that none are preserved. Active Action Ratio. Active action ratio measures the fraction of generated actions that are expected to advance the task or change the environment state.
We map benchmark-specific action strings or skill API calls to a shared set of task-progressing action categories.
For episode i i with action sequence 𝒜 i = ( a i , 1 , … , a i , T i ) \mathcal{A}_{i}=(a_{i,1},\ldots,a_{i,T_{i}}) , we compute ActiveAct = 1 N ∑ i = 1 N 1 T i ∑ t = 1 T i [ a i , t ∈ 𝒜 act ] . \mathrm{ActiveAct}=\frac{1}{N}\sum_{i=1}^{N}\frac{1}{T_{i}}\sum_{t=1}^{T_{i}}\boldsymbol{1}\!\left[a_{i,t}\in\mathcal{A}^{\mathrm{act}}\right]. A higher value indicates that the agent more frequently performs task-progressing actions rather than passive, invalid, or redundant steps. Action Diversity Ratio. Action diversity measures the average per-episode ratio of unique actions among all generated actions.
For episode i i with action sequence 𝒜 i = ( a i , 1 , … , a i , T i ) \mathcal{A}_{i}=(a_{i,1},\ldots,a_{i,T_{i}}) , we compute Diversity = 1 N ​ ∑ i = 1 N | Unique ⁡ ( 𝒜 i ) | T i . \mathrm{Diversity}=\frac{1}{N}\sum_{i=1}^{N}\frac{\left|\mathrm{Unique}(\mathcal{A}_{i})\right|}{T_{i}}. Visual tokens from the current observation are encoded normally at each decision step and are not position-remapped. System architecture. HeMeR is implemented as an inference framework placed between the memory-augmented embodied agent and the backbone foundation model.
At each decision step, the agent retrieves declarative, procedural, and working-memory contents, forms the memory context X t X_{t} , and passes it to HeMeR for KV reconciliation.
The framework maintains a chunk-level memory schema, maps each memory chunk to its KV range, and reconciles the previous KV cache with the current memory context before action generation.
Environment execution and memory retrieval are handled by the agent loop, while HeMeR handles cache reuse, affected-range detection, RoPE-based remapping, local recomputation, and adapter compatibility checks. Memory schema and reconciliation rules. Each memory content is represented as a memory chunk and stored with schema fields used for reconciliation.
The schema records each chunk’s persistent ID, memory module type, semantic role, dependency annotation, temporal origin, position, token span, KV range, supporting evidence, normalized content, and adapter identifier when applicable. HeMeR computes Δ t = Diff 𝒮 ​ ( X t − 1 , X t ) \Delta_{t}=\mathrm{Diff}_{\mathcal{S}}(X_{t-1},X_{t}) by first matching chunks by persistent IDs and then comparing their schema fields rather than raw token overlap.
Inserted chunks are prefilling targets, evicted chunks are removed, and reordered chunks are reused only when schema fields, normalized content, and adapter identifiers remain compatible.
For schema-compatible position shifts, RoPE remapping corrects the cached key’s positional phase; unsafe cases are handled by local recomputation. Adapter compatibility. Procedural memory contents are associated with LoRA adapter configurations. HeMeR records adapter identifiers in the memory schema and uses them as a compatibility condition for KV reuse.
If a procedural change affects an adapter-dependent range, that range is locally recomputed to avoid reusing KV states from an incompatible adapter configuration. Fair comparison protocol. All methods use the same backbone model, task split, decoding configuration, action interface, and maximum step budget within each environment.
Memory-augmented baselines are given access to the same memory-content pool when applicable.
Cache-level baselines are evaluated on the same sequence of memory contexts and memory-content updates as HeMeR .
Thus, the comparison isolates how each method processes the memory context and reuses or recomputes KV states. B.3 Prompt Templates We document the prompt templates used in our experiments.
The system prompt, task brief, action grammar, and observation-action format are shared across methods within each benchmark.
Methods differ only in whether and how they use the provided memory contents, and in how their serving policy reuses or recomputes KV states.
This ensures that performance differences are not caused by benchmark-specific prompt engineering.
Although the prompt template is shown in full, cache-reuse methods do not prefill the entire rendered prompt at every decision step.
TTFT includes KV cache updates, required prefill, and local recomputation up to the first generated token, excluding memory retrieval, prompt construction, and schema-diff planning. Shared System Prompt. The same system prompt is used by ReAct, Reflexion, MemRL, CacheBlend, KEEP, LRAgent, and HeMeR . Interact with a household to solve a task.
Imagine you are an intelligent agent in a household environment and your target is to perform actions to complete the task goal.
At the beginning of your interactions, you will be given the detailed description of the current environment and your goal to accomplish. For each turn, you will be given the observation from the last turn.
You should first think about the current condition and plan your future actions, and then output your action for this turn.
Your output must strictly follow this format: ‘‘Thought: your thoughts.\nAction: your next action’’. The available actions are: 1. go to {recep} 2. take {obj} from {recep} 3. move {obj} to {recep} 4. open {recep} 5. close {recep} 6. use {obj} 7. clean {obj} with {recep} 8. heat {obj} with {recep} 9. cool {obj} with {recep} where {obj} and {recep} correspond to objects and receptacles.
After each turn, the environment will provide feedback.
If the environment outputs ‘‘Nothing happened’’, the previous action is invalid and you should try another valid action. Your response should use the following format: Thought: <your thoughts> Action: <your next action> The same Thought-Action output format is used for all methods, including cache-reuse baselines, so that differences are not caused by response-format prompting. For HeMeR , this block corresponds to the memory context X t X_{t} used by the reconciliation policy.
The same text-side memory context format is used across benchmarks, while visual observations are provided through the multimodal input interface when applicable. [Memory context X t X_{t} ] [Declarative memory] - <declarative memory content 1> - <declarative memory content 2> … [Procedural memory] - <procedural memory content> [Working memory] - <working-memory summary 1> - <working-memory summary 2> … At each decision step, the block is rendered from the current memory contents and their schema fields.
Memory-content updates, such as insertion, eviction, and reordering, appear to the foundation model through the updated memory context, while procedural adapter changes are tracked as schema metadata for KV compatibility.
For cache-level baselines, we use the same rendered memory context when applicable, but each method applies its own cache reuse policy.
For HeMeR , the rendered chunks are additionally aligned with KV ranges through the memory schema, enabling schema-guided KV reconciliation.
Adapter identifiers are stored as schema metadata for compatibility checking and are not used as additional natural-language hints unless required by a baseline interface. Task Brief. The first user turn specifies the task type, goal, and initial admissible commands.

When the admissible-command list is long, it is truncated using the same limit for all methods.
Subsequent observation turns include the dynamically updated admissible-command list. Observation-Action History. After the task brief, each step appends a user turn of the form: Observation: {obs} The assistant response follows the shared ReAct-style format: Thought: <reasoning about the current state> Action: <next action> The conversation history persists within an episode so that each method has access to previous observations and actions.
Long observations are truncated using the same character budget across all methods.
The memory context block may change across steps as memory contents are updated, but past assistant turns are not rewritten. Retrieved Trajectory Memory. For methods that use episodic or trajectory memory, we optionally include a compact retrieved trajectory from the same task type.

We further analyze representation-level robustness under memory-content updates.
While task success measures whether the final action trajectory satisfies the goal, it does not directly show whether KV reuse destabilizes internal model representations.
To inspect this effect, we compare each cache-reuse method against Full Rebuild, which recomputes the full KV cache after every memory-content update.
For each method, we measure hidden-state drift at each layer and token position: Drift ℓ , i = ‖ h ℓ , i method − h ℓ , i full ‖ 2 , \mathrm{Drift}_{\ell,i}=\left\|h^{\mathrm{method}}_{\ell,i}-h^{\mathrm{full}}_{\ell,i}\right\|_{2}, (8) where h ℓ , i method h^{\mathrm{method}}_{\ell,i} is the hidden state at layer ℓ \ell and token position i i after applying the method’s cache update rule, and h ℓ , i full h^{\mathrm{full}}_{\ell,i} is the corresponding hidden state from Full Rebuild.
The heatmap in Figure 9 visualizes this drift across layers and token positions.
Brighter regions indicate larger representation mismatch from Full Rebuild. The drift patterns reveal how each method propagates memory-content updates through the cached representation.
CacheBlend produces drift around reusable segment boundaries.
This suggests that segment-level reuse is sensitive to boundary mismatch: even when a non-prefix segment is reused, local changes near the segment boundary can perturb nearby reused states.
KEEP shows broader downstream propagation.
Because KEEP invalidates affected regions and preserves later cache regions under a coarser update rule, representation mismatch can propagate to later token positions after a memory-content update.
LRAgent shows gradual drift accumulation over later positions.
This pattern indicates that adapter-level reuse alone does not fully account for updates to declarative or working-memory contents, so representation mismatch accumulates when the memory context changes across decision steps. In contrast, HeMeR confines high-drift regions to a small number of affected memory chunks.
This pattern follows from the schema-indexed reconciliation rule.
A KV range is reused only when the corresponding memory content remains compatible under the memory schema, including its normalized content, dependency annotation, and adapter identifier.
When the update is limited to a position shift, RoPE remapping corrects the positional phase of cached key states.
When the memory content, dependency annotation, or adapter identifier changes, HeMeR locally recomputes the affected KV range rather than reusing stale states.
In the evaluated settings, representation deviations remain comparatively small outside the affected memory chunks. This analysis supports the robustness claim of HeMeR .
The benefit is not only that more KV states are reused, but that reused states remain localized and compatible with the current memory context.
Thus, HeMeR reduces redundant recomputation while limiting broad hidden-state drift under the evaluated memory-content updates. Deviation Accumulation over Successive Memory-Content Updates. The gap between this variant and the full framework supports the role of adapter-aware compatibility checks in maintaining stable action decisions. Overall, the ablation results separate the roles of the three components.
The memory schema identifies which contents can be reused, chunk-level KV reconciliation localizes memory-content updates to affected ranges, and adapter-stable KV reconciliation prevents incompatible reuse under procedural changes.
Together, these components allow HeMeR to reduce inference cost while preserving task success and action-level robustness.
